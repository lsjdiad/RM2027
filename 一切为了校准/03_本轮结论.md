## 一、硬结论（可以直接用）

### 1. 三角形函数零点锚定的拟合**成立**，"能拟合吧" = 能

把换相点推出的**理论过零点**（＝这一步的正中，`u=0.5`）当三角函数的零点钉死，
只拟合每相的幅值 A 和直流 C（**每相 2 个参数**）：

| 台阶 | 参数个数 | 残差 RMS |
|---|---|---|
| 噪声地板（逐段自由直线） | 2/段（过参数化） | 19~27 码 |
| **公平基准**（逐步自由直线） | **12** | 35~56 码 |
| **本模型**（三角零点锚定） | **6** | 45~98 码 |

6 个参数做到 12 参数基准的 **1.04~1.68 倍** ⇒ 拟合成立。
多出来的那一小截不是"模型不对"，正是**六步各自的竖直偏置** —— 也就是要校准的那个量。

### 2. "过零位置测不准"的主因是**口径**，不是转子

同一组数据，五个口径给出的过零偏差（°E）中位：

| 口径 | 过零点在窗内？ | 口径散差 |
|---|---|---|
| 局部插值 / 全步直线 / 中段直线 | ✅ | **0.7~2.0 °E** |
| 前半窗 `0.15~0.50` / 后半窗 `0.70~0.95` | ❌ 外推 | **10~18 °E** |

⇒ 交接 §5① 说的"过零位置测不准（口径不同能给出 +4°~+17°）"**主要是口径假象**。
　交接轮 20 用的 `0.15~0.50`、`0.70~0.95` 都是**半窗外推**（过零点落在窗外），
　那样求出来的 u0 等于把斜率误差放大一倍，所以散得离谱。
　**口径定案：只用"窗内含过零点"的口径**（变号插值 / 全步或中段直线），三者互差 ≤2°E。

### 3. 换一个参考点 V0，六步散差塌掉 3~4 倍（本轮最重要的发现）

同一组数据、同一套口径，**只换 V0**：

| run | 六步散差 hw V0 → sw V0 | 口径散差 hw → sw |
|---|---|---|
| `20261013_115519` | **11.0 → 2.8 °E** | 1.2 → 0.9 °E |
| `20261013_105232` | **21.8 → 5.6 °E** | 1.2 → 0.7 °E |

**机理**（推导 + 实测一致）：六步里恒为"两相驱动互补 + 一相悬空"，两相占空比之和恒等于母线电压 ⇒

```
sw = (v_悬空 + Vbus)/3      ⇒      d = v_悬空 − sw = (2/3)·(v_悬空 − Vbus/2)  ∝ 悬空相反电势本身
```

⇒ **软件均值参考下，`d` 只是悬空相反电势的一个纯缩放**，V0 的误差只改变增益、**不移动过零点**；
　而硬件星形网络是模拟电路，它的偏差不随悬空相成比例 ⇒ 会按**步**把过零点推走 ⇒ 造出"六步不对称"。

**硬件 V0 到底差多少**（回归 `v0_hw = k·(VA+VB+VC)/3`，开环段，只取有驱动的采样点）：

| run | k | 残差 RMS |
|---|---|---|
| `20261013_115519` | 0.966 | 22 码 |
| `20261012_223708` | 0.972 | 32 码 |
| `20261012_224624` | 0.972 | 33 码 |
| `20261013_105232` | 0.976 | 42 码 |

⇒ 差 2~3% 增益 + 22~42 码的**结构性残差**（不是纯增益误差）⇒ **"硬件 V0 = 三相均值"这个前提不成立**。

**推论**：硬件 V0 的这张账，正好能解释为什么活下来的补偿族只有**不随时间跳变的常量偏移**——
常量偏移就是"V0 的直流/增益误差"的样子；而随时间跳变的补偿在补一个**主要来自测量链的量**，
所以越补越坏（这与轮 11 的自我更正方向一致，但机制定位不同）。

### 4. 理论标准 = "过零在换相之后 30°"，已用三条独立证据钉死

```
   换相点              理论过零点              下一次换相
     |                     ▲                     |
     |<---- 30° 电角度 ---->|<--- 30° 电角度 --->|
     |<---------------- 一步 = 60° ------------->|
   u=0                   u=0.5                  u=1
   τ=0                   τ=30                  τ=60
```

1. **经典无感六步**：检测到过零后再等 30° 才换相（TI SPRABZ3 框架），而一步 = 60° ⇒ 过零落在步正中。
2. **固件自己的注释**（`Src/main.c`）：L462 `ccm_wait[] = waitTime（换相后要等的 30 度延迟，= ci/2 - advance）`；
   L3956 `即换相发生在【过零后 15°】，而教科书位置是 30°（waitTime = ci/2）`；L3971 明确要"回到教科书位置"。
3. **实测**（`tools/cal-anchor.py <run> --standard`，整转拼接拟一根正弦）：

| run | V0 | 三个相的拟合过零点 τ_z | 离最近换相点 | 三相相位差（理想 ±120/±240） | 残差 |
|---|---|---|---|---|---|
| `20261013_115257` | sw | 35.4° / 36.5° / 37.6° | **35~38 °E**（理论 30） | **+121.1° / −117.8°** | 43~47 码 |
| `20261013_115519` | hw | 32.9° / 35.6° / 41.0° | **33~41 °E** | +125.4° / −111.8° | 43~71 码 |

⇒ 落在理论 30° 之后 **5~8°**（干净的 sw 那组），三相互相 121°/118° 几乎正好是理想值。
**不是 0°（过零在换相点上），也不是 90°。**
多出来的 5~8° 就是**转子负载角**（开环时定子磁场按定时器走、转子滞后），属正常物理。
另一条推论：**换相那一刻悬空相反电势正好是幅值的一半**（sin30°=0.5），既非峰值也非零。

### 4b. "为什么看着像直线不是正弦"——因为一次只看得见正弦的 1/6

一步只有 60°，而过零点在正中 ⇒ 可见的只是过零前后 ±30° 这一小段。在 ±30° 内
正弦与直线的最大差只有半量程的 **1.24%**（RMS 0.89%，见《交接》§3.5 / `ramp-fit.py`）⇒ 数值上分不出。
把同一个相在**一个电周期里的两段弧拼起来**（`--standard`，图 `理论标准_*.png`），
完整正弦的曲线立刻显现；再把**三相数据折叠到各自过零点**（图 `三相合一_*.png`），
三相全部塌到同一根 `sin(x)` 上（紫色分箱中位线落在正弦上）。
**所以"直线"不是模型错，是观测窗太窄 + 以前的图从没拼过一个整转。**

> ⚠ **结构性边界（别过度解读）**：能看到的数据只有过零附近**约一个步宽**（x∈[−29°,+25°]）。
> 一个相一个电周期只悬空 2×60°=120°，且必然包着它自己的过零点；**波峰在 ±90°，那时该相正在被
> 驱动（端子是 PWM 方波）⇒ 永远测不到反电势**。
> ⇒ **"正弦 / 梯形 / 直线"这个形状问题，悬空相数据永远证不了**（这正是轮 20 段内量不出曲率的
> 结构性原因）。能证的是：两段弧相隔 180°、三相相差 120°、过零点在步正中——校准要的就是这些。
> 想看见波峰必须换采集方式（三路端子电压按占空比补偿后再算 `v_P − v_n`，或改正弦驱动）。

### 4c. 把"悬空相"当【一个通道】看：不是正弦，是周期 120° 的三角/锯齿波

（图 `悬空相合成_20261013_115257.png`）任一时刻恰好一个相悬空（每相 120°、三相拼满 360°），
所以"悬空相 − V0"是**一条连续曲线**；但每 60° 换相时它跳到**另一相**的反电势上，
而换相点落在步边界（该相 BEMF = ±半幅）、三相相差 120° ⇒ **每 60° 上升/下降翻号**
⇒ 合成结果是**周期 120° 电角度（＝2 步）的三角波，幅值只有 ±半幅**。
频率 = 3× 电频率 = 18× 机械频率（115257：190.5 Hz → 571 Hz）。

- 三条直接后果：① 所有工具必须带**每步一个符号 `S_s`**（不翻符号这根锯齿波里拟不出东西）；
  ② **固件的过零检测看的就是这条锯齿波**，每 60° 一个过零 ⇒ 一电周期 6 个过零，正好对上固件
  注释里"`thiszctime` = 两次过零之间的时间 = 一个完整换相步"；
  ③ **"理论标准"的正确做法是把这条合成曲线按"当下是哪个相"拆开**，每段才是正弦，
  再把同一相的两段弧拼起来 → 一根完整正弦。
- 理想情形拐角平滑（两边都是 ±半幅）；实测过零在 ~36°、三相幅值不同 ⇒ 拐角变成约 ±100 码小台阶。

## 五、分阶段路线：先做 ADC 初步校准，再谈六步不对称（2026-10-13 新增）

**答案：可以，而且已经做出来了**（`tools/cal-anchor.py --adc-gain`，表 `04_ADC增益表.md`，图 `ADC增益校准.png`）。
但有一个必须先纠正的坑。

### ⚠ 千万别用"悬空读数幅值"当增益

三种幅值口径在同一组数据上给出的**相间大小顺序互相矛盾**：

| 115519 · V0=sw | 相A | 相B | 相C |
|---|---|---|---|
| 极差 max−min | 395（最大） | 363 | 301.7（最小） |
| 拟合正弦幅值 | 397 | 407（最大） | 329（最小） |

按幅值口径校正，六步散差会从 11.0°E **改坏到 51.7°E**（实测）。
原因：悬空弧的摆幅只有 150~350 码，而读数里还叠着 ≈600 码的中性点电平，幅值口径被
"换相尾巴 + 每步直流"污染得很厉害。**幅值不是良定义的增益量。**

### ★ 正确口径：拿【过零点位置】反解

```
d = g_P·v_P − g_0·V0       过零 ⟺ v_P = V0·g_0/g_P
v_P = v_n + e_P ， v_n ≈ 母线中点 ≈ 600 码 ≫ 弧幅 150~350 码
⇒ 增益误差等效成 e_P 上一个【常数偏置】 o_P = v_n(1 − g_0/g_P)
⇒ 它的特征是：同一个相的两个步里【符号相反】（那两步的 BEMF 斜率反号）
```

所以做法是：逐相搜索 o_P，使该相两步的过零偏差对消。固件里有两种等价实现（都是常量、不随时间跳变）：

- **偏置侧**：`d ← d − o_P`（或 `v_P ← v_P − o_P`）—— 就是交接里那族"活下来的常量偏移"；
- **增益侧**：`v_P ← v_P / g_P`，其中 `g_P = 1/(1 − o_P/v_n)`。

### 三句话

1. **ADC 初步校准确实有效**：它治的是"相内反对称"那一项（7~12°E），能干净地打到 0.1°E。
   等效的通道增益差只有 **2.5~5.5%**（而不是幅值口径暗示的 19%）。
2. **剩下的是"相间差"**：hw V0 下约 9~10°E、sw V0 下 3~5°E。**这一项任何逐相读数偏置/增益都改不了**
   ——因为偏置在同一个相的两个步里是对称抵消的，动不了两点的均值。⇒ **这才是"消除六步不对称"
   真正的靶子**，而首选嫌疑仍是 **V0 参考**（sw V0 已把它砍掉一半以上）与**驱动侧**（占空比/死区/
   相电阻），不是 ADC。
3. **一个硬约束**：过零必须留在这一个步内 ⇒ 偏置不能超过约 ±150 码（≈ ±25% 增益）。
   **ADC 校准能修的增益误差有个 ±25% 的上限，超过就无解**（工具会打印 ⚠）。

### ★ V0 要不要一起校？——不要，也不能单独校（这是本轮最容易搞错的一点）

`d = 悬空相 − V0`。四个通道 A/B/C/V0 **同时乘一个常数会整个约掉** ⇒ 只有
**A/V0、B/V0、C/V0 三个比值**有意义，再扣掉一个整体尺度 ⇒ **自由参数只有 2 个**。
本表的三相系数（已归一化到均值=1）正好把它们编码完 ⇒ **增益这一层是完备的**，
V0 通道不需要、也拿不到一个额外的"增益校准系数"。
（唯一受绝对码值影响的是固件里 16 码的滞回阈值：同乘 k 会让等效滞回变 16/k，相对 400 码级的弧幅是二阶小量。）

**但 V0 还有另一个毛病，不是增益能治的**：实测 `v0_hw ≈ 0.966~0.976 × (VA+VB+VC)/3`，
残差 RMS 22~42 码，而且它**跟驱动极性相关**（不是标量增益）。这正是"相间差"的来源，
也是为什么换 sw V0 能把总散差 6.9 → 3.2 °E。⇒ **V0 参考是下一轮的头号靶子。**

### ⚠⚠ 重大数据问题：`evt_run_20261013_115519` 是 A/C 对调过的

用"步内斜率"当稳健增益代理（对带校正的 135039 先反解掉固件加的系数）：

| run | A | B | C | 图样 |
|---|---|---|---|---|
| `115519`（交接说是基线、轮 19/20 全用它） | **1.211** | 0.995 | **0.794** | A 强 C 弱 |
| `135039`（本固件实测，已反解校正） | **0.827** | 0.975 | **1.198** | A 弱 C 强 |
| `103829`（复测#1 基线） | 0.709 | 0.979 | 1.312 | A 弱 C 强 |
| `223708` | 0.679 | 0.973 | 1.348 | A 弱 C 强 |

后三组互相一致，`115519` 与它们**互为倒数**，A↔C 对调后复现到 1~5%
⇒ **`115519` 是 A/C 对调的数据**（很可能就是 `1013-g071-AC对调分辨` 那次留下的，而交接记成了基线）。
后果：① 本工具第一版的增益表是从它推的 ⇒ 系数张冠李戴（已修正，见上表三轮）；
② **交接里凡是用 `115519` 得出的"分相位"结论都要复核**（过零位置的统计不受影响，因为那是
   与相位标签无关的量；但"哪一相偏多/偏少"这类结论会张冠李戴）。

## 七、再加一版：V0 = 三相平均（2026-10-13 14:01）

用户方案："只考虑 ADC 增益 → 把 ABC 三相搞好 → 然后注意三相平均、注意它与原理图的联动"。
这一版就是把 V0 从硬件星形换成**三相平均**（`RM2027_V0_SOFTMEAN=1`），**其余不动**。
窗口载荷仍然记硬件 V0（新增 `bemf_adc_v0_hw`）⇒ 同一轮数据里两种参考都能对照。

### ★ 与原理图的联动：均值上对上了，逐步没对上

| 量 | 数值 |
|---|---|
| 硬件 V0 − 三相平均，**六步均值** | **−1.0 码**（未做增益归一前是 −19.1 码） |
| 硬件 V0 − 三相平均，**逐步** | 步1..6 = +1.0 / −3.0 / **+16.8** / −4.7 / +5.3 / **−21.7** 码 |

⇒ 原理图说"V0 就是三只电阻从三相接到一个公共节点"⇒ 它**本来就应该等于三相平均**。
增益归一之后这句话在**均值上成立**了（差 1 码）✓；
但**逐步还差 ±20 码**（另一轮实测极差到 **74 码 = 12%**）⇒ 硬件 V0 节点有**逐步失真**，
不是增益问题（增益是标量，改不了逐步形状）。
从 d_sw/d_hw 的峰峰比（实测 **1.16**，理想应为 1.00）反推：浮空相在 V0 节点上的耦合
比理想值大 ~28% ⇒ 与交接 §4 的候选②"驱动相对悬空相的共模耦合"一致。

### 开环散差：三版一路降下来

| 版本 | 开环六步散差 | 口径散差(×3) |
|---|---|---|
| 基线（hw V0，无增益归一） | 11.0 °E | ~1.2 |
| + ADC 增益归一（hw V0，`135347`） | 6.9 °E | ~1.1 |
| **+ V0 = 三相平均（`140117`）** | **4.3 °E** | **0.4** |
| （同一轮 `140117` 若仍用 hw V0） | 8.0 °E | ~1.1 |

⇒ **测量链这一层"能好"，而且这是目前最好的一版**（口径之间只差 0.4°E，史上最紧）。

### ⚠ 但闭环反而更差：六步散布 26%（hw V0 那版 14%）

原因是**换参考以后过零"检测点"整体移动了**，逐步偏差前后对比：

| 步 | 1(C) | 2(A) | 3(B) | 4(C) | 5(A) | 6(B) |
|---|---|---|---|---|---|---|
| hw V0 | +5.9 | +10.6 | +6.6 | +5.6 | +12.9 | +4.8 |
| sw V0 | +4.9 | +8.5 | +7.2 | +5.2 | +9.2 | +6.6 |
| 移动 | −1.0 | −2.1 | +0.6 | −0.4 | **−3.7** | +1.8 |

⇒ 检测点动了 0.4~3.7°E，而闭环对换相相位**极端敏感**（交接 §5③ 的结构性发现）
⇒ 检测点一挪，闭环就变差。**这也解释了归档分支 `归档/1013-g071-V0软件均值` 上线跑败**
（超时 42240、散布 18%）——不是"软件均值这条路本身错"，而是**换了参考却没重调判据**。

顺带纠正一个我之前推错的直觉：换三相平均**不会**把判据信号缩到 2/3——
实测 d_sw/d_hw 峰峰比 = **1.16**（理想情况两者本来就等价，见上面"联动"那段）。

### 所以这一版的结论

- **测量层：成了。** 开环散差 11.0 → 4.3°E，口径散差 0.4°E，可以拿它当"理论标准"的基准。
- **闭环层：不行，光换 V0 不够。** 必须把**过零检测的滞回（现 16 码）/换相屏蔽帧数/判据阈值
  一起按新参考重调**；更彻底的做法是把判据改成**与参考、幅值都无关的量**（例如只判
  "斜率符号 + 单调性"，像 `adc_zc` 那个环形缓冲判据，而不是判"跨某个绝对阈值"）。
- 固件里两个版本都在（`RM2027_V0_SOFTMEAN` / `RM2027_ADC_GAIN_CAL` 两个开关），
  日志永远带硬件 V0 ⇒ 下一轮可以直接同轮对照两种参考。

## 八、ADC 读取误差：定性 + 定量的终点（2026-10-13 14:20~14:30）

用户要求：开环 + 采样时间加到最长 + 逐步缩小 CCR4，把 ADC 读取误差查到底；并试"交换次序校正"。

### ① 扫描是七路，但只有前 4 路卡预算

```
rank1=VA(CH5)  rank2=VB(CH4)  rank3=VC(CH2)  rank4=V0(CH3)
rank5=电流      rank6=母线电压   rank7=温度(单独 SMP2=160.5 周期)
```
导通期约束只对**前 4 路**成立（它们先采完）；rank5/6 落在 324/355 tick 也还在窗口内；
rank7 温度是**片内**通道，采在窗口外无所谓 ⇒ **把温度挪走也腾不出 BEMF 的空间**。

### ② "采样时间加到最长"——实测"最长"只能是 19.5，而且那已是边界

反解出每通道扫描时间 ≈ `(SMP+12.5)×1.55 tick`：

| SMP | 4 通道扫描 | CCR4=200 时终点 | 导通期(duty 300) | 实测 |
|---|---|---|---|---|
| **7.5** | 124 | 324 | 400 | ✅ 四路正常（余 76） |
| 19.5 | 200 | **400 = 边界** | 400 | ⚠ rank4(V0) 压在关断沿 ⇒ 被采坏一半 |
| 39.5 | 323 ≈ 6.5 µs | 523 | 400 | ❌ **vc、v0 恒 0**（rank3/4 越界） |

**缩小 CCR4 补不回来**：SMP=39.5 时把 CCR4 从 150 减到 90，失效点只从 rank3 推到 rank4
（`vc` 恢复、`v0` 仍恒 0）——因为**扫描总长本身（6.5 µs）就超过整个导通期（6.2 µs）**。

### ③ "ADC 有改善吗"——分两半答

| 项 | 状态 |
|---|---|
| **增益型误差**（三相之间的相对增益） | ✅ **已消除**：逐相需要的偏置 +19/+29/+31 → **+4/+4/+3 码**；旁证：硬件 V0 与三相平均的均值差 −19.1 → **−1.0 码**；开环六步散差 11.0 → **4.3°E** |
| **采样保持 settling** | ✅ **已排除**：源码自算 τ≈15ns（7.5 周期 = 15τ）；唯一真正生效的加长（7.5→19.5，SMPR 验证）**没减小逐相幅值差** |
| **逐相幅值/斜率差（15~44%）** | ❌ 不是"读取误差"，是**采样顺序 rank 效应** —— 见④ |

### ④ ★ 交换次序的决定性实验：图样精确翻转 ⇒ 确认是 rank 效应

`RM2027_ADC_AC_SWAP=1` 把 **rank1 与 rank3 对调**（rank1=VC、rank3=VA），并把 DMA 槽位映射反过来
（保证 va/vb/vc 仍是引脚语义）。纯开环 3 秒 ×2 点，`ADC1_CHSELR` 用 SWD 验证不同（`0x013245` vs `0x013542`）：

| 配置 | 半A | 半B | 半C | 斜A | 斜B | 斜C |
|---|---|---|---|---|---|---|
| R 基线序（rank1=VA, rank3=VC） | 0.937 | 0.923 | **1.140** | 0.795 | 0.969 | **1.235** |
| S 交换序（rank1=VC, rank3=VA） | **1.193** | 0.986 | **0.821** | **1.218** | 0.982 | **0.799** |
| **两序取平均** | 1.065 | 0.955 | 0.980 | **1.007** | **0.976** | **1.017** |

- A 从"最弱 0.795"变"最强 1.218"、C 从"最强 1.235"变"最弱 0.799"，**B（两轮都在 rank2）几乎不动**
  ⇒ 纯顺序效应；且 A/C 比值互为倒数（0.644 × 1.524 ≈ 1）⇒ 没有其它机制混在里面。
- **两序平均后斜率散差 44.0% → 4.1%**（10 倍改善）；半量程散差 21.7% → 11.1%。
  ⇒ **"交换次序 + 平均"就是这样用的：离线标定一次，得到无偏的逐相幅值/斜率。**
- 数据：`evt_run_20261013_142656`（基线序）、`142729`（交换序）；配置表 `序交换_配置对应表.md`。

### ⑤ 但"交换次序"**不能直接用于在线判据**

判据每帧立即消费样本；顺序一交替就等于给阈值注入一个**交替偏移** ⇒ 闭环会更差
（与"换 V0 不重调判据"是同一类坑）。若要在线上用它，必须按**"同一个相的两步用相反的 rank 误差"**
来设计轮转（A 的两步相隔 3 步 ⇒ 每步轮转 2 格才能让误差反号），而且要先离线验证；
**这一步先不做**，因为判据侧用硬编码增益表已经达到同样效果（相内反对称 → 0.1°E）。

### ⑥ 合理的采样时间 = 7.5 周期（现状）

理由：① 它和 CCR4=200 一起，是唯一让六路都落进导通期且余量最大（76 tick）的组合；
② 19.5 会让 V0 压在关断沿上（实测已见副作用：六步散差 4.3→7.2°E）；③ τ≈15ns 说明它本来就够。

**板子已恢复到这一版并片上验证：`SMPR=0x00100072`（SMP1=7.5）、`CHSELR=0x013245`（基线序）、
`TIM1_CCR4=0xC8`（200）、`RM2027_NEVER_HANDOVER=0`、`V0=三相平均`、`三相增益归一`。**

## 九、六步分步"竖直增益 + 竖直偏移"：让换相连续、过零居中（2026-10-13 14:40）

用户目标（在 ADC 校准之后）：
① **换相时"悬空相读数"两侧连续**（用户的"测量是否合理"判据）；
② 过零点尽量落在步内**正中**（开环，不强制）。

### 为什么"连续"是对的目标（物理依据）

三相反电势互差 120°，而换相点落在步边界（该相 BEMF = ±半幅）⇒
**出去的悬空相反电势恰好等于进来的那一个** ⇒ 六步的悬空相读数拼起来，理想是一根**连续的三角波**。
所以"接缝两侧之差"（跳变）就是可量、可压的误差。

工具：`tools/cal-anchor.py <run> --step-fix`（闭式解，不迭代）。

### 闭式解（一条代数就够）

记每步两端**外推值** e0_s / e1_s（从 u∈[0.15,0.95] 直线拟合外推到该步两端——必须外推，
因为 u<0.12 是换相振铃）、幅值 A_s = e1_s − e0_s、中点 m_s = (e0_s+e1_s)/2。
施加 `d' = g_s·d + o_s` 后：

```
跳变  J_s = (g_s·A_s + g_{s+1}·A_{s+1}) / 2
居中  u0 = 0.5  ⇔  o_s = −g_s·m_s
```

取 **g_s = C/|A_s|**（C = 六步 |A| 的中位 ⇒ 把六步幅值**归一**）⇒ g_s·A_s = ±C 交替抵消
⇒ **六个跳变恒为 0**；再取 o_s = −g_s·m_s ⇒ **过零恒落在步正中**。
⇒ 两个目标同时精确满足，且表是闭式给出的。

### 标定结果（`evt_run_20261013_142656`，纯开环 3 s）

| 边界 | 步1→2 | 步2→3 | 步3→4 | 步4→5 | 步5→6 | 步6→1 |
|---|---|---|---|---|---|---|
| 原始跳变中位（码） | +33 | **−122** | **+120** | −41 | **+115** | **−126** |

- 原始：跳变 RMS **101 码**（全样本 114）；过零 u0 = 0.587 / 0.643 / 0.605 / 0.596 / 0.646 / 0.606（σ=0.023）
- **施加本表后：跳变 RMS = 0 码；过零 u0 = 0.500 × 6（σ=0.000）** ✓✓

**固件表**（索引按 step 1..6，`d' = g_s·d + o_s`）：

```
增益 g_s :  0.8628  1.1556  1.0064  0.8831  1.1497  1.0206      (±16%)
偏移 o_s :   −36     +61     −45     +41     −60     +42      (码)
```

接线图：`分步校正_拼图_20261013_142656.png`（灰=原始，外推到两端后**每步两端对不上**；
红=施加后**六个接缝全部接上**，过零点▲全部落在步正中）。

### ⚠ 一个必须记住的取舍

**只压跳变（只用偏移解）会把过零推出这一步**：仅偏移解的 u0 变成 0.585/0.553/0.393/0.531/0.616/0.344
（σ=0.100，有的已经 u0>1 即过零跑出步外）。⇒ **必须"增益归一 + 偏移居中"一起上**，
才能同时满足连续与居中；这也说明这两个自由度（12 个）对这两个目标是刚好够用的。

### ⚠ 闭环风险与重测理由

这一族是"随时间跳变"的补偿，交接 §5③ 记着它**在闭环里失败过**（5+ 变体）。
**但那个结论早于轮 20 的两项修复 —— "`waitTime` 表索引差 1" 与"换相屏蔽 BEMF_BLANK_FRAMES"
—— 而这两项正是治"换相点跳台阶"的。** 所以它值得重测。
建议路径：先在纯开环（`RM2027_NEVER_HANDOVER=1`）确认固件表与离线一致，再进闭环。

固件已加 `RM2027_STEP_GAINOFF`（`Mcu/g071/Src/adc_bemf.c` 的 `adc_bemf_get_delta()`，
**默认 0 = 关**，板上配置不变）。只改【判据用的 d】，窗口载荷仍记原始 va/vb/vc/v0
⇒ 日志语义不变、离线可用同一张表复算。

## 十、分步增益+偏移的【闭环验收】：失败（2026-10-13 14:40）

把 `RM2027_STEP_GAINOFF=1`（其余保持已知最好那版）编进去烧上跑闭环：

| 判定项 | 结果 |
|---|---|
| 交棒 / 闭环时长 | ✅ 7.76 s / 1.42 s |
| lock_trips | ✅ 0 |
| **超时 bemf_timeout** | ❌ **232 次**（此前各轮均为 **0**） |
| A×ci / 基准 | ❌ 0.23（此前 0.7~0.8） |
| 幅值中位 | **38 码**（基线 ~158） |
| 六步散布 | 10%（表观好于 24~26%） |
| 换相节拍 / duty | **2602 转/分** / [300, 512] |

⇒ **失败。过零检测被打坏**，换相由 22.5 ms 超时顶着走（所以"转速变高、散布变小"是假象，
不是改善）。数据 `evt_run_20261013_144004`。

### 固件确实施加了表（反汇编逐条核对）

`arm-none-eabi-objdump -d --disassemble=adc_bemf_get_delta`：

```
ldrh r0,[r2,#2] / ldrh r2,[r2,#4] / subs / sxth r0,r0     ← d = vph − v0
ldrb r4,[r3,#0]; subs r2,r4,#1; cmp r2,#5; bhi            ← step 范围检查
ldrsh r3,[r4,r5]                                          ← 取 sg[step]（表在 0x08008E54）
muls r0,r3; movs r1,#250; lsls r1,r1,#2 (=1000); bl __divsi3   ← ×sg/1000
adds r5,r5,r4; ldrh r3,[r5,#16]; adds r0,r0,r3; sxth       ← + so[step]
```

⇒ 是"**表在闭环里不 work**"，不是没生效。

### 机理（与"换 V0 不重调判据"是同一个坑）

这张表把判据信号**整体平移 ±60 码、并缩放 0.86~1.16**；而固件里
**过零检测的滞回（16 码）/ 阈值 / ADC 看门狗窗口**、以及
**`waitTime` 比例表 `wt_num[]`** 全都是按【未补偿】的信号尺度标定的
⇒ 检测点跑偏 ⇒ 认不到过零 ⇒ 只能靠 22.5 ms 超时硬踹。

**规律（第三次踩到同一个坑）：凡改动判据信号的"口径/尺度"，必须同步重调
滞回 / 阈值 / waitTime 表。** 或者更彻底：把判据做成**与幅值/参考都无关的量**
（判斜率与单调性，像 `adc_zc` 那个环形缓冲判据），那样补偿与换参考都不再影响检测点。

### 但表作为【测量校正】仍然成立

离线接缝图（`分步校正_拼图_20261013_142656.png`）证明：施加后**六个接缝全接上、过零全落在步正中**。
所以这张表的作用应该定位在**离线标定/诊断**，而不是直接进闭环。
要进闭环，必须先解决"检测器随信号尺度变化"这件事。

## 十一、把 `wt_num[]` 当"测量修正"重标 → **错判并撤回**（2026-10-13 14:44）

### 做了什么

查出 `Src/main.c` 的 `wt_num[6]`（每步 waitTime 比例，**= 换相提前量**）是按**旧配置**实测的
`p_open = 0.682/0.636/0.727/0.636/0.952/0.571` 反推的，而当前配置（V0=三相平均 + 三相增益归一）
实测 u0 = 0.587/0.643/0.605/0.596/0.646/0.606 ⇒ 于是按 `wt_num[s] = (1 − u0)×1000`
重标成 `{413, 357, 395, 404, 354, 394}`（旧表 `{314, 359, 269, 359, 47, 423}`）。
代数上这个式子 ≡ `ratio_old + (u0_old − u0_new)`，即"保留老提前量、只补检测延迟 δ 的位移"。

### 结果（`evt_run_20261013_144428`）：混合，且**不能算通过**

| 项 | 新表 | 旧表 + V0三相平均 |
|---|---|---|
| 交棒 / lock / 超时 | ✅ 8.00 s / 0 / **0** | ✅ / 0 / 0 |
| A×ci / 基准 | ✅ 0.70 | ✅ 0.71 |
| **六步散布** | ✅ **7%**（史上最好） | ❌ 14~26% |
| **转速** | ❌ **420 转/分** | 1450 转/分 |
| ci vs 波形 | ❌ 差 37% | ✅ 4~11% |

**"7%" 主要是"转得慢"的假象**：散布是相对量，步长从 ~2000 拍变 ~5000 拍 ⇒
同样的绝对抖动折算成电角度小 2.5 倍。

### 错在哪（这条比结果本身有价值）

**`wt_num[]` 不是"测量修正"，它是【换相提前量(advance)】的载体。**

- 旧表比例 0.05~0.42（大量提前）⇒ 转矩大 ⇒ 1450 转/分；
- 按 `1−u0` 重标成 0.35~0.41（接近教科书的 30°）⇒ 提前量小 ⇒ 转矩掉 ⇒ 420 转/分。

而按代数推导（"保留老提前量、只补 δ 位移"）**转速本该不变**，实际变了 ⇒
⇒ **结论：开环实测的 u0 不能直接搬到闭环。检测延迟 δ 在开环/闭环里不一样**
（斜率、换相屏蔽窗、过零接受窗都不同），"用开环 u0 标闭环的表"这个假设不成立。
⇒ 已把表**回滚**（哈希回到 `e4dc145358db4c53`，即已知最好配置）。

### 由此得到的**统一病根**（本轮所有闭环回归都能对上）

闭环的换相相位 = δ（检测延迟）+ `waitTime`。**δ 一旦变，相位就变。**
而这一轮我们每一次改信号通路都动了 δ：

| 改动 | δ 怎么变 | 闭环后果 |
|---|---|---|
| V0 硬件 → 三相平均 | 检测点整体移 0.4~3.7°E | 散布 4% → 14~26% |
| 加电压域"分步增益+偏移" | 信号整体平移 ±60 码、缩放 0.86~1.16 | 超时 **232** 次 |
| 换相顺序交换（在线用） | 每帧阈值交替偏移 | （未做，预判会更差） |
| 重标 `wt_num[]` | 提前量被改成"教科书 30°" | 转速 1450 → 420 |

### 下一步的想法（回答"根据转速得到预期过零时刻"）

**对，而且它就是解掉上面这一整张表的办法**：把换相时刻从"**检测事件的函数**"改成
"**转速时序的函数**"：

1. 用 `ci` 推算一个**固定节拍栅格**：`t_comm(k+1) = t_comm(k) + ci`（像开环那样自己走）；
2. **检测只用来慢环校正 `ci` 与相位**（低带宽，比如每转更新一次），
   而不是每一拍直接决定换相时刻（高带宽）；
⇒ **δ 的抖动就不进相位**了；六步不对称剩下的才是真正的驱动/机械因素。

这等价于经典无感 BLDC 的"过零 + 30° + 频率锁相/速度环"结构，也正是把
"ADC 校准 / V0 / 序交换 / 分步补偿"这四件事从"互相打架"变成"只影响一两个可独立调节的量"的前提。

## §十八 窗口流降采样：把"观测者效应"从源头拆掉（2026-10-14 晚，用户方案）

### 问题
窗口包 = 12 + 512×12 = **6,156 B / 21.3ms** ⇒ 需要 ~**289 KB/s**，而 1Mbaud 串口只有 ~**125 KB/s**
⇒ 天生超预算 2.3 倍。DMA 常年占 83%、主循环还要跑 512 次组包循环 ⇒ **扰动时序 ⇒ 过零认不上**。
实测（补偿 OFF 的波形轮）：2,576 个换相段里 **0.97% 整段无过零**（补偿 ON 时高达 23.26%）。

### 做法（`RM2027_WIN_EVERY_N`，默认 1 = 老行为）
**窗内仍全速采 512 点**（判过零要看逐采样，分辨率不能丢），但**只把每 N 个窗中的一个发出去**，
其余在**组包之前**就丢掉（组包 512 次循环 + DMA 都是扰动源，一起省掉）。
`win_seq` 照旧每窗 +1（主机从 seq 空档看出降采样）、`win_sent` 只数真正发出去的。

### 验证（同固件基线 OFF + 额度 6000，唯一差别 = 降采样；`test-05` vs `test-07`）
| 指标 | 不降采样 | **降采样 ×8** |
|---|---|---|
| 窗口包 | 248 | **70**（= 1/8，精确） |
| 事件帧 | 2,341 | **9,732（4.2 倍）** |
| 串口占用 | 103.8 KB/s（83%） | **59.9 KB/s（48%）** |
| **整段无过零** | 25/2576 = **0.97%** | **0/1292 = 0.00%** |

### 意义（三条）
1. **"波形轮必然扰动被测对象"这条约束被拆掉了** —— 以后看波形不再毁掉被测对象。
2. **波形轮同时变成近似可用的计数轮**（事件从 13% 提到 ~50%），带宽还有一半余量。
3. 它把 §十六那个发现（窗口流自己造出 ~9.5 次/秒漏过零）**从"分析时绕过"升级为"从源头消除"**。

## §十九 自适应电压偏移第 1 轮（`test-08` @ `4acaf20`，用户方案）：符号对、上限到

### 实现
- 误差信号（用现成变量，不新增测量）：`e = bemf_zc_time − ci/2`（拍，正 = 过零偏晚）；

- 计数器全放 RAM 走 SWD 读（`tools/ao-dump.py`）：`ao_off` / `ao_chg`（改动次数）/ `ao_nozc`（无过零次数）/ `ao_err`

### 两条结论
1. **符号规律被自动学出来了**：`ao_off` 的符号 = **奇步负 / 偶步正** ✓✓，与 §19 之前从 106 个闭环窗量出的
   "奇步过零下降、偶步上升"完全一致 ⇒ 用户那条"按奇偶决定方向"得到独立验证。
2. **★ 电压偏移能修的相位量有硬上限 = 该步半幅 A_s**：实测六步半幅只有 **86~145 码**
