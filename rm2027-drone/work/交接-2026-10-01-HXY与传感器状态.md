## 2. 今天确认的两条"器件级"结论

### 2.1 ★ 4/6 的判决窗口（code-auditor 给出，可复用）

```
detect_orientation 通过某面 ⇔ 4.81 < g_k·9.80665 < 14.81 ⇔ 0.490 < g_k < 1.510
  三轴全在窗口内 ⇒ 6/6 ｜ 全在外 ⇒ 0/6 ｜ 恰好一轴在外 ⇒ 4/6
```
⇒ 修 Y 之前 hxy 有一个轴 **3.6**（≫1.51）⇒ **4/6**；修后三轴 **1.007/0.888/0.779** 全在窗口内 ⇒ **6/6**。**与实测完全自洽。**

### 2.2 加计的异常是**器件给的**，不是驱动解码

- `burst-vs-single.tcl`：突发读与单寄存器读**一致**（差 6~16 码 = 活动数据抖动）
- code-auditor 穷举**所有字节配对**都无法还原 ~4678 码
- `PX4Accelerometer::update` 三轴共用**同一标量** `_scale`；旋转只做置换/变号 ⇒ **驱动数学上不可能造出逐轴差异**
- 配置侧全清白：`OIS_CONF=00`、`DATA_SAT=00`、`SEG_SEL=00`、FIFO 区全缺省、`HPF&LPF=80`

## 3. 待验收：标定成色（用户已完成六面，数据未回）

```
param show CAL_ACC*      ← 重点：hxy 那一路的 {X,Y,Z}SCALE
param show CAL_GYRO*     ← 单位是 rad/s，应 ≪0.01
param show CAL_MAG*
listener sensor_accel    ← 两路 |a| 都应 ≈9.8，且彼此差 <0.5 m/s²
listener sensor_gyro     ← 两路三轴都应 ≈0（|ω|<0.02 rad/s）
sensors status
```

**判据：**

| 看到 | 含义 |
|---|---|
| `CAL_ACC*_SCALE` 三轴都 ≈1 | 那个 bench 常数在起作用 ⇒ **必须长期留着，不能单独撤** |
| 明显偏离 1（如 0.78/0.89） | 标定自己解出了逐轴增益 ⇒ 将来撤常数**必须撤完重标** |
| 之前三条红字（`High Accelerometer Bias` / `Accel 0/1 inconsistent` / `Attitude failure`）消失 | ✅ 标定真的成了（一致性门限 `COM_ARM_IMU_ACC=0.7 m/s²`，标定前必然报红） |

⚠️ **"驱动常数 + 标定"是叠加关系**：要么永远留着常数，要么撤掉并**重新标定一次**。**别只撤不重标。**

## 4. 未决项（按优先级）

1. **标定成色验收**（§3）—— 最急，因为后续所有事都靠它
2. **参数持久化**：改参数 → 断电 → 复核（从未做过）
3. **选源该钉谁**（见 §5）—— 现在 `vehicle_acceleration` 用的是 **100 Hz 的 H104**，而板载 hxy 有 **1 kHz**
4. **`fail:` 日志**：投票器切换会打 `Accel/Gyro #i fail: OFF/STALE/TIMEOUT/ERR CNT/ERR DNST!`
   ⇒ 先看是谁被降权，再决定钉谁（**别急着手工钉 PRIO**）
5. **H104 的 X/Y 符号**用实物转动验证（放飞前必须）
6. **H104 提频**：上限 1000 Hz（UART@921600）；**建议只做 200 Hz**（纯赚：消除欠采样 + 对齐 `IMU_INTEG_RATE` 缺省 200）
7. **USART1 中断风暴**的真因已查明：NuttX 上电按 `57600` 采样 H104 的 115200 流（`defconfig:223`，仅 bootloader 用）

## 5. 选源：钉 hxy 还是钉 H104

| | hxy（板载） | H104（外挂） |
|---|---|---|
| 速率 | **1000 Hz**（SD 11.7 µs） | 100 Hz（SD 562 µs，5.6%） |
| 总线 | SPI1 直连 | 串口 + 帧解析 |
| 带宽 | 可配（ACC_CONF/GYR_CONF 的 BWP/ODR） | **固定 80~200 Hz**（PROFILE 决定，手册明说"用户无需单独配置"） |
| 健康 | 逐轴增益差 11~22%（待标定吸收） | 干净 1g |
| 身份校验 | ✅ `WHO_AM_I==0x6A` | ❌ **无身份校验**（只验 CRC+tag） |

**⇒ 若 A/B 两轮都干净，建议钉 hxy 作主 IMU**（1 kHz；多旋翼机型 `rc.mc_defaults` 会把 `IMU_GYRO_RATEMAX` 提到 800，1 kHz 刚好够），H104 留作 EKF 辅助。

**钉法（⚠️ 三条硬规矩）：**
```
param show CAL_ACC0_ID CAL_ACC1_ID CAL_GYRO0_ID CAL_GYRO1_ID
#   3735562 = hxy ；1677721613 (0x6400000D) = H104
param set CAL_ACC<idx>_PRIO 80
param set CAL_GYRO<idx>_PRIO 80
param save
# 重启
sensors status     # 只认 [vehicle_acceleration] selected sensor: 与 rate: 这一行
```
1. **绝不要用 `CAL_ACCx_PRIO 0`** —— 那是禁用，那一路会从 `sensor_combined`/`vehicle_imu` 整路消失
2. **改完必须重启**（`VehicleAcceleration` 自 latch 源，不重启不重评）
3. **判源只认 `sensors status` 的 `[vehicle_acceleration] selected sensor:`** —— 别用 `sensor_selection`（踩过它 661 s 未更新的坑）

**为什么之前是 hxy 被投票器选中、实际却用 H104**：`CAL_ACC0/1_PRIO` 出厂缺省 **−1** ⇒ 第一次参数更新 `change=-1-50=-51` ⇒ 两路优先级都被压到 **1** ⇒ 平票 ⇒ 同优先级不退位 ⇒ index 0（hxy）胜出；而 `vehicle_acceleration` 是自己 latch 的，两者可以不一致。

## 6. 现场命令的两条坑

1. **`listener` 的话题名必须在最前**：`listener sensor_mag -n 3` ✅ ／ `listener -n 3 sensor_mag` ❌
   （根因：`listener_main.cpp:178` 取 `argv[1]`，而 `px4_getopt` 会 `reorder()` 重排参数）
2. **`h104_imu` 的 `error_count` 恒为 0**（从不调 `set_error_count`）⇒ **不能**拿它跟 hxy 的 `error_count` 比"谁干净"
   要比就比：`[vehicle_imu] N` 的 data gap、`h104_imu status` 的 CRC坏/重同步、`hxy42688p status` 的 bad register/transfer/stale

## 7. 复现脚本（`work/spi-runtime/`）

| 脚本 | 用途 |
|---|---|
| `measure-point.tcl` | 干净单姿态测量（原子读 + 64 样本 + 静止门） |
| `hold-steady.tcl` / `byteorder-test.tcl` / `watch-rotate.tcl` | 等静止/等转动后连续记录，用于多姿态 |
| `burst-vs-single.tcl` | 突发读 vs 单寄存器读对照（判解码是否错位） |
| `chipstate-safe.tcl` / `rawbyte-dump.tcl` | 寄存器直读（⚠️ 手工拉 CS 时 `CR1` 必须 `0x1201`） |
| `flash-and-dump.sh` / `dumplog.sh` | 烧写并**尽快**抓 console 整块环形缓冲区 |

**三条踩过的坑（都在脚本头注释里）：**
- **绝不要动 `SPI1_CFG1` 的 DMA 使能位**（清了没恢复 ⇒ 之后读什么都恒 `0x1F`，看着像芯片挂了；恢复办法 = `reset run`）
- **"双读一致"不能用在活动数据寄存器上**（0x0C~0x17 是活动数据，两次读天生不同）
- **一轴一次 CS 周期原子读 16 位**，别拆成两次单字节读
