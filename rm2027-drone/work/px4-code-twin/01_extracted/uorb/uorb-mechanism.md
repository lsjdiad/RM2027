| 讲 | 不讲 |

| **★ 三份 `uORB.h`**（本板用哪份、宏签名不同的坑） | `uxrce` / ROS2 桥接 |

**★ 一句话总览（先记这个）：**
```
一个「模块」= 一段能被 NSH 命令启停的代码
              + 它订阅一些 uORB 话题、发布一些 uORB 话题
              + 它跑在某条【工作队列】上（不是自己开个线程）
              ↑
        uORB 就是它们之间唯一的通信方式（发布/订阅、按名字索引）
```

## 3. 三个核心宏（逐字展开）

**都定义在 `platforms/common/uORB/uORB.h`：**

### 3.1 `ORB_ID(_name)` —— `:80`
```c
#define ORB_ID(_name)   &__orb_##_name
```
**⇒ `ORB_ID(sensor_gyro)` 展开成 `&__orb_sensor_gyro` —— **就是取那个元数据结构的地址**。**
**⇒ 所以 `ORB_ID(x)` 的类型是 `orb_id_t`（`:60` 的 `typedef const struct orb_metadata *`）。**

### 3.2 `ORB_DECLARE(_name)` —— `:88` / `:90`
```c
#ifdef __cplusplus
# define ORB_DECLARE(_name)  extern "C" const struct orb_metadata __orb_##_name __EXPORT
#else
# define ORB_DECLARE(_name)  extern const struct orb_metadata __orb_##_name __EXPORT
#endif
```
**⇒ 只是**声明**（"有这么个元数据，别处定义了"）。**
**⇒ 注意 `__EXPORT` 和 `extern "C"` —— 都是为了让**不同编译单元/语言**能找到它。**

### 3.3 `ORB_DEFINE(...)` —— `:109`
```c
#define ORB_DEFINE(_name, _struct, _size_no_padding, _message_hash, _orb_id_enum, _queue_size) \
	const struct orb_metadata __orb_##_name = {  \
		#_name,                                  \
		sizeof(_struct),                         \
		...                                      \
	};
```
**⇒ **这才是实例化**（在 `.cpp` 里出现一次，全局就这一份）。**
**⇒ `#_name` 是 **C 预处理的字符串化** —— 把 `sensor_gyro` 变成 `"sensor_gyro"` 这个字符串。**
**⇒ 所以话题名有两个来源：**人写的 `.msg` 文件名** 与 **宏里的 `#_name`** —— 它们必须一致。**

### 3.4 `struct orb_metadata` 里装了什么 —— `:50`
```
o_name        话题名字符串（#_name）
o_size        结构体大小（sizeof(_struct)）
…             hash / id / queue_size 等（不同版本字段不同）
```
**⇒ 运行时 `orb_subscribe(ORB_ID(x))` 就是拿这个"名片"去索引话题。**

```

## 5. ★★ 语义（最容易误解的三条）

### 5.1 **last-value，不是队列**
```
uORB 默认【只保留最后一次发布的值】—— 慢的订阅者会【跳过】中间的值，不会排队积压。
⇒ 所以：
  · "我漏了一帧怎么办" → 不存在这个问题，你拿到的永远是最新的
  · "我能不能不丢数据" → 不能（除非给话题设 ORB_QUEUE_LENGTH > 1）
```
**⇒ `ORB_QUEUE_LENGTH`（`.msg` 里那个 `= 8`）就是给这种话题开的小队列**（默认 1）。

### 5.2 **是拷贝，不是共享内存**
```
发布 = 把结构体【拷进】uORB 内部
订阅 = 从内部【拷出】到你自己的结构体
⇒ 所以：拿到数据后，你可以随便改自己那份，不影响别人
⇒ 也所以：结构体越大，拷贝开销越大（这就是为什么 .msg 字段要克制）
```

### 5.3 **时间戳是"约定"，不是机制**
```
uORB 不管你的 timestamp 是什么。它是各模块自己填的，约定：
    timestamp        = 这条消息【发布】的时刻
    timestamp_sample = 数据【采样】的时刻（可能比发布早很多）
⇒ 两者差得大 = 从采样到发布之间的延迟大（排查实时性时看它）
```c

## 7. 你跑在哪：`task_spawn`（独立任务）vs `WorkItem`（借队列）

### 7.1 两种"跑法"
| 方式 | 谁在调度 | 什么时候用 | 代价 |
|---|---|---|---|
| **`task_spawn`（NuttX 独立任务）** | NuttX 调度器 | 需要**独立栈/独立优先级**、或会阻塞的活 | 每个模块一个线程 ⇒ **费 RAM、上下文切换多** |
| **`WorkItem`（借工作队列）** | 某条 `wq:*` 队列的线程 | ★ **绝大多数模块** | 与同队列的其他工作项**串行**（所以不能阻塞！） |

**⇒ PX4 的主流是 `WorkItem`** —— 几十个模块共享少数几条队列线程，省 RAM。

### 7.2 `px4::wq_configurations` —— 工作队列全集
**定义在 [`platforms/common/include/px4_platform_common/px4_work_queue/WorkQueueManager.hpp:50`](uorb-mechanism.md#^src-platforms-common-include-px4-platform-common-px4-work-queue-WorkQueueManager-hpp-50)（`:44` 是 `struct wq_config_t`）**，
每条的格式是 `名字{"wq:名字", 栈大小, 优先级}`：

| 类别 | 队列 |
|---|---|
| **控制** | ★ **`rate_ctrl`**（`{wq:rate_ctrl, …}`）—— `mc_rate_control` / `control_allocator` / `VehicleAngularVelocity` 都在这条，**优先级最高** |
| | `nav_and_controllers` · `vte` |
| **传感器总线** | `SPI0`~`SPI6` · `I2C0`~`I2C4` · `INS0`~`INS3` |
| **串口** | `ttyS0`~`ttyS9` · `ttyACM0` · `ttyUnknown` |
| **通用** | `hp_default`（高优先级默认）· `lp_default`（低优先级默认） |
| | `uavcan` · `test1` · `test2` |

**★ 为什么"驱动不能阻塞"（判据链）：**
```
多条工作项共享同一条 wq 线程 ⇒ 你阻塞 = 同队列所有人都卡住
⇒ 所以驱动用 "状态机 + ScheduleDelayed(下次时间)" 而不是 delay()/sleep()
⇒ 本项目实测过的例子：`px4::wq_configurations` 里 rate_ctrl 优先级 0，
   而输出那跳 dshot 在 hp_default(-18) —— 见 03_moc/03-module-map
```

**★ 本板队列优先级的**实测值**来源**：`build/rm2027_fmu-h743_default/px4_boardconfig.h`（`CONFIG_WQ_*_PRIORITY`）。

## 8. 出问题时的排查命令（NSH / QGC 控制台）

| 命令 | 看什么 |
|---|---|
| `uorb top` | **每个话题的发布频率 + 谁在发** —— 第一手资料 |
| `uorb top <话题>` | 只盯一个话题（如 `sensor_gyro`） |
| `listener <话题>` | 打印该话题**当前的值**（含字段名，靠 `.json` 生成的字段表） |
| `<模块名> status` | 该模块自己的状态（由 `print_status()` 实现） |
| `work_queue -p` | **实际起了哪几条 wq、优先级多少** |
| `dmesg` / 启动日志 | 模块启动、probe 成功/失败 |

**★ 判据示例（本项目实际的例子）：**
```
"两个 IMU 谁被选中？"  → uorb top / sensors status + listener sensor_selection
"话题没人发？"        → uorb top 里那一行频率是不是 0
```
