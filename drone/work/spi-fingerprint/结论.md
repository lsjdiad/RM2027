# 寄存器指纹结论（2026-09-30）

## 一句话
SPI1 上那颗 IMU **使用 BMI270 的寄存器布局**（数据寄存器 0x0C~0x17 实时变化，
BMI270 的 PWR_CONF/PWR_CTRL/ACC_CONF/GYR_CONF 序列有效），
**但它的 CHIP_ID(0x00) 读出来是 0x00，不是 BMI270 的 0x24**。

## 关键证据（run-bosch.log）
```
CHIPIDHUNT rd00 x3      : 0x0 0x0 0x0          ← ★ 芯片 ID 读出来是 0x00（BMI270 应为 0x24）
WATCH 0c+12 ffa4fed10898ffc50028ff4a           ← ★ 0x0C~0x17 数值在【变化】
WATCH 0c+12 ff65ff7c0892fff6ff49ff89              （BMI270 布局：0x0C~0x11=加速度 0x12~0x17=陀螺）
WATCH 0c+12 ffb3ff080851002a0021ff49              ⇒ 有实时传感器数据流
WATCH 0c+12 ffb5ff800890007cff5d011b
BMI270_READBACK 40=0xa8 41=0x2 42=0xa9 43=0x0   ← BMI270 的配置寄存器可读回
BMI270_TEMP 22=0x28 23=0x51 24=0x0
CHIPIDSEQ6: ff 00 6a 11 00 00                  ← 读序列，疑似有 1 字节偏移
```
另：`PWR_CTRL` 置 0 → 数据冻结（再次证明是它在控制数据流）

## ⇒ 这解释了全部矛盾
```
为什么 6 个标准驱动全不中？  → 因为 PX4 的 bmi270 驱动探针要求 CHIP_ID == 0x24
                              而这颗读出 0x00 ⇒ 探针直接失败
为什么指纹像 BMI270？        → 因为寄存器布局和电源序列确实是 BMI270 那一套
```

## 下一步（小改动，不用写新驱动）
**放宽 PX4 bmi270 驱动的芯片 ID 检查**，让它接受这颗的实际 ID（或接受 0x00 / 增加变体 ID）。
参考：`src/drivers/imu/bosch/bmi270/BMI270.cpp` 的 `probe()`。
⚠️ 若放宽后驱动能起，还要确认数据寄存器读取正确（可能有 1 字节偏移要处理）。
