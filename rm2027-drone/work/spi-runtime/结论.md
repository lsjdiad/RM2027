> ## ⚠️⚠️ 更正（2026-09-30）：本文【第三节】"这颗芯片没有 FIFO"的结论是**错的**
>
> 拿到厂商数据手册后逐条对照（深圳华轩阳电子 HXY《ICM-42688P 六轴惯性传感器模块》，
> 完整对照见 [`器件手册对照-华轩阳ICM42688P.md`](器件手册对照-华轩阳ICM42688P.md)，另见本文 §6.4）：
>
> - **本片【有】FIFO，地址在 `0x1C~0x21`**：
>   `FIFO_CFG0/1/2 = 0x1C/0x1D/0x1E`、`FIFO_STAT0/1 = 0x1F/0x20`、`FIFO_DATA = 0x21`
>   （2048 B，默认 By-Pass；每组 12 B：4 B Sensor_Time + GYR XYZ + ACC XYZ）
> - 我们当时读写的 **`0x48/0x49`(FIFO_CONFIG) 和 `0x24/0x25`(FIFO_LENGTH) 是 BMI270 的地址，
>   本片寄存器表里根本没有这两个地址** ⇒ "写不进 / 恒为 0" 的真正原因是**地址不存在**，
>   不是"没有 FIFO"。
> - 所以本文第三节的**现象描述（写不进、恒 0）仍然成立**，但**归因错了**。
> - **补救**：轮询实现本身不受影响（手册明确支持"查询方式"取数），但若想"不丢样本"，
>   正规做法是按 `0x1C~0x21` 重建 FIFO 路径。
>
> 另：`CHIP_ID(0x00)` 也**不在本片寄存器表里**（0x02-0x03 是 Reserved）；
> 真正的器件 ID 是 **`WHO_AM_I(0x01) = 0x6A`**。本文里凡以 `CHIP_ID==0x00` 为准的表述
> 都属于"读了一个不存在的地址"，能用只是碰巧。
>
> **仍然成立、且被手册正面证实的结论**：SPI 读**无 dummy 字节**（手册 §3.2.1：读命令
> 16 个时钟，Bit8-15 就是数据）、数据寄存器 `0x0C~0x17` **高字节在前**（手册里就叫
> `ACC_XH@0x0C`）、量程寄存器工作正常。

> 结论先行（原文，阅读时请结合上面的更正）：**PX4 的 SPI board 层、引脚、总线注册全部正确。** 之前"所有 SPI 设备都找不到"
> 的假象，是**这颗 IMU 芯片本身的两个特性**造成的，与板级移植无关。
> 全部结论均有**运行中硬件实证**（ST-Link + openocd 只读/受控读写），不是代码级推断。

## 二、真正的根因 #1：这颗芯片 SPI 读**没有 dummy 字节**

PX4 的 `BMI270::RegisterRead()`：

```cpp
uint8_t cmd[3] {};
cmd[0] = reg | DIR_READ;      // 0x80|reg
// cmd[1] dummy byte
transfer(cmd, cmd, 3);
return cmd[2];                 // ← 取第 3 个字节
```

本板器件是 `[cmd][data0][data1]...`（无 dummy），所以 `cmd[2]` 拿到的是 **reg+1 的内容**。

### 实测证据（三条独立）

| # | 实验 | 结果 | 说明 |
|---|---|---|---|
| 1 | 写 0x75=0x11 / 0x76=0x22 / 0x77=0x33，从 0x75 突发读 | `ff 11 22 33` | 第 2 字节就是 0x75 的内容 ⇒ **无 dummy** |
| 2 | 3 字节读 0x00 | `0x6a` | PX4 的 `RegisterRead(CHIP_ID)` 实际值 |
| 3 | 2 字节读 0x01 | `0x6a` | 与 #2 相等 ⇒ 整串结果右移一格 |

而 `probe()` 要求 `CHIP_ID == 0x24`（或补丁接受的 `0x00`）：拿到 `0x6a` ⇒ **必然失败**。
`DEVICE_DEBUG` 在 release 里不输出 ⇒ **完全静默**，这就是"没有任何 probe 日志"的原因。

### 修复

`BMI270.hpp` / `BMI270.cpp` 增加 `BMI270::transfer()` 拦截读操作：**时钟数不变**，
只把收到的字节数组右移一格、dummy 位填 0。于是 `RegisterRead` / `FIFOReadCount` /
`FIFORead` / `UpdateTemperature` 四条读路径**一个字都不用改**。

**实测效果（烧写后读 console buffer）：**

```text
INFO  [bmi270] Skipping BMI270 microcode upload (compatible part)
```

⇒ **`probe()` 通过、驱动启动、`Configure()` 跑到微码跳过分支。** 根因 #1 确认修好。

## 三、真正的根因 #2：这颗芯片**没有 FIFO**

修复后驱动进入 `FIFO_READ` 状态拿不到数据 → `_failure_count > 10` → 每 ~16 ms 一次
"RESET → 跳微码 → CONFIGURE → FIFO 空 → 再 RESET" 循环（console 里刷屏）。

### 停住 PX4 后读芯片真实状态

```text
0x00=00  0x21=00  0x22=20  0x23=81  0x24=00 0x25=00 0x26=00
0x40=AC  0x42=EC  0x48=00  0x49=00  0x7C=00 0x7D=0E 0x7E=00
DATA 0x0C-0x17 = FF E1 FE FC 04 95 00 00 00 15 FF F1

flush FIFO (0x7E=0xB0) 后：
  t+0.1s LEN=0x0 0x0
  t+0.6s LEN=0x0 0x0
  t+1.6s LEN=0x0 0x0
```

- `0x7D (PWR_CTRL) = 0x0E` ⇒ **驱动写的配置落进去了**（accel_en|gyr_en|temp_en）
- `0x40=AC`、`0x42=EC` ⇒ 驱动写的 ACC_CONF/GYR_CONF 也落了
- **`0x48/0x49 (FIFO_CONFIG_0/1) = 0x00`**，而驱动应该写 `0x03` / `0xD0`

### 受控写入测试（halt 状态下手工写、立刻回读）

```text
写前:  0x40=0x0  0x48=0x0  0x49=0x0  0x7D=0xe
写 0x40=0xA8 → 回读 0xA8   ✓ 写能落
写 0x48=0x03 → 回读 0x00   ✗ 写不进去
写 0x49=0xD0 → 回读 0x00   ✗ 写不进去
```

**⇒ 0x48/0x49 硬为 0x00，FIFO_LENGTH(0x24/0x25) 恒为 0 ⇒ 这颗芯片没有实现 FIFO。**

而 PX4 的 `bmi270` 驱动是 **FIFO-only**（`RunImpl` 只走 `FIFOReadCount`/`FIFORead`）
⇒ **无论怎么改 SPI/引脚/devtype，它都不可能拿到数据。**

## 四、传感器本体是好的（这点很重要）

数据寄存器 `0x0C–0x17`（BMI270 的 `DATA_0..DATA_11`）在 PX4 停住时**持续平滑变化**：

```text
T0: FF D6 FE 6C 04 9B 00 00 00 11 FF F0
T1: FF D1 FE 8A 04 8F 00 F9 00 15 FF F8
T2: FF C6 FE 62 04 84 00 0B FF 17 FF F5
T3: FF DB FE 45 04 97 00 FF 00 0F FF 01
```

- 6 轴全部有真实、小幅、连续的变化 ⇒ **是真数据，不是噪声/悬空**
- `0x18–0x1A` 有活跃的 24 位 SENSORTIME 计数器
- `0x40/0x42/0x44/0x45/0x7C/0x7D` 可读写，值与 BMI270 语义吻合
- 寄存器可写性扫描（写 0x5A 回读）：
  `0x3E` 仅 bit4 可留、`0x3F` 全可写、`0x44/0x45/0x4A` 可写、**`0x46–0x49` 全为 0**

## 五、这颗芯片到底是什么

**"BMI270 寄存器图兼容件"**，但有三处不同：

| 特性 | 正品 BMI270 | 本板实物 |
|---|---|---|
| CHIP_ID (0x00) | 0x24 | **0x00** |
| SPI 读时序 | `[cmd][dummy][data...]` | **`[cmd][data...]`（无 dummy）** |
| FIFO | 完整（0x48/0x49 可配） | **无（0x48/0x49 恒 0，LENGTH 恒 0）** |

⇒ **不是任何原版 PX4 驱动能直接驱动的器件。**

## 六、最终选择与结果：走【选项 B】—— 改造 `bmi270` 驱动为轮询读数据寄存器（2026-09-30 已实施）

### 6.1 结论

| 选项 | 结果 |
|---|---|
| **A** 新写板级轮询驱动 | 未采用（要重写 ~300 行，且会丢掉 PX4 现成的 `PX4Accelerometer`/`PX4Gyroscope` 发布链路） |
| **B** 改造 `bmi270` 驱动：`FIFO_READ` → 定时轮询读 `0x0C–0x17` | ✅ **已实施**：PX4 提交 `b746294`（分支 `imu/bmi270-polled-data-regs`），编译通过 |
| **C** 换正品料 | 未做（硬件侧的事） |

改动要点：新增 `STATE::DATA_READ`；`Configure()` 成功后兼容件走新路、**FIFO 路径完整保留**
（正品 BMI270 自动走原路）；`ScheduleOnInterval(1000, 1000)` = 1 kHz 定时轮询，
**不用 DRDY 中断**（INT1 行为未知）；`(x,-y,-z)` 保持原 FLU→FRD 轴向约定；
约 1 Hz 更新温度。详见 [`实现-轮询读数据寄存器.md`](实现-轮询读数据寄存器.md)。

### 6.2 这次实测**推翻了第三节末尾"下一步"里的两个隐含假设**，必须记下来

1) **数据寄存器是"高字节在前 (MSB-first)"，与 Bosch 手册写的 LSB-first 相反。**
   （第三节第 133–140 行那组 `FF D6 FE 6C 04 9B ...` 当时被当成"两种解释都凑不出 1g"，
   其实那张表是**在配置还没落稳的瞬间**抓的；这次重新用 `datadump.tcl` 抓 64 个样本，
   数据干净得多。判定方法与数据见新文档第 1 节。）

2) **静止 1g 在 `ACC_RANGE=0x03`（名义 16g，手册 2048 counts/g）下只读到 ~1185 counts。**
   实测四个量程是 **9289.5 / 4648 / 2316 / 1185**，严格 8:4:2:1
   ⇒ **量程寄存器本身工作正常，是绝对灵敏度比手册低 ~1.73x**。
   驱动里已用实测系数 `2048/1185 ≈ 1.7283` 做单点增益标定（只对兼容件生效）。

### 6.4 ★ 2026-09-30 拿到厂商数据手册后的重大更正

用户拿到实物厂商手册：**华轩阳电子（HXY）《ICM-42688P 六轴惯性传感器模块》**
（下载目录 `F58A73F6B8D6319EEDDDDA2ED27CA8C9.pdf`）。逐条对照后：

- ❌ **"本板器件没有 FIFO" 是错的**：本片有 FIFO，在 **0x1C~0x21**（2048B/341 组，默认 By-Pass）。
  以前读的 0x48/0x49/0x24/0x25 是 **BMI270 的地址，在本片不存在** ⇒ "写不进/恒 0"的真正原因
  是地址不对。本次实现（查询方式轮询）仍然成立（手册明确支持"查询方式"取数），
  但"FIFO 不可能"这个判断作废。
- ✅ **SPI 无 dummy 字节被手册证实**（§3.2.1：读 16 时钟，bit8 就开始驱动 SDO）——
  1f614b3 的 transfer() 补丁与手册时序一致，不再是经验 hack。
- ✅ **数据寄存器"高字节在前"被手册证实**（寄存器表就叫 ACC_XH@0x0C、ACC_XL@0x0D；
  正品 BMI270 手册是 LSB-first，两者相反 —— 这正是当初判定困难的原因）。
- ⚠️ **器件 ID 其实是 WHO_AM_I(0x01) = 0x6A**，0x00 不在手册表里。更严谨的识别是读 0x01。
- ⚠️ 本片软复位是 **SOFT_RST(0x4A)=0xA5**，中断配置在 **0x06/0x07**（不是 0x53/0x58），
  手册里**没有** BMI270 的微码上传机制（红线有了正式依据）。
- ⚠️ **1.73x 灵敏度之谜手册没能解释**：手册规格确实是 0.488 mg/digit（=2048 counts/g @±16g），
  实测只有 1185 counts/g。手册另给了两个**能定论**的实验（自测 ±6g/±8g 差分；翻板看 |a| 是否变化），
  见新文档 §5.4。

**完整逐条对照见 [`器件手册对照-华轩阳ICM42688P.md`](器件手册对照-华轩阳ICM42688P.md)。**

**注意：不要试图重新开启微码上传。** 之前实测上传 329 字节官方微码会把该器件锁死
（读全 0xFF，只能断电恢复），说明微码与其硅片版本不匹配。
