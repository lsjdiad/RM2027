# 开发日志 · 规则与索引

> 这里是 `fmu-h743` 板级移植的**过程记录**。
> 目的：三个月后回看时，能知道「当时为什么这么写、依据是哪一行、什么时候推翻过」。

## 一、写日志的规则

**每条记录必须能回答这 5 个问题：**

```text
1. 输入是什么     → 具体文件路径 + 页/图号 + （有的话）截图路径
2. 怎么得到的     → 用的什么工具/命令，能复现
3. 提取到什么     → 原始信息，不是结论
4. 据此决定了什么 → 结论 + 落到哪个文件的哪一行
5. 有没有后悔药   → 如果错了，怎么回退
```

**为什么这么严**：板级移植的坑几乎都是「当时以为对」。
比如把 `SPI1 = PA5/6/7` 写进 `board_config.h`，
如果没记「这个结论是哪来的」，三个月后没人敢改它。

## 二、commit 放不下的都放这里

```text
git commit message  → 只放「改了什么的摘要 + 为什么」
开发日志            → 放「推导过程、试错、命令、负结果、回退记录」
```

负结果尤其重要：**「试过、不通」比「没试过」值钱**，
因为它能阻止下一个人再花两小时。
