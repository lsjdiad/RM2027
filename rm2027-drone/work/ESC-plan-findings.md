# §1 问题的本质：为什么必须软件过零

三相无感 BEMF 过零检测的常规做法是**模拟比较器**：把悬空相的端电压与虚拟中性点送进 MCU 的 COMP，硬件在跨越瞬间翻转输出、触发中断。

**本板做不到**，原因是**引脚能力**（`STM32G071GB_datasheet` 的 Additional Functions 列）：

| 相电压 | 引脚 | COMP 能力 |
|---|---|---|
| VC | **PA2** | ✅ `COMP2_INM` |
| VB | **PA4** | ❌ **无** |
| VA | **PA5** | ❌ **无** |
| V0（虚拟中性） | PA3 | ✅ `COMP2_INP` |

**⇒ 三相里只有 1 相能进比较器 ⇒ 三相比比较物理不可行 ⇒ 过零必须由软件判。**
（这正是硬件设计方所说"本该硬件做、要靠软件实现"的那一项。）

# §2 ★ 信号物理：过零阈值是 **VBAT/2**，不是"任意值"

六步换相的一个步内（A 相上管通、B 相下管通、C 相悬空）：

```
V_A ≈ VBAT      V_B ≈ 0      V_C = 悬空（只有 BEMF，无电流）
虚拟中性点 V_n = (V_A + V_B + V_C) / 3
C 相过零 ⟺ V_C = V_n  ⟹  3V_C = VBAT + V_C  ⟹  【V_C = VBAT/2】
```

**⇒ ⇒ 结论 A（重要）**：**过零判据 = "悬空相端电压到达母线电压的一半"。**
**⇒ ⇒ 结论 B（更重要）**：**这个阈值 `VBAT/2` 我们本来就知道** —— `ADC_raw_volts` 一直在测电池电压。
**⇒ ⇒ 结论 C（最重要）**：**阈值不需要与 V0 (PA3) 实时相减** —— 它是**绝对值**，可以直接写进硬件比较阈值寄存器。

# §3 ★ 精度由**信号**决定，不由检测方法决定

这是我最初想错的地方（曾以为"采样率越高精度越高"）。实际：

```
BEMF 常数（4600KV 电机）≈ 217 µV / 机械RPM
过零处斜率 dV/dt ≈ BEMF_peak × ω ∝ R²   （R = 机械转速）
设有效噪声 20 mV：

  机械转速      过零处斜率      信号本身支持的过零精度
  1,000 RPM     0.159 V/ms     ≈ 126 µs      ← 根本模糊
  5,000 RPM     4.0   V/ms     ≈ 5   µs
  15,000 RPM    35.8  V/ms     ≈ 0.56 µs
  60,000 RPM    573   V/ms     ≈ 0.035 µs    ← 极锐
```

**⇒ ⇒ 两条推论：**
1. **低速时"微秒级"是假的** —— 信号自身就糊在 100 µs 量级。**任何方法（硬件比较器也一样）都做不到。** 这正是 AM32 必须有**开环启动**的原因。
2. **中高速（>1 万转）微秒级是真的** —— 但那是信号陡，不是采样快。

**⇒ ⇒ 设计后果：采样/中断的密度应该【跟着转速走】。** 而 AM32 手上已经有 `average_interval`（上一步时长），天然就能做到。

# §4 技术路线选型

| 路线 | 做法 | 中断率 | CPU | 精度 | 判定 |
|---|---|---|---|---|---|
| **A. 恒定高频轮询** | 定时器 167 kHz 触发，ISR 里比较 | **167k/s** | **8~17%** | 好 | ❌ 否决（D1） |
| **B. 窗口采样 + 插值** | 只在预期过零附近提速，插值出时刻 | ~50k/s | 3~8% | 好 | ⭕ 备选 |
| **★C. ADC 模拟看门狗 (AWD)** | **阈值比较在硅片里做**，只在跨越时中断 | **≈42k/s** | **≈2%** | 好 | ✅ **选定** |

**判据（技能要求：选型必须有判据，不能凭偏好）：**
1. C3 约束「中断占用 ≤5%」⇒ **A 直接出局**
2. B 与 C 都能满足 CPU；**C 的比较延迟恒定、与转速无关，B 有插值误差**
3. C 的实现在 AM32 里替换面最小（只在 ISR 触发源上换，换相逻辑复用）
4. B 仍需要"高频采样"这个动作；**C 把"高频"从"中断"降级为"DMA 搬运"** ⇒ 更干净

# §5 ★★ ADC 模拟看门狗（Analog Watchdog）—— 技术路线详解

## 5.1 它是什么

STM32 的 ADC 里有一组**硬件比较器**，叫模拟看门狗。它不是外设，而是**ADC 内部的一个数字比较逻辑**：

```
每次 ADC 转换结束（EOC）
   ↓
【硬件】把该通道的结果与预设的 [LOW, HIGH] 阈值比较
   ↓
越界 ⇒ 置 AWD 标志 + 触发中断          ← 只有越界才中断
未越界 ⇒ 什么都不做                     ← CPU 完全不知情
```

**⇒ 关键点：比较发生在 ADC 的转换流水线里，不需要 CPU 参与。**
**⇒ 这就是"用硬件做比较"—— 不需要任何外部比较器器件，也不需要 COMP 外设引脚。**

## 5.2 G071 上有什么（已核实）

```
LL_ADC_EnableIT_AWD1 / AWD2 / AWD3              三个独立看门狗，各有中断
LL_ADC_AWD_CHANNEL_2_REG / _4_REG / _5_REG ...  可监视任意普通通道
LL_ADC_IsActiveFlag_AWD1 / ...
```
**⇒ 三个看门狗 ⇒ 我们甚至能同时监视 3 个通道（本设计只需 1 个：当前悬空相）。**

## 5.3 为什么它能用在这儿（三条前提全部成立）

| 前提 | 是否成立 | 依据 |
|---|---|---|
| 过零判据是**绝对阈值**，不是"两路相减" | ✅ | **§2 推导**：`V_C = VBAT/2` |
| 阈值**能算出来** | ✅ | `ADC_raw_volts/2`（已测） |
| ADC 会**持续转换**该通道 | ✅ | DMA 循环扫描（无中断） |

**⇒ 三条都成立 ⇒ AWD 完全够用，而且比软件轮询更接近硬件比较器的行为。**

## 5.4 与"软件轮询"的本质差别

| | 软件轮询 | **AWD** |
|---|---|---|
| 谁比较 | CPU，每个采样点都要 | **ADC 硬件** |
| 中断次数 | = 采样次数 | **= 真正跨越阈值的次数** |
| 延迟 | 半个采样周期（随采样率抖动） | **一个转换周期（恒定）** |
| 滞后/消抖 | 要自己写施密特 | **AWD 的 [LOW,HIGH] 窗口天然就是施密特** |

**⇒ 你提的"施密特触发器"想法，在 AWD 上甚至不用写代码 —— 窗口的上下沿就是两个阈值。**

## 5.5 阈值怎么定（含消抖）

```
center = ADC_raw_volts / 2                 （母线电压的一半，按同一分压比折算）
hyst   = 由噪声水平定（初值取 ~16 LSB）      （对应相电压侧约 75 mV）
LOW    = center - hyst
HIGH   = center + hyst
```
**并在每次换相时重算**（电池电压会降；且悬空相变了 ⇒ 要改监视通道）。
**⚠️ 注意极性方向**：AM32 用 `rising` 区分"应该上升还是下降穿越"，AWD 的"越界方向"要与之一致。

# §6 详细设计（P2 阶段）

## 6.1 ADC 扫描（DMA，无中断）

```
6 通道： [电流, 电压, VA, VB, VC, V0]
  · 保留 V0 —— 便于台架期诊断（可对比 AWD 阈值与 V0 实测）
  · DMA 循环，长度 6
  · ADC 时钟 16→32 MHz，采样时间 19.5 周期（相分压源阻抗 ~8.3kΩ 的要求）
```

## 6.2 触发

```
· 触发源：软件 → 【新的定时器 TRGO】（不复用 TIM6，避免破坏 10 kHz 任务）
· 频率分档（依据 §3）：
    低速（步长 > 200 µs）:  20~40 kHz   —— 反正信号也糊
    中速                   60~80 kHz
    高速（步长 < 40 µs）: 120~150 kHz
· 分档判据用 average_interval（AM32 已有）
```

## 6.3 AWD 中断

```
· 监视【当前悬空相】通道，窗口 [center-hyst, center+hyst]
· 中断里做的事 = AM32 原来 ADC1_COMP_IRQHandler 做的事：
     沿用 interruptRoutine() + 原有的"半周期内假边沿丢弃"保护
· 换相时（changeCompInput）：重设监视通道 + 重算阈值
```

|---|---|---|
| 1 | `Mcu/g071/Src/ADC.c` | `ADCDataDMA[6]`、时钟 /2、6 通道序列、DMA 长度 6、回调映射 |

# §7 ★ AWD 的真实边界（补正 §5 的"太轻巧"）

**§5 只讲了 AWD 能做什么，没讲它做不到什么。补上 —— 这几条直接改了设计。**

## 7.1 它省的是"中断"，不是"转换"

```
AWD 只在【每次转换完成】时顺带比阈值。
⇒ ADC 不转换该通道时，AWD 一无所知。
⇒ 中断率 167k/s → ~42k/s（省 4 倍），但 ADC 该转还得转（DMA 后台搬，不占 CPU）。
```
**⇒ AWD ≠ 省掉采样。它只是让"比较"这件事从 CPU 搬到硅片。**

## 7.2 ★★ 判定分辨率 = 该通道的【两次转换间隔】，不是总采样周期

| 方案 | 悬空相通道的转换间隔 | 过零判定分辨率 | 最高转速(步长24µs)下误差 |
|---|---|---|---|
| 6 通道轮询 @167 kHz | **6 µs** | **6 µs** | 步长的 25% ⇒ **电角度 ~15°** ⚠️ |
| **2 通道轮询 @500 kHz** | **2 µs** | **1~2 µs** | 步长的 8% ⇒ **电角度 ~5°** ✅ |

**⇒ ⇒ 设计修正：快通道只留 `[当前悬空相, VBAT]`，每次换相重设序列。**
**电流/电压/温度挪到慢通道（主循环按需触发，或低频 AWD 不使能中断）。**

## 7.3 另外三条真实约束

| # | 约束 | 后果 | 缓解 |
|---|---|---|---|
| 1 | **阈值必须跟着母线电压走** | 大电流时 VBAT 瞬降 ⇒ 阈值滞后 ⇒ 过零判偏 | 每次换相用最新 `ADC_raw_volts/2` 重算（42k/s 足够快）+ 滞回兜底 |
| 2 | **AWD 每次只监视 1 个通道** | 换相后必须重设通道；**重设前 AWD 还在监视旧相 ⇒ 可能误触发** | **用 AM32 原有的 `maskPhaseInterrupts()`/消隐窗口遮住重设期** |
| 3 | **AWD 有硬件滤波选项**（`LL_ADC_AWD_FILTERING_*`） | 滤波 N 次可抗噪，但**增加 N 个转换周期的延迟** | 初版不用；噪声大且转速不高时再启用 |

## 7.4 结论（修正后的路线）

**路线 C 依然成立**（比 167 kHz 轮询省 4~8 倍中断），**但必须加上序列设计**：

```
快通道： [当前悬空相, VBAT]        2 通道，~500 kHz，AWD 使能中断
慢通道： [电流, 电压, 温度]         低频（主循环按需）
换相时： ① 屏蔽 AWD（沿用 AM32 的 mask）
        ② 重设快通道序列（换成新的悬空相）+ 重算阈值
        ③ 消隐期结束后使能 AWD
```
