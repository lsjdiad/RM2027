# 为了成功闭环换向 —— 交接文档

> 最后更新：2026-10-11 22:30
> 固件仓库：`~/桌面/RM2027/AM32-rm2027`　当前分支：`串口测试-g071`
> 硬件：自研电调板（STM32G071）+ HSKRC 1404-4600KV 电机（9N12P，12 磁钢 = 6 对极），
> 台架供电 12V，被测目标：**无感六步闭环换相**

---

## 一、一句话结论

**闭环能起来（开环起步 → 交棒 → 闭环都通了），但只能好 2 秒。**
2 秒后转速从 1670 转/分掉到 450，占空比顶到上限、电流翻倍也拉不回来。
已经定位到"电调内部**步长估计被推大并锁死**"这条正反馈，但**把它推大的那一下是谁干的，还没钉死**。

---

## 二、问题现象（有数据）

### 2.1 一次 20 秒连续记录的完整过程

（图：工作区根目录 `闭环全过程2.png`）

| 时段 | 转速 | 占空比 | 电流 | 状态 |
|---|---|---|---|---|
| 0~1.5 秒 | 爬到 **1700** | 0→13% | 45 | 起步加速 |
| **1.5~2 秒** | **1670~1700** | **13%** | 45 | **最好时（比开环 1670 还略快）** |
| 2~3.5 秒 | **掉到 400~500** | **降到 7.5%** | 35 | 转速塌，油门反而减了 |
| 3.5 秒 | 仍 400~500 | **跳到 20%（撞上限）** | **70** | 速度环开始拼命加 |
| 3.5~10.5 秒 | 300~600 抖 | 20% 顶格 | 70 顶格 | 电在烧，转速不涨 |
| 10.5 秒后 | — | 0 | 0 | 手动断电 |

**最关键的一组对比：**

- 1.5 秒时：**13% 占空比 → 1670 转**
- 5 秒后：**20% 占空比 → 450 转**

⇒ 同样的电，出力掉了一半以上 ⇒ **不是"功率不够"，是"效率塌了"**（电都变成电流 35→70 和热）。

### 2.2 交棒后头 42.7ms 是正常的

（图：根目录 `波形相位.png`、`闭环综合.png`）

- 每个换相步**恰好认到 1 次过零**（33 个步 / 33 次，一次不多不少）
- "过零 → 换相"的延迟 / 换相步宽 = **0.395**（理想 0.50，即过零后 30° 换相）⇒ 相位基本正确、略偏早
- 转速中位 1333 转/分

⇒ **所以问题不是从交棒就有的，而是 2 秒后才恶化。**（这也是为什么只看 RAM 里那 1 秒多的数据时会误判"一切正常"。）

## 三、已经查清的因果链

### 3.1 闭环怎么换相

```
每 41.7µs 采一帧「悬空相电压 − 虚拟中性点」(delta)
   ↓ 判据（adc_zc.c）：① 变号 ② 斜率≤100码/点 ③ 回看2点单调
认出过零 → 等 waitTime（= ci/2，即 30° 电角度）→ 换相
```
`ci` = `commutation_interval`，电调对"一步多长"的估计（六步平均）。

### 3.2 塌陷的机制：正反馈自锁

1. `ci` 有**天花板 13000 拍 = 6.5ms**；实测 5~10 秒的间隔中位 **6.583ms** ⇒ **正好贴在天花板上** ⇒ **电调是「主动」按 6.5ms 一步在换相，不是被转子拖慢的**
2. 固件里"**变长方向没有限制、变短方向每步只许降 1/8**"（本意防假过零）⇒ **不对称** ⇒ 一旦被扰动推大，几乎回不来
3. 于是：某次真实扰动（转子卡一下 / 丢一次过零）⇒ `ci` 被推大 ⇒ 换相变晚 ⇒ 相位偏 ⇒ 转矩下降 ⇒ 转速更低 ⇒ 过零更难认 ⇒ `ci` 更大 …… **锁死在 6.5ms**

### 3.3 还没钉死的两处（下一步的入口）

1. **是谁把 `ci` 第一次推大的**（需要一个"塌陷那一刻"的现场）
2. **`waitTime` 读出来恒为 6152 拍 = 3.076ms** —— 而当时步长只有 1.0ms，按设计它该是 **0.5ms**（半步）。**6 倍**。这个量在换相函数末尾按 `步长/2` 计算，正常不可能出这个值，只可能"算完没被更新"或"被别处覆盖"。

## 五、数据采集方式（两种，互补）

### 5.1 换相事件流（看长时趋势）

每次换相发一包 20 字节：`A5 5A A5 5A | seq u16 | ts u32 | delta i16 | step u8 | wait u16 | duty u16 | cur i16 | crc8`
- 约 1000 包/秒 ⇒ 约 18KB/s ⇒ **1 Mbaud 下轻松**
- **时间覆盖率 100%**，可连记几十秒（不受 16KB RAM 限制）
- PC 端：`脚本/evt-dump.py`（收 + CRC 校验 + 存 CSV）→ `evt-plot.py`（四栏图）→ `evt-analyze.py`（按时段统计）

### 5.2 窗口式全速采样（看逐帧波形）

- **窗口内**：24kHz 全速采 512 帧（21.3ms），存 delta + step
- **窗口间**：整窗用 DMA 发出去（1548 字节，约 15.5ms）⇒ **采与发时间错开，数据永不被自己干扰**
- 覆盖率约 **58%**
- PC 端：`脚本/win-dump.py`（收 + 三合一图：电压 / 转速 / 过零）
- **触发时刻可设定**（用于对比不同时段）：SWD 直接改变量，不用重编译
  ```
  mww 0x200003b4 36000    # zcw_trig_delay_frames = 交棒后 1500ms（1 帧 = 41.67µs）
  mww 0x200003b4 120000   # 交棒后 5000ms
  ```

### 5.3 接线与纪律

- **串口 RX 接电调 PB6，共地，1 Mbaud**（电调用的是半双工单线）
- **一次别跑太久：闭环 ≤7 秒**（电机会发热，实测 20 秒会烫）
- **跑之前先确认母线 ≥1100**（`bash 脚本/esc-snap.sh | grep bat`）
- 读状态用 `脚本/esc-snap.sh`（SWD，非侵入式；它 halt 后会喂狗，因为固件开了 IWDG）

## 七、给接手人的建议（按优先级）

1. **先查 `waitTime` 恒为 6152（3.076ms）的来源。** 改动小、最可疑：它本该等于半步（当时约 0.5ms）。
   - 写点在 `Src/main.c` 的 `commutate()` 末尾：`waitTime = (commutation_interval >> 1) - advance;`
   - 怀疑：闭环这条路上 `commutate()` 是否走到了这一行；或者 `advance`/`commutation_interval` 在那一刻是什么值
2. **给 `ci` 的上升方向也加限制**，并把天花板 6.5ms 换成一个"基于已知转速的合理值"（开环已知约 1.0ms/步，天花板给 2~3ms 就够）。
3. **抓"塌陷那一刻"的现场**：短跑 7 秒，把窗口采样触发设在交棒后 2~5 秒之间（扫几个值），对比塌陷前后的波形相位。
4. **两个已排除的方向**（别再回头查）：
   - "闭环**费电**"——实测闭环占空比 15% 比开环 17% 还低，电流也相当；
   - "判据**认不到**过零"——实测认到 7464 次、拒收仅 127 次，且"每步恰好 1 次"。

## 八、本次调试中被验证/推翻的结论（避免重复劳动）

| 一度以为 | 实测结果 |
|---|---|
| 闭环把占空比推满了（所以费电） | **否**：占空比 15% < 开环 17% |
| 判据"严格单调"把真过零拒了 | **部分对**：改 MONO_N 4→2 后拒收 7384→127，但那不是"慢"的主因 |
| "低惯量被齿槽抓住"（堵转） | **否**：卡顿时电流只 28~57，堵转应接近 110 |
| "过零检测失效、信号消失" | **否**：是被拒样本只有 ±10 码，我误读了过零瞬间的正常采样 |
| 闭环稳态已达标（1629 转/分、差 2.5%） | **不完整**：RAM 只存 1 秒多，读到的是第 2~3 秒那段正常期，漏掉了 5 秒后的塌陷 |
| 过零时刻往前移能补偿"越来越慢" | **否**：扫 0/84/168/336 拍 ⇒ 前移越多转速越低（前移 = 换相提前 = 反向转矩） |
