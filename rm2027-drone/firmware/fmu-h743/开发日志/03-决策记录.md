## D-02 · `default.px4board` 先命名为 `default.px4board.wip`

- **日期**：2026-09-28
- **输入**：PX4 顶层 Makefile 用 `find boards -name '*.px4board'` 枚举全部构建目标
- **决定**：草稿阶段用 `.wip` 后缀，**故意不被 glob 命中**
- **为什么**：
  ```text
  若直接叫 default.px4board，它会立刻出现在 `make list_config_targets` 里，
  还会出现在 CI / build_all 的枚举中 —— 而它现在是半成品，
  一旦被误构建就是一堆看不懂的报错，污染构建目标列表。
  ```
- **落点**：PX4 源码 `boards/rm2027/fmu-h743/default.px4board.wip`
- **回退/推进方式**：引脚确定后 `git mv default.px4board.wip default.px4board`
- **后续注意**：README 里要写明这一点，否则下一个人会以为文件名写错了

## D-05 · PX4 侧用独立分支 `board/fmu-h743`，不碰 `main`

- **日期**：2026-09-28
- **输入**：PX4 仓库当前在 `main` @ `2c47a16`，工作区干净（0 改动）
- **决定**：新建分支 `board/fmu-h743` 承载板级工作
- **为什么**：
  ```text
  main 跟随上游，随时可能 git pull；
  板级文件是长期半成品，混在 main 上会：
    1. 每次 pull 都要处理未提交改动
    2. 无法干净地分辨「上游的改动」与「我们的改动」
  ```
- **回退方式**：`git checkout main` 即可完全回到上游状态
- **后续注意**：PX4 升级时在 main 上 `git pull`，再 `git rebase main`（或 merge）到本分支

## 回退/返工实录（本次会话真实发生的）

> 用户要求「回改、回退都要记录原因」。以下为本轮实际操作中真实发生的返工。

### R-01 · `git commit --amend` 把归档文件误并进 commit 1

- **现象**：commit 1（`.gitignore` 瘦身）的 `--stat` 里多出 `archive/` 两个文件
- **原因**：
  ```text
  archive/ 当时已经 git add 到索引里，而我用 `git commit --amend --reset-author`
  修作者信息 —— amend 会把「当前索引」一起提交进去。
  ```
- **修复**：
  ```bash
  git reset --soft b557fae   # 退回，保留全部改动
  git reset -q               # 全部取消暂存
  git add .gitignore && git commit -F /tmp/m1.txt
  git add archive/   && git commit -F /tmp/cmsg.txt
  ```
- **教训（已生效）**：**`--amend` 之前先 `git status` 确认索引是干净的。**
- **同类二次**：任务 1 的笔记被 `git add learning/` 扫进 commit 3，同样用
  `git reset --soft` + `git reset -- <file>` 拆出。说明**批量 `git add 目录` 有风险**。

### R-02 · `what_i_do.md` 格式整理时手滑改了 3 处文字

- **现象**：归一化校验报出 24 处差异，其中 3 处是**真正的文字改动**：
  ```text
  1. 我自己加了「PX4 setup 目录：」这个标签（原文没有）
  2. 把 4 个箭头 → 写成了 ->
  3. 把两行 URL 的括号说明拆到了下一行（原文是一行）
  ```
- **原因**：手写替换内容时凭印象写，没有逐字对照原文
- **修复**：按原文逐字回填，重新校验 → 「原文有、新文件没有」= 0 条
- **教训（已生效）**：
  ```text
  做「仅格式」任务时，必须有一个可执行的「内容守恒」校验，不能只靠肉眼看。
  本次校验器：去列表标记/引用标记/反引号 + 空白折叠 → 逐行比对
  ```

## D-07 · 引脚提取改走「渲染成图 + 引脚号当锚」（取代 D-03）

- **日期**：2026-09-28（与 D-03 同日，用户提醒后推翻）
- **触发**：用户指出「其实 fmu 的 pdf 都已经标注了啊？总不能让我再给念一遍」
- **做法**：
  ```text
  1) pdftoppm -r 300 -png 渲染成图
  2) pdftotext -bbox-layout 取文字坐标
  3) 用「引脚号」当锚（不是引脚名！），按 y 坐标关联网络名
     —— 经验值：网络名中心 ≈ 引脚号中心（Δ≈0.7pt）
     而引脚名的 y 偏 3.6~25pt，且 VDD/VSS 无 GPIO 名会让名字列表整体错位
  4) 引脚号 → 引脚名：查 datasheet Table 9 (LQFP100)
  ```
- **两道校验**（缺一不可）：
  ```text
  A. 看图：切条带 300dpi 渲染，肉眼核对关键行
  B. datasheet AF 交叉校验：每个网络名必须是该引脚的合法复用功能
     → 本次 48 个信号引脚 100% 命中，故判定「高置信」
  ```
- **产出**：`../引脚映射-H743.md`
- **回退方式**：若发现某行与实物不符，改该行并在 `04-待确认与风险.md` 记录
- **教训**：
  ```text
  失败的方法（纯欧氏距离最近邻）之所以看起来"此路不通"，
  是因为它同时犯了三个错：用欧氏距离而非同线对齐、用引脚名而非引脚号当锚、
  以及——从头到尾没看图。
  ```
