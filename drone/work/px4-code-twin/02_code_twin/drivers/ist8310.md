# `src/drivers/magnetometer/isentek/ist8310/` —— 磁罗盘（I2C4，0x0C）

> **运行时一句话**：它是 **50 Hz** 的慢速轮询驱动，跑在 **`wq:I2C4`**（本板优先级 **-12**），
> 发 `sensor_mag`。它 **probe 会校验 `WAI`（WHO_AM_I）**，是本板"身份坐实"的关键一步。
> **⇒ 它给 EKF2 提供唯一的航向观测（本板无 GPS、无光流）。**
> 行号基准 `源码根（见 `tools/source-root.conf`）` HEAD `3b5de24`。
> **⚠️ 这个驱动在本项目历史上被"冤枉"过** —— 见 §4，那段是本篇最有价值的部分。

## 4. ★ 这个驱动被冤枉的那段历史（教学价值最高）

**当年的结论**（**已作废**）：
> "实物不是 IST8310，是 Voltafield AF9838" —— 依据是 `ist8310 -I -b 4 start` 报 `WARN`。

**真相**（三重证据，`rc.board_sensors:12-28` 与 [`i2c.cpp:57`](ist8310.md#^src-boards-rm2027-fmu-h743-src-i2c-cpp-57) 有完整记录）：

| 证据 | 说明 |
|---|---|
| ① `af9838.cpp` 的 `probe()` **从不比较读到的 ID** | [`src/drivers/magnetometer/voltafield/af9838/af9838.cpp:67`](ist8310.md#^src-src-drivers-magnetometer-voltafield-af9838-af9838-cpp-67)：循环里只要 `transfer(&REG_PCODE,1,&id,1) == PX4_OK` 就 `return PX4_OK`（`:74-78`），**读到的 `id` 一次都没比较**。⇒ 它把 IST8310 **认成了 AF9838**，读数当然是错的（标度/复位/自检三处与手册不符）。这就是"错驱动认错芯片" |
| ② 那次测试**走的是 `-X` 而不是 `-I`** | [`platforms/common/i2c_spi_buses.cpp:766`](ist8310.md#^src-platforms-common-i2c-spi-buses-cpp-766) 只有 `-X` 路径会打 `WARN`；`-I` 打的是 `ERROR`。当年报的正是 `WARN` ⇒ **根本没遍历 Internal 总线**（`I2CBusIterator` 在 `-X` 下只走 external） |
| ③ 缺省地址是 0x0E，而本片在 0x0C，且代码只用 0x0C~0x0F 写软复位、**不用来读** | [`ist8310_main.cpp:45`](ist8310.md#^src-src-drivers-magnetometer-isentek-ist8310-ist8310-main-cpp-45) + [`IST8310.cpp:107`](ist8310.md#^src-src-drivers-magnetometer-isentek-ist8310-IST8310-cpp-107) ⇒ 不传 `-a 0x0C` 永远读不到 |

**⇒ 最后一句坐实身份的动作**：
```
ist8310 -I -b 4 -a 0x0C start    →  ✅ device_id Type=0x06(I2C:4 0x0C)，|B|=0.259 G
```
`[实测]`（用户 2026-09-30 在 QGC MAVLink Console 里敲出来的）

**⇒ 三条可迁移的纪律**（本项目已登记）：
1. **`probe()` 必须比对器件 ID**（不校验 ID 的驱动 = 会认错芯片的驱动）。
2. **报错等级本身是证据**：`WARN` 和 `ERROR` 来自不同代码路径，能反推你走的是哪条路。
3. **"起不来"要分三层**：总线没遍历到 / 地址不对 / 器件真坏 —— 三者现象都是"no instance started"。
