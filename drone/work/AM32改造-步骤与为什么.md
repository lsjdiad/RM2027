# AM32 改造步骤 —— 从开源到能跑我们这块板

> 对象：AM32 上游 `2738df3`　→　我们的 `RM2027_ESC_G071`
> 改动量：**6 个文件 / +261 −4**（4 改 2 新）
> 补丁：`esc-artifacts/AM32-RM2027.patch`（386 行）
> 配套：`ESC-plan-task_plan.md`（计划）、`ESC-plan-findings.md`（技术路线）、`ESC-引脚映射-已核对.md`（引脚依据）

---

## 0. 先看 AM32 长什么样（理解后面所有改动的钥匙）

```
Inc/targets.h            ← 【核心】所有板子的定义都在这一个文件里
Mcu/g071/Src/            ← G071 的底层实现（官方已支持）
Src/                     ← 与 MCU 无关的通用逻辑（换相状态机在 Src/main.c）
```

**关键架构（决定了我们改动能这么小）：**

| 抽象层 | 是什么 | 我们的板要做什么 |
|---|---|---|
| **target** | 一块板子的参数（量程、分压比、电流灵敏度…） | **新增一个** |
| **hardware group** | 一块板子的**引脚映射** | **新增一个** |
| **BEMF 来源** | `Src/main.c` 只要一个**布尔量** | **换掉实现，接口不变** |

**⇒ 因为 AM32 把"板子差异"抽象成了两个宏块 + 一个布尔接口，所以我们只改了几百行。**

## 步骤 1：先让它能编（`Makefile` +1 −1）

**现象**
```
Src/main.c:1773: error: array subscript 0 is outside array bounds
                of 'const struct devinfo[0]' [-Werror=array-bounds]
```

**为什么报错**：AM32 把 `devinfo` 放在**地址 0**（`(struct devinfo *)(0x1000 - 32)`），
新 GCC 13 认为这是越界访问 ⇒ 报错。

**改动**
```make
CFLAGS_BASE += ... -Werror -Wno-error=array-bounds -Wno-error=stringop-overflow ...
```

**验证**：`make ARM_SDK_PREFIX=arm-none-eabi- AIKON_PRO_G071` 编过。

**⇒ 这一步纯属**工具链版本兼容**，与逻辑无关。**

## 步骤 2：认领我们的板子（`Inc/targets.h` +73）

**现象**：AM32 有 12 个 G071 硬件组，但**没有和我们板子引脚一致的**。

**★ 关键发现**：**AM32 原生的 `HARDWARE_GROUP_G0_K` 几乎就是我们这块板**——

| AM32 `G0_K` | 我们板子 | |
|---|---|---|
| `PHASE_C_LOW/HIGH = PA7/PA8` | C_LIN/C_HIN = PA7/PA8 | ✅ |
| `PHASE_B_LOW/HIGH = PB0/PA9` | B_LIN/B_HIN = PB0/PA9 | ✅ |
| `PHASE_A_HIGH = PA10` | A_HIN = PA10 | ✅ |
| `PHASE_A_LOW = PB1` | A_LIN = **PB15** | ❌ **唯一差异** |
| `INPUT_PIN = PB4` | DShot = **PA6** | ❌ 第二个差异 |

**⇒ 所以我们的硬件组 = 复制 `G0_K`，改两行。**

**改动（`Inc/targets.h`）**
```c
#ifdef HARDWARE_GROUP_G0_RM2027        /* = G0_K，只改两处 */
#define INPUT_PIN LL_GPIO_PIN_6        /* PB4 -> PA6，同为 TIM3_CH1 */
#define PHASE_A_GPIO_LOW LL_GPIO_PIN_15/* PB1 -> PB15 (TIM1_CH3N) */
/* C/B/A 其余引脚原样 */
#endif

#ifdef RM2027_ESC_G071
#define TARGET_VOLTAGE_DIVIDER 110     /* (47K+4.7K)/4.7K = 11.0 -> ×10 */
#define MILLIVOLT_PER_AMP 60           /* 3mΩ × 20V/V */
#define CURRENT_OFFSET 0               /* INA240 REF 接 GND（原理图实测） */
#define DEAD_TIME 60
#define VOLTAGE_ADC_PIN/CH  PA0 / CH0
#define CURRENT_ADC_PIN/CH  PA1 / CH1
#define HARDWARE_GROUP_G0_RM2027
#endif
```

**为什么这么省**：**AM32 的引脚不是硬编码的** —— `Mcu/g071/Src/peripherals.c` 用的是
来自硬件组的 `PHASE_x_GPIO_LOW/HIGH` 宏 ⇒ **改宏就等于改引脚**。

**⚠️ 注意**：`targets.h` 里**不要**定义 `SIXTY_FOUR_KB_MEMORY` ——
权威是 bootloader 的**运行时握手**（`devinfo@0x08000FE0` 的 `deviceInfo[4]=0x2b` ⇒ EEPROM 在 `0x0801F800`）。
（这是本项目踩过的坑：我一度去对齐**链接脚本**，方向错了。）

## 步骤 3：★★ 发现"比较器方案物理不可行"（整件事的核心）

**现象**：原理图上三相电压 `VA=PA5 / VB=PA4 / VC=PA2`、中性点 `V0=PA3` **全进 ADC**，
**整张图没有任何比较器器件/网络**。

**查 G071 数据手册（Additional Functions 列）**：

| 引脚 | COMP 功能 |
|---|---|
| **PA2** | ✅ `COMP2_INM` |
| **PA3** | ✅ `COMP2_INP` |
| **PA4** | ❌ **无** |
| **PA5** | ❌ **无** |

**⇒ 三相里只有一相（VC）能进比较器 ⇒ 三相比比较物理不可行。**

**⇒ 这就是硬件设计方说的"本该硬件做、要靠软件实现"的那一项。**

## 步骤 5：写软件过零模块（新文件 `adc_bemf.c/.h`，136 行）

**★ 最重要的设计决定：接口与 `comparator.c` **完全同名**。**

| AM32 原实现（comparator.c） | 本模块（adc_bemf.c） |
|---|---|
| `getCompOutputLevel()` 读 `active_COMP->CSR>>30&1` | **施密特滞回**比较 `相−V0` 与 ±阈值 |
| `changeCompInput()` 用 `LL_COMP_ConfigInputs` 切比较器输入 | 按 `step` 切换**读取哪个 ADC 通道** |
| `enableCompInterrupts()` 使能 EXTI 17/18 | 空实现（触发源待改成定时器/AWD） |
| `maskPhaseInterrupts()` 关 EXTI | 空实现 |

**⇒ 因为 `Src/main.c` 里 BEMF **只是一个布尔量**，换相状态机、消隐、数字滤波、30°延迟**
**一行都不用改。**

**核心代码（施密特滞回）**
```c
uint8_t getCompOutputLevel(void)
{
    int16_t d = adc_bemf_get_delta();          /* 当前悬空相 − V0 */
    if (d >  (int16_t)bemf_hyst)      bemf_state = 1;
    else if (d < -(int16_t)bemf_hyst) bemf_state = 0;
    /* 落在 ±hyst 之间 ⇒ 保持原状态（这就是滞回） */
    return bemf_state;
}
```

**`step → 悬空相` 映射照抄 `comparator.c`**：`1/4→C`、`2/5→A`、`3/6→B`

**加 AWD（模拟看门狗）接口**：把阈值比较**放进 ADC 硬件**，只有跨越时才中断 ⇒ 中断率降 4 倍、CPU ~2%。

## 步骤 6：把 4 路 ADC 接进去（`ADC.c` +31 −3）

**现象**：`bemf_adc_*` 恒为初值 2048 ⇒ 没有任何东西填它们。

**改动 5 处**
```
① DMA 缓冲区 3 -> 7（USE_ADC_BEMF 分支）
② ADC_DMA_Callback 里映射 bemf_adc_va/vb/vc/v0 = ADCDataDMA[3..6]
③ ADC 时钟 DIV4 -> DIV2（16 -> 32 MHz）
④ 序列 3RANKS -> 7RANKS，追加 RANK_4..7 = VA/VB/VC/V0（全用 COMMON_1=19.5 周期）
⑤ DMA 长度 3 -> 7
```

**为什么采样时间不能用 1.5 周期**：相分压源阻抗 `47K∥10K ≈ 8.3 kΩ`，
12 位精度需 `≈ R·C·ln(4096) ≈ 0.27 µs` ⇒ 32 MHz 下约 9 周期 ⇒ **19.5 周期是合理下限**。

**验证（已做，实测）**：SWD 读 RAM
```
bemf_adc_va/vb/vc/v0 = 16 / 17 / 17 / 14   ✅ 四路都在被 DMA 填充
ADC_raw_volts = 330    ADC_raw_temp = 945
ADCDataDMA[0..6] = 1, 330, 945, 16, 17, 14, 17   ← 通道顺序正确
```

## 步骤 7（**未完成**）：把触发架构改掉

**现象**：ADC 现在挂在 **1 kHz 的 PID 循环**上（`Src/main.c:1439` 置标志、`:2127` 软件触发），
而软件过零需要 ~100+ kHz ⇒ **差两个数量级**。

**计划（`findings.md` §7.4）**
```
① 删掉 Src/main.c 里 LL_ADC_REG_StartConversion(ADC1)
② 独立定时器 -> ADC TRGO（【不复用 TIM6】，它被 10 kHz 任务占着）
③ 快通道改成 [当前悬空相, VBAT] 两路（分辨率 1~2 µs）
④ 换相处调 adc_bemf_watchdog_for_phase() + AWD 中断 -> interruptRoutine()
```

**⇒ 故意先不做**：要让第一次台架验证只回答"**接线对不对**"，不动时间架构。
