# 轮询路径的「重复样本抑制」——防 ODR 没生效导致的假数据

> PX4 `b1f1abb`（分支 `bringup/imu-polled-and-params`）。**已改 + 编译通过；未上板验证。**

---

## 1. 风险从哪来

轮询是**定时 1 kHz** 的（`ScheduleOnInterval(1000, 1000)`），
但**器件真实的有效 ODR 未必等于我们写进 `ACC_CONF`/`GYR_CONF` 的值**。

本片已经有明确的旁证说明"配置可能没落稳"：

| 观测 | 含义 |
|---|---|
| `ACC_CONF` 改 bwp 半字节 ⇒ 读数在 **~1177 / ~2302** 两档间跳 | 配置确实影响行为，但档位编码不是 BMI270 那套 |
| `ACC_CONF` 的**回读恒等于写入值**，但行为对不上 | **回读可能是影子寄存器** |
| 某些 `ACC_CONF` 取值下，写 `ACC_RANGE=0x00` 与 `0x03` **读数完全一样** | 量程寄存器**看起来失效** |

**如果 ODR 实际停在缺省档**（本片 `ACC_CONF` 缺省 `0xA8` ≈100 Hz、`GYR_CONF` 缺省 `0xA9` ≈200 Hz），
那么 1 kHz 轮询会把**同一个样本重复发布 10 次**。

**对 EKF2 而言**："dt > 0 但测量值一个字节都不变" ⇒ 被当成**零角速度/恒定加速度**，
会把陀螺零偏估计和姿态积分带偏。**这比 1.73x 增益问题更危险。**

---

## 2. 做法

`DataReadPublish()` 里比较 `0x0C~0x17` 的 **12 个原始字节**，与上一次**完全相同就不发布**：

```cpp
if (12 个字节与 _last_data 全等) { perf_count(_duplicate_sample_perf); return true; }
```

- **发布频率自动跟随器件实际更新率** ⇒ 无论真实 ODR 是 1.6 kHz 还是 100 Hz，**永不重复**
- 代价：极端静止时可能少发一两个样本 —— **丢样本比重复样本安全**（这一点和轮询周期的取舍原则一致）
- 返回 `true` 而不是 `false`：这不是错误，只是"这一拍器件还没更新"，不该累加失败计数

---

## 3. 顺带得到的一个现场诊断信号

新增计数器 **`MODULE_NAME": duplicate sample"`**。

**它长期快速上涨 = ODR 没生效的直接证据。**

烧写后在 QGC 的 MAVLink Console 里：

```
bmi270 status          # 或用 perf_print / perf 相关命令看计数器
```

- 计数器 ≈ 0 → 器件确实在 ~1 kHz 更新（ODR 配置生效）
- 计数器 ≈ 900/秒（即 90% 被抑制）→ 真实 ODR ≈ 100 Hz，**配置没生效**，要按
  `cleaninit.tcl` 的思路查初始化时序

---

## 4. 关于"ODR 到底是几"：Lead 试着用已有数据判过，**判不出来**

用手上那 64 个静止样本（`datadump.log`）算：

```
SENSORTIME 相邻增量 = 1700 ~ 1789 tick
⇒ openocd 每次采样的间隔 ≈ 27 ms
相邻样本 12 字节完全相同 = 0 / 63
```

**27 ms 的采样间隔比 100 Hz ODR（10 ms）还慢**，所以检测不到重复样本。
"0/63 完全相同"只能推出 **ODR > 37 Hz**，推不出具体值。

⇒ **ODR 只能上板验**：跑 `cleaninit.tcl`，用本片 FIFO 的 `FSS` 组数直接量
（等 100 ms 读组数：1600 Hz ≈ 160 组 / 200 Hz ≈ 20 / 100 Hz ≈ 10）。

---

## 5. 更正统的长期做法（暂未实现）

手册 `DATA_STAT(0x0B)` 带 **`DRDY_ACC` / `DRDY_GYR` / `DRDY_T` 状态位**。
正规的查询方式应该是：**先读 `0x0B` 判断有没有新数据，有新数据才去读 `0x0C~0x17`** ——
这样轮询天然与器件同步，也不需要"和上一次比较"这种土办法。

**没采用的原因**：万一配置导致 DRDY 位不置起，就会完全不发布，表现成"IMU 坏了"，
风险比"重复样本抑制"高。等 ODR/配置之谜查清、`DATA_STAT` 实测可用之后，再换成这套。
