# 一切为了校准

> 2026-10-13 新建。**目的只有一个：先把"过零点到底在哪"测准，再谈补偿。**
> 上一轮（轮 20）的结论就是"过零位置本身就测不准"，本文件夹是接着它往下做的。

## 0. 一句话思路（为什么这么做）

六步换相里，**换相点**和**过零点**的位置关系是死的：

```
        换相点              理论过零点              下一次换相
          |                     ▲                      |
          |<------ 30° 电角度 --->|<---- 30° 电角度 ---->|
          |<----------------- 一步 = 60° --------------->|
          0                    0.5                    1.0     ← 步内归一化位置 u
```

一步正好 60° 电角度，而过零发生在换相之后 30° ⇒ **理论过零点永远落在这一步的正中**，
即归一化位置 `u = 0.500`。这就是"换相点 → 理论过零点"的来历，不需要任何拟合。

反过来，我们想要的是：**数据自己的过零点**离这个正中偏了多少。那个偏差就是校准量。

### 为什么只用【开环】数据（这是整个文件夹的地基）

| | 换相时刻由谁定 | 能不能当参照 |
|---|---|---|
| **开环**（固件 `stage==1`） | 固件定时器 / `input` 表 —— **跟反电势毫无关系** | ✅ 换相点是**独立真值**，拿它推出的理论过零点是硬参照 |
| **闭环**（固件 `stage==0`） | 由固件**实测到过零后**再等 30° 才换 | ❌ 拿它当参照 = 自己证明自己（循环论证） |

所以 `--pick` 只挑 CSV 里 `stage==1` 连成一片、且 `ci`（换相间隔）几乎不变的 run。
注意：**开环跑和不交棒是两件事**——有些 run 全程开环（从未 `1→0`），那是最干净的开环数据。

## 1b. "理论标准"到底是什么（含证据）

**结论：理论过零点在换相之后 30° 电角度，也就是这一步的正中（u = 0.5，τ = 30°+60k）。**
不是"在换相点上"（那是 0°），也不是"离换相点 90°"。

三条独立证据：

1. **教科书/经典无感六步**：检测到悬空相过零后，**再等 30° 电角度**才换相；而一步 = 60° ⇒
   过零必然落在这一步的正中。（TI SPRABZ3 就是这个框架。）
2. **固件自己的注释**（`AM32-rm2027/Src/main.c`）写得很明确：
   - L462 `ccm_wait[] = waitTime（换相后要等的 30 度延迟，= ci/2 - advance）`
   - L3956 `即换相发生在【过零后 15°】，而教科书位置是 30°（waitTime = ci/2）`
   - L3971 `让换相点真正回到 waitTime = ci/2 的教科书位置。`
   即：这份固件的设计目标就是"过零后 30° 换相"。
3. **实测**（`--standard`，整转拼接拟一根正弦，见下）：`20261013_115257`（V0=sw、2278 个开环步段）
   拟合出的三个过零点分别在 **τ_z = 35.4° / 36.5° / 37.6°**，三相互相差 **+121.1° / −117.8°**（理想 ±120°/±240°）。
   ⇒ 落在理论 30° 之后 5~8°，**不是 0°，也不是 90°**。多出来的那 5~8° 就是**转子负载角**
   （开环时定子磁场按定时器走，转子滞后）。

### 为什么"看起来是直线而不是正弦"

因为**一次只看得见正弦的 1/6**：一步 60°，而过零点在正中 ⇒ 我们看到的只是过零前后 ±30° 这一段。
在 ±30° 内，正弦与直线的最大差只有半量程的 **1.24%**（RMS 0.89%，
见《交接/00_交接说明.md》§3.5 与 `tools/ramp-fit.py`）——**数值上就是分不出的**。
把同一个相在**一个电周期里的两段弧拼起来**（`--standard`），完整正弦的**曲线**立刻就出来了：
数据点严丝合缝地落在一根正弦上（残差 43~47 码，占幅值 9~10%），三相数据折叠到各自过零点后
**全部塌到同一根 `sin(x)` 上**（图 `三相合一_*.png` 左栏的紫色中位线）。

> ⚠ **但有两条边界必须说清楚，否则会过度解读：**
> 1. **能看到的数据只有过零附近约一个步宽**（x∈[−29°,+25°]）。因为一个相一个电周期只悬空
>    2×60°=120°，而且这两段必然包着它自己的过零点；**波峰在 ±90°，那时这一相正在被驱动
>    （端子是 PWM 方波）⇒ 永远测不到它的反电势**。
>    ⇒ **"是正弦、还是梯形、还是直线"这件事，悬空相数据永远证不了**（这也解释了轮 20 为什么
>    在段内怎么都量不出曲率）。**能证的是**：两段弧相隔 180°（同一根正弦的半个周期）、
>    三相相差 120°、过零点落在步正中——**这些正是校准需要的全部信息**。
> 2. 想真的看见波峰，得换采集方式：让三相都被驱动时也能算出反电势（例如三路端子电压各按占空比
>    补偿后再求 `v_P − v_n`），或换成 SVPWM/正弦驱动。当前六步 + 只采悬空相做不到。

> 顺带一个有用的推论：既然换相点固定在步边界、过零点在正中，那么**在换相点那一刻，
> 悬空相的反电势正好是幅值的一半（sin30° = 0.5）**——不是峰值，也不是零。

### 1c. 把"悬空相"当【一个通道】看：它是三角/锯齿波，**不是正弦**

这是个容易绕进去的点，单独说清楚（图 `悬空相合成_<run>.png`）：

任一时刻恰好一个相悬空（每相悬空 2×60° = 120°，三相拼起来正好 360°），所以
**"悬空相 − V0" 是一条连续的时间曲线**，没有断点。但它**不是正弦**：

- 每 60° 换相时，这条曲线从"某一相的反电势"跳到"另一相的反电势"上；
- 换相点落在步边界，此刻该相反电势 = ±半幅，而三相相差 120°；
- ⇒ 每 60° **上升/下降翻一次号**；
- ⇒ **结果 = 周期 120° 电角度（＝2 步）的三角/锯齿波，幅值只有 ±半幅。**

频率换算：**3 × 电频率 = 18 × 机械频率**。例：`20261013_115257` 步长 1750 拍 ⇒ 电频率
190.5 Hz ⇒ 该通道 571 Hz。

- 理想情形（过零正好在 30°、三相幅值相同）换相处两边都是 ±半幅 ⇒ 拐角平滑，是干净的三角波；
  实测过零在 ~36°、三相幅值也不同 ⇒ 拐角变成约 ±100 码的小台阶。
- **这就是为什么所有工具都必须带"每步一个符号 `S_s`"**（`ramp-fit.py` / `theory-sine.py` / 本工具）：
  不翻符号，这根锯齿波里拟不出任何东西。
- **固件的过零检测看的就是这条锯齿波**：每 60° 出一个过零 ⇒ 一电周期 6 个过零（3 升 3 降），
  正好对应固件注释里"`thiszctime` 是两次过零之间的时间 = 一个完整换相步"。
- 反过来，**"理论标准"的正确做法是把这条合成曲线按"当下是哪个相"拆开**，每段才是正弦；
  再把同一个相在一个电周期里的两段弧拼起来，就是一根完整正弦（见 §1b 与 `理论标准_<run>.png`）。

## 2. 模型（"这个能拟合吧"的答案）

把理论过零点当**三角函数的零点**，相位/频率/零点位置全部由理论给出，只留下幅值和直流：

```
悬空相 P 在第 s 步的电压     d(u) = A_P · S_s · sin( π/3 · (u − 0.5) ) + C_P
                              └ 零点恒在 u=0.5（＝换相后 30°）┘
u = (采样点 − 换相点) / 步长        每相 2 个参数，线性最小二乘 ⇒ 良态、不会过拟合
S_s = ±1   只表示"这一相这半步是上升还是下降"（由数据斜率投票决定，不是可调参数）
```

判据是三个台阶的残差（数字见 `02_校准结果.md`）：

| 台阶 | 参数个数 | 残差 RMS | 含义 |
|---|---|---|---|
| 逐段自由直线 | 2/段（过参数化） | ~20–27 码 | **噪声地板**（只反映采样噪声） |
| 逐步自由直线 | 12（2×相×步） | ~35–56 码 | **公平基准**（把"每步各偏一点"也算进去） |
| **三角零点锚定** | **6（2×相）** | **~45–98 码** | 本模型 |

⇒ 6 个参数做到 12 参数基准的 **1.04~1.68 倍** ⇒ **能拟合**；
   多出来的那一小截正是"六步各自的竖直偏置"，也就是要校准的东西。

## 3. 三个"测不准"来源要分开（重要）

`--pick` 出来的组跑完会打印一张 `口径 × 步` 的矩阵（口径 = 用哪段数据去求过零点）：

| 口径 | 含义 | 可信吗 |
|---|---|---|
| 局部插值 | 变号处线性插值 | ✅ 最局部 |
| 全步直线 | `u∈[0.15,0.95]` 直线拟合 | ✅ 过零点在窗内 |
| 中段直线 | `u∈[0.30,0.70]` 直线拟合 | ✅ 过零点在窗内 |
| 前半窗 `0.15~0.50` | 用前半截外推 | ❌ **窗外推** |
| 后半窗 `0.70~0.95` | 用后半截外推 | ❌ **窗外推** |

**结论（本轮实测）**：过零点在窗内的三个口径彼此只差 **0.7~2.0°E**；
一旦用交接里那两个"半窗外推"口径，就蹿到 **10~18°E**。
⇒ 交接 §5① 说的"过零位置测不准（+4°~+17°）"**主要是口径假象**，不是转子偏了。

## 4. V0 是什么，为什么它比口径重要

- 反电势不能直接测。测的是**相端子电压** `v_P`，要减掉一个"中性点"参考 `V0` 才是反电势。
- 板上有两种 `V0`：
  - **硬件 V0（hw）**：三个电阻接成星形做出来的"虚拟中性点"，走 ADC 第 4 个采样槽；
  - **软件均值（sw）**：`(VA+VB+VC)/3`，纯算术。
- 六步里任一时刻是"两相驱动 + 一相悬空"，两相驱动的占空比互补 ⇒ 两者之和恒等于母线电压，所以

```
        sw = (v_悬空 + Vbus) / 3       ⇒      d = v_悬空 − sw = (2/3)·(v_悬空 − Vbus/2) ∝ 反电势本身
```

  也就是说 **sw 参考点上，`d` 只是悬空相反电势的一个缩放** ⇒ V0 的误差只会改变"增益"，
  **不会把过零点推走**。而硬件 V0 是模拟网络，它的偏差不随悬空相成比例 ⇒ 会把过零点推走。

- 实测（同一组数据只换参考点）：

| run | 六步散差 hw → sw | 口径散差(3 口径) hw → sw |
|---|---|---|
| `20261013_115519` | **11.0 → 2.8 °E** | 1.2 → 0.9 °E |
| `20261013_105232` | **21.8 → 5.6 °E** | 1.2 → 0.7 °E |

  回归 `v0_hw = k · sw`：`k ≈ 0.966~0.976`（差 2~3%）且残差 RMS 22~42 码（不是纯增益误差）。

> ⚠ **与轮 11 的张力**：轮 11 把"判据用的 V0 换软件均值"上线测过，**失败了**（超时 42240、散布 18%），
> 并由此"排除"了候选①（V0 网络 RC 不一致）。本轮证据是**离线、逐步过零位置**口径：sw 明显更一致。
> 两者不必然矛盾（轮 11 否的是**闭环表现**，不是离线一致性；轮 11 自己的表里 sw 也把 step5 从 +92 降到 +52），
> 但**"硬件 V0 ≈ (VA+VB+VC)/3"这个前提已被回归证伪**，轮 11 的"排除"应当复核。

## 6. 别踩的坑

1. **NPZ 的 `seq` 和 CSV 的 `seq` 不是同一个计数器**：前者是**波形窗口号**，后者是**换相事件号**。
   窗口包 6144 字节要发 61 ms，这期间事件全丢 ⇒ CSV 的 seq 有大量跳号。
   **唯一可靠的对齐量是 `ts`（固件 ADC 帧号）**，一律按 ts 对齐。（所有旧工具用 seq 对齐，都要留意。）
2. **死窗**：有的波形窗口整窗都是 0（DMA 缓冲没填上 / 当时没上电）。判据要用"逐采样点三相最大值的中位"，
   用"最大值"会被几根尖峰骗过去。工具会自动剔除并计数。
3. **V0 通道可能是死的**：`--v0 auto` 会先体检（全零比例 / 与 `(VA+VB+VC)/3` 的相关 / 是否有 ±32000 溢出），
   不合格就自动改用软件均值，并在报告里写明原因。目前已知 `115054`、`115257`、`224910`、`184850` 有问题。
4. 判断"这一轮是开环还是闭环"**不能**用"CSV 里出现过 `stage==0`"——每次上电起始那两行就是 0。
   要看 `stage` 有没有 `1→0` 的跳变（`index-runs.py` 本轮已修）。
5. 安全红线照旧：**不加大占空比、单次闭环 ≤7 s、每轮间隔 ≥60 s、采样不降速**（见《交接/00_交接说明.md》§7）。
   本文件夹的工具**全部离线**，不涉及这些。
