## 1. 判据：我凭什么说"你可能不会"

**不猜你的水平 —— 判据是"**离'裸机 C + CubeMX/Keil'这张经验图有多远**"：**

| 你已经会的（本项目已确认的事实） | 由此推断的盲区 |
|---|---|
| 会写 C、用 CubeMX 生成工程、Keil/IAR 那套 | **CMake / GNU Make 的构建期魔法** —— CubeMX 帮你藏了 |
| 自己写过 F103 测试固件、改过 AM32 电调（裸机 + 手写外设） | **RTOS / uORB / work queue / module 模型** —— 裸机里没有 |
| 有 Ozone / ST-Link 调试习惯 | **NuttX 那套 shell 命令 / ROMFS / 启动脚本** —— 裸机里没有 |
| 刚说看不懂 `$(eval …)` / `$(call …)` | **Make 的函数式构造** —— 已补 §6，但只补了一部分 |
| 用过 CubeMX 生成的 `startup_stm32xxx.s` | **启动汇编的门道**（向量表/VTOR/段搬运）—— 以前从不用看 |

**⇒ 规则：**偏离这四条经验越远 = 越该讲；等于"你本来就懂"的（纯 C 语法、寄存器读写）**不再解释**。**
