## 零、一句话结论（★ 两条，缺一不可）

```text
① 这颗芯片是【BMI270 寄存器图兼容】的 6 轴 IMU（几乎可以肯定是山寨/打磨件，
   或 ID 未编程的 BMI270 变种）。证据：寄存器图与 Bosch 官方图逐条吻合 +
   功能铁证（按 BMI270 写法开传感器，加速度/陀螺数据立刻活起来）。
   唯一异常：CHIP_ID(0x00) 读出 0x00，而正品 BMI270 必须是 0x24。

② ★★ 【放宽 PX4 bmi270 驱动的 CHIP_ID 检查】是【错误方案】，不许采用。
   放宽后驱动会继续执行它的"微码上传"步骤，把 PX4 自带那份 329 字节配置块
   写进芯片 —— 本次实测：一写就把芯片锁死（不再回话），只能靠断电恢复。
   ⇒ 正确方案是【跳过微码上传】的驱动（已证明：不上传微码也能出数据）。
```

## 二、完整 dump（原始数据）

### 2.1 读协议先说清楚（不然后面数字会误读）

```text
SPI MODE3，8bit；主机 = MCU 的 SPI1（SCK=PB3/MISO=PA6/MOSI=PD7），片选 = PB4（软件拉 GPIOB BSRR）
读：先发  0x80|addr  （地址帧；从机不驱动 ⇒ 收回 0xff），再发 0x00 ⇒ 收回的就是该寄存器值
写：先发  addr(bit7=0)，再发 data
★ 对齐验证（决定性）：写 0x75=0x11、0x76=0x22、0x77=0x33，
  再突发读 [0xF5,00,00,00,00] ⇒ 收到 [ff,11,22,33,00]
  ⇒ ① 地址后【紧跟】就是数据（**没有 dummy 字节**）② 地址线性（无偏移）
     ③ 多字节读【自动增量】④ 读写命中同一地址空间
★ 降速对照：24MHz 与 0.75MHz 结果一致 ⇒ 与速率/走线无关
★ 排除 MISO 回环：不发读命令时 MISO 恒高（07 号日志实验 C 亦同）
```

### 2.3 读/写性图（写 0x5A → 回读，写 0xA5 → 回读，再还原原值）

```text
【完全可写】32 个：06 08 1d 1e 30 32 33 34 36 37 3f 40 42 44 45 4a
                    51 55 56 57 68 6c 71 72 73 74 75 76 77 78 79 7a
【位掩码可写（写进去只保留部分位）】20 个：04 05 07 19 1a 1b 1c 38 3a 3e
                    41 43 53 54 69 6b 6d 7c 7d 7f
【写不进（只读）】其余 76 个地址
【还原校验】除 0x19/0x1A（活计时器，本来就在动）外，全部还原成功
```

对照 BMI270 官方图，可写的是：`0x40 ACC_CONF`、`0x41 ACC_RANGE`、`0x42 GYR_CONF`、`0x43 GYR_RANGE`、
`0x44 AUX_CONF`、`0x45 FIFO_DOWNS`、`0x68 AUX_IF_TRIM`、`0x6C DRV_STR`、`0x7C PWR_CONF`、`0x7D PWR_CTRL`
—— **全是 BMI270 里应该可写的配置/微调寄存器**；而 `0x7E CMD` 写不进（BMI270 的 CMD 本来就是"只写"）。

### 2.4 稳定性

```text
· 同一轮内连读 3 遍全 128 地址：除 0x18-0x1A 外【完全一致】
· 0x18-0x1A = 唯一的"活"寄存器组（24 位计时器，单调递增）
· 0x22/0x23 跨轮次会变（温度，见第三节）
· 计数器速率实测：sleep 1000ms → +24829；sleep 2000ms → +49338
  ⇒ 约 24.7 kHz，线性（49338/24829 = 1.987）
```

### 2.5 数据寄存器是"活"的（见第三节功能铁证）

```text
开传感器后 0x0C~0x17（BMI270 的 DATA_0..DATA_11）4 次连读：
  ffa4fed10898ffc50028ff4a
  ff65ff7c0892fff6ff49ff89
  ffb3ff080851002a0021ff49
  ffb5ff800890007cff5d011b        ← 每次都不一样 = 真在采数
把 PWR_CTRL 写回 0（关传感器）后 4 次连读完全冻结：
  ffd8ff7508c60077ffdfff91  ×4   ← ★ 冻结证明上面那些变化不是噪声
```

## 三、★ 型号判定：BMI270 寄存器图兼容件

### 3.1 逐条与 Bosch 官方图对应（来源见 `bmi270-official-regmap.md`）

| 地址 | Bosch 官方名称 | 本片实测 | 判定 |
|---|---|---|---|
| 0x00 | CHIP_ID（固定 0x24，只读） | 0x00（只读） | ❌ **唯一异常** |
| 0x03 | STATUS | 0x00 | ⚪ 一致（无异常状态） |
| 0x0C..0x17 | ACC/GYR 数据 12 字节 | 开传感器后变活 | ✅✅ 数据位置对 |
| **0x18** | **SENSORTIME（24bit）** | **活计时器 0x18-0x1A** | ✅✅✅ |
| 0x1B | EVENT | 0x00 | ✅ |
| 0x1D | INT_STATUS_1 | 0x07 | ⚪ 地址对 |
| 0x21 | INTERNAL_STATUS | **0x00 = "not initialized"** | ✅ 语义对得上（微码没上传） |
| 0x22/0x23 | TEMPERATURE_0/1 | 变动 | ✅✅ |
| 0x24/0x25 | FIFO_LENGTH_0/1 | 0x00 | ✅（没开 FIFO） |
| 0x40 | ACC_CONF（复位 0xA8） | **0xA8** | ✅✅✅ |
| 0x41 | ACC_RANGE | 0x02（2bit 可写） | ✅ |
| 0x42 | GYR_CONF（复位 0xA9） | **0xA9** | ✅✅✅ |
| 0x43 | GYR_RANGE | 0x00（4bit 可写） | ✅ |
| 0x44 | AUX_CONF（复位 0x46） | **0x46** | ✅✅✅ |
| 0x45 | FIFO_DOWNS（复位 0x88） | **0x88** | ✅✅✅ |
| 0x46/0x47 | FIFO_WTM_0/1 | 0x00 | ✅ |
| 0x53/0x54 | INT1_IO_CTRL / INT2_IO_CTRL | 位掩码可写 | ✅ |
| 0x68 | AUX_IF_TRIM | 可写 | ✅ |
| 0x6C | DRV_STR | 可写 | ✅ |
| 0x7C/0x7D | PWR_CONF / PWR_CTRL | 可写（0x7D 写入 0x0E 能回读 0x0E） | ✅✅ |
| 0x7E | CMD（只写） | 写不进（符合"只写"） | ✅ |

**未对上的一小撮**：0x01=0x6A、0x02=0x11、0x05=0x50、0x08=0x80、0x1E=0xFF、0x1F=0x40、0x3A=0x08
—— 这些地址在 Bosch 官方公开图里**没有定义**，推测是这颗（山寨/变种）多出来的私有用寄存器。
**关键点**：它们不影响数据通路。

### 3.2 ★★ 功能铁证（这一步才叫"确定"）

```text
按 BMI270 数据手册的写法操作本片：
  PWR_CONF(0x7C)=0x00 → ACC_CONF(0x40)=0xA8 → ACC_RANGE(0x41)=0x02
  → GYR_CONF(0x42)=0xA9 → GYR_RANGE(0x43)=0x00 → PWR_CTRL(0x7D)=0x0E
结果：
  · PWR_CTRL 写入 0x0E 能【原样回读 0x0E】⇒ 这是真的 BMI270 风格电源控制寄存器
  · 0x0C~0x17（BMI270 的 12 字节数据区）【立刻出现不断变化的数值】⇒ 加速度/陀螺在采数
  · 把 PWR_CTRL 写回 0x00 ⇒ 数据【立刻冻结】⇒ 因果明确，不是噪声/幻读
⇒ 寄存器图 + 功能行为 双向吻合 ⇒ 判定成立（不是"只看一个 ID 值"）
```

### 3.3 为什么说它"不是正品 BMI270"（诚实标注）

```text
· CHIP_ID(0x00) = 0x00 ≠ 正品必须的 0x24 ⇒ PX4 驱动直接拒
· 多出 0x01/0x02 等一批 Bosch 公开图里没有的寄存器
· 更硬的一条：PX4 自带的 329 字节配置块（在真 BMI270 上可用）写进去后
  把本片【锁死】了（第五节）——真品不至于如此
⇒ 结论：BMI270 寄存器图兼容件（山寨/打磨，或 ID 未编程的变种）。
   可信度：寄存器图+功能证据 = 高；"具体是哪家山寨" = 无法判定，也不影响下一步。
```

## 五、★ 事故：微码上传把芯片锁死（全过程 + 恢复 + 为什么不建议再试）

### 5.1 我做了什么

```text
目的：想一锤定音回答"它到底能不能吃 BMI270 微码"（能吃 ⇒ 只需改 ID；不能 ⇒ 得另写驱动）。
做法：从 PX4 驱动里抽出那份 329 字节配置块（`maximum_fifo_config_file[]`，:78 起；
      首字节 0x5E 就是 INIT_DATA 地址），按数据手册序列手工跑：
        1) CMD(0x7E)=0xB6（软复位）
        2) PWR_CONF(0x7C)=0x00
        3) INIT_CTRL(0x59)=0x00
        4) 一次 CS 低窗口内突发写 329 字节到 INIT_DATA(0x5E)
        5) INIT_CTRL(0x59)=0x01 → sleep 200ms → 读 INTERNAL_STATUS(0x21)
```

### 5.2 结果：芯片从此不回话

```text
· 突发写完成后，读任何寄存器（0x00/0x01/0x02/0x21/0x40…）**全是 0xFF**
  ⇒ MISO 没人驱动（芯片不再响应）
· 软件恢复全部试过、全部无效：
    CMD(0x7E)=0xB6 软复位 ×2 ／ PWR_CONF=0x00,0x03 ／ PWR_CTRL=0x00
    ／ IF_CONF(0x6B)=0x00 ／ INIT_CTRL(0x59)=0x00 ／ 把 0x00–0x7F 全部写 0
    ／ CS 反复拉高拉低 20 次 ／ 把 SPI1 主机 CFG1/CFG2/CR1 重新初始化
· ★ 已排除"是单片机这一侧坏了"：
    CR1=0x1201 CFG1=0x10070007 CFG2=0x87400000 SR=0x1802 GPIOB_ODR=0x00000c10（CS=高）
    GPIOA_MODER=0xabfeefff（PA6=MISO 仍是 AF）；事务能正常完成（SR 正常、RXDR 有字节）
    ⇒ 主机健康，是【芯片自己锁住了】
```

### 5.3 恢复办法（唯一）：断电重启


| # | 失败 | 碰到硬件？ | 真实影响 |
