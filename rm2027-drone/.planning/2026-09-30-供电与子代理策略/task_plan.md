## 二、子代理策略（改法）

| 场景 | 用什么 | 理由 |
|---|---|---|
| 同一项目**连续推进**（板子 bring-up 这类） | ✅ **复用 `qgc-bringup`** | 它已有项目背景，唤醒即可继续；且可被 `wait_agent` 观察 |
| 短、独立、一次性（查资料、跑一个实验） | `subagent`（一次性） | 跑完即走，不需留岗 |
| 完全独立视角复核 | 才新开持久队友 | 少数情况 |

**规则（写给自己）**：
```text
1. 默认先看有没有可复用的持久队友 → 有就 send_message 唤醒，不新开
2. 只有"一次性、短、独立"才用一次性子代理
3. 一个目标没做完就断掉 = 浪费（用户已经为此不满两次）
```

## 三、★ 电池供电这件事（用户要求第一个想清楚）

### 3.1 已知事实

```text
· 板子供电拓扑：电池 → SY8303（降压）→ 5V → TLV75533（LDO）→ 3.3V
· 原理图里有【两条独立的 3.3V 网络】：3.3V_H7 和 3.3V_F1
  ⇒ 主控 H743 和 协处理 F103 的 3.3V 是【分开的】！
· 5V 的去处：SY8303 输出、连接器 U16~U21、CAN 收发器 SIT3051TK、Q17/R19 开关电路
· 用户当前的接法：★ 电池 和 ST-Link 的 3.3V 【同时接着】
```

### 3.2 ★ 关键问题（必须先查清，再决定接法）

```text
Q1 3.3V_H7 和 3.3V_F1 分别由谁产生？
   ✅ **已查明（2026-09-30，原理图渲染直读）**：
      TLV75533 在原理图里出现 **2 次** ⇒ **两颗独立的 LDO**
        5V ──┬── TLV75533 #1 ──→ 3.3V_H7（H743 及外设：U2~U7/U10 一带）
             └── TLV75533 #2 ──→ 3.3V_F1（F103 及协处理：U9 一带）
      两颗 LDO 的输入【都是 5V】
   ⇒ ★★ **ST-Link 3.3V 单独供电不可行**：H7 有电、F103 没电，
      且 H7 的串口会往未上电的 F103 引脚灌电流（有损坏风险）

Q2 ST-Link 的 3.3V 应该接哪条？还是都不接（只当参考电平）？

Q3 电池 + ST-Link 3.3V 同时接，实际是【谁在供电】？
   （板载 LDO 输出 3.3V vs ST-Link 输出 3.3V，谁电压高谁供 → 会互相灌）
```

### 3.3 候选方案

| 方案 | 接法 | 优点 | 缺点/风险 |
|---|---|---|---|
| **A（推荐）** | 电池 + ST-Link **只接 SWDIO/SWCLK/GND**（3.3V 线拔掉） | 走板载正常链路；电流足；无互灌；5V 外设也可用 | 需要确认 SWD 在无 ST-Link 3.3V 时仍能识别（多数情况可以，ST-Link 会读目标电压） |
| **B** | 只用 ST-Link 3.3V，不接电池 | 最简单，一条线 | ❌ **已判定不可行**：两颗独立 LDO（3.3V_H7 / 3.3V_F1）输入都是 5V ⇒ 只接一条的话另一颗主控没电；且会向未上电的 F103 灌电流 |
| **C** | 电池 + ST-Link 3.3V 都接（**现状**） | 无 | ✗ 双电源互灌，疑似就是"温热"的来源，长期伤 LDO |

### 3.4 待办（按顺序）

```text
P1  读原理图确认 Q1/Q2（3.3V_H7 与 3.3V_F1 的产生方式与连接）
    → 证据：references/硬件手册/FMU_飞控板_原理图_*.pdf 渲染成图看
P2  量一次（板子断电）：两条 3.3V 之间是【导通】还是【隔离】？
    （万用表电阻档，3.3V_H7 点 对 3.3V_F1 点；导通=同一颗 LDO）
P3  定方案（预期 A），写进交接文档
P4  用户按方案接线 → 上电 → 用 ST-Link 只读验证：
    · 两条 3.3V 的电压
    · 之前子代理写过的 SPI1 CFG1/CFG2 / CS 是否已还原
P5  板子确认正常 → 才恢复传感器/IMU 的活
```
