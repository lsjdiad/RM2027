## 二、★ 最大风险点：25MHz 晶振

| | 模板 matek | **本板** |
|---|---|---|
| HSE | 8 MHz | **25 MHz** |

**问题**：PX4 的 61 块 H7 板里，晶振只有 8 / 16 / 24 MHz 三种，**没有 25MHz 先例**，
所以没有现成的 PLL 配置可抄。

**解法**：手算一组，目标是**复现模板的全部输出频率**（这样下游 SPI/ADC/FDCAN 行为不变）：

```text
                    模板(8MHz)              本板(25MHz)
PLL1  M/N/P        1 / 120 / 2         →   5 / 192 / 2
      VCO           960 MHz             →   5MHz×192 = 960 MHz      ✅ 一致
      P/Q/R         480/240/120         →   480 / 240 / 120         ✅ 一致
PLL2  M/N/P/Q/R    2 / 48 / 2,2,2      →   5 / 96 / 5,5,5
      VCO           192 MHz             →   5MHz×96 = 480 MHz
      输出           96/96/96            →   480/5 = 96/96/96        ✅ 一致
PLL3  M/N/P/Q/R    2 / 48 / 2,4,2      →   5 / 96 / 5,10,5
      VCO           192 MHz             →   480 MHz
      输出           96/48/96            →   480/5, 480/10, 480/5   ✅ 一致
```

**约束核对**：
- PLL 参考输入 = 25/5 = **5 MHz** → 仍落在 `RGE_4_8_MHZ` 档 → **RGE 设置无需改**
- VCO 960/480/480 MHz ∈ [192, 960] ✅
- M ≤ 63、N ∈ [4,512]、P/Q/R ∈ [2,128] ✅

**依据**：`nuttx-config/include/board.h` 里原有的约束注释 + STM32H743 datasheet 的 PLL 章节。

> ⚠️ **这是上板第一件要验证的事**：如果板子起不来、串口没输出，
> 第一个怀疑对象就是这组 PLL 参数。

## 三、编译过程中真实遇到的 6 个错误（全部已修）

> 这一节是本文档最有价值的部分：**同样的坑不用再踩一遍。**

### E-01 · CMake 报「NuttX custom board directory 不在 board 目录里」

```text
CMake Error: NuttX custom board directory
(../../../../boards/matek/h743-slim/nuttx-config) isn't in board directory
```

- **原因**：抄模板时，`nuttx-config/nsh/defconfig` 与 `nuttx-config/bootloader/defconfig`
  里的 `CONFIG_ARCH_BOARD_CUSTOM_DIR` 还指向 matek
- **修**：两处路径改成 `../../../../boards/rm2027/fmu-h743/nuttx-config`
- **教训**：**抄板子必须全局搜模板板名**（`grep -rn matek`），CMake 的报错只提一处，
  另一处要自己找出来

### E-02 · NuttX `olddefconfig` 失败：SDMMC 与 MMCSD 冲突

```text
warning: SDIO_DMA has direct dependencies MMCSD with value n,
         but is currently being y-selected by STM32H7_SDMMC_IDMA
```

- **原因**：我按「本板无 SD 卡」删了 `CONFIG_MMCSD*` 和 `CONFIG_SDMMC1_*`，
  但漏了 `CONFIG_STM32H7_SDMMC1=y`（前缀不同，没被规则命中）
- **修**：删掉 `CONFIG_STM32H7_SDMMC1=y`
- **教训**：**删配置要连"前缀不同的同族项"一起扫**（MMCSD / SDMMC / SDIO 三种前缀）

### E-03 · `GPIO_UART5_TX` / `UART7_CTS` 未定义

```text
chip/stm32_serial.c:1247: error: 'GPIO_UART5_TX' undeclared
chip/stm32_serial.c:1383: error: 'GPIO_UART7_CTS' undeclared
```

- **原因**：
  - 我在 defconfig 里开了 UART5（DBUS 要用），但没在 board.h 定义它的引脚
  - 我把 UART7 的 RTS/CTS 定义删了（本板没接），但 defconfig 里还开着流控
- **修**：board.h 补 `GPIO_UART5_RX/TX`；defconfig 去掉 `CONFIG_UART7_IFLOWCONTROL/OFLOWCONTROL`
- **教训**：**「开外设」和「定义引脚」必须成对**；反向也成立（删引脚定义就要关对应的功能开关）

### E-04 · `ADC_BATTERY_VOLTAGE_CHANNEL` 未声明

```text
board_common.h:164: error: 'ADC_BATTERY_VOLTAGE_CHANNEL' was not declared
```

- **原因**：本板**没有电池电压采样**，我如实删了该宏；但 PX4 的
  `board_common.h` 在**编译期**就要用它拼 `BOARD_BATT_V_LIST`，删不掉
- **修**：给占位值（指向 PC0/PC1）+ 同时置 `BOARD_ADC_BRICK_VALID 0`
  ——即"能编译，但 PX4 把这块砖标记为无效，不会拿错误电压去做 failsafe"
- **教训**：PX4 有些宏是**编译期契约**，不能因为硬件没有就删；
  正确做法是「给占位 + 显式标记无效」并写清 TODO

### E-05 · `too many initializers for 'const timer_io_channels_t [8]'`

- **原因**：`MAX_TIMER_IO_CHANNELS = DIRECT_PWM_OUTPUT_CHANNELS`（我在 board_config.h 设成 4），
  但模板的 `timer_config.cpp` 里列了 12 条通道
- **修**：重写 `timer_config.cpp`，只列 4 条（TIM1_CH1..4 = PA8/PE11/PE13/PE14）；
  DMA 映射**照抄 `boards/3dr/ctrl-n1`** —— 发现该板 TIM1 的通道引脚与本板**完全一致**
- **教训**：数组长度由宏推导时，**改了宏就要同步改所有相关数组**

### E-06 · `undefined reference to stm32_spi2select / spi3select`

```text
libarch.a(stm32_spi.o): undefined reference to `stm32_spi2select'
```

- **原因**（两层）：
  1. PX4 的 SPI 校验规则是「**NuttX 里开了的总线，必须在 PX4 的 SPI 总线表里有条目**」。
     我们在 defconfig 里开着 SPI2/SPI3，但 `spi.cpp` 只声明了 SPI1 → 触发 constexpr 断言
  2. 本板的 SPI2/SPI3 **没有引出片选脚**，PX4 的 SPI 设备必须带 CS，所以"声明成外部总线"也不成立
- **修**：**从 defconfig 里删掉 SPI2/SPI3**（承认它们不可用），只留 SPI1
- **额外踩坑**：改完仍有同样报错 —— 是**上一轮编译的残留目标文件**；
  而且我当时有**多个 `make` 在并发跑**互相踩。
  最终靠「杀掉全部构建进程 + 删整个 build 目录 + 单实例重编」解决
- **教训**：
  ```text
  ① 改 Kconfig 后如果报错没变，先怀疑残留目标文件
  ② 绝不要并发跑多个 make（我用 nohup 连开了几次，自己踩自己）
  ③ 最干净的办法：rm -rf build/<board> 后单实例重编
  ```

### E-07 · `firmware.prototype` 缺失（我自己删的）

- **原因**：清理模板残留文件（`extras/matek_*.bin`、`firmware.prototype`）时删多了 ——
  `firmware.prototype` 是 PX4 构建**需要**的（提供固件 `board_id`）
- **修**：新建，`board_id = 2027`
- **选号依据**：统计全部 113 块板的 ID 后发现 **2000-2999 号段完全空闲**
  （PX4 的自定义板号段），取赛季号 2027 便于记忆
- **教训**：**清理模板文件前先确认它是不是构建需要的**；`firmware.prototype` 名字像文档、其实是配置
