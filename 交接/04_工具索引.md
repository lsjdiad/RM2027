## 2026-10-14 新增 / 修改的工具

> ⚠ **`tools/` 是按分支各存一份的**（.gitignore 里靠 `git add -f` 提交）⇒ 切分支会把工具版本一起切回去。
> 判分器一律提交在基础设施基线 `test-01-计数轮-缩短闭环` 上。

| 工具 | 干什么 | 关键点 |
|---|---|---|
| **`count-run.py`（新）** | **计数轮判分器**：关窗口流 → 跑 → 出精确报表。判分口径三件套 + 三道跑前闸 | ① 关 `win_enable`（窗口流要 288KB/s、串口只 125KB/s ⇒ 数学上不可能共存；开着它事件流只采到 ~3 成，**而且它自己会扰动过零**：实测开着 57 次/6 秒 vs 关掉 0）② 判分窗口 = **锚定闭环**（`stage==0 且 duty==300` 的 ts 最长连续块）—— 不能用 `stage` 定义 ③ 时长用 **Δts 累加**（不用"末 ts−首 ts"，会被 ts 跳跃切碎）④ 跑前三闸：**串口存活**（3s <5000B 放弃）、**母线 ≥10V**、**窗口 ≥0.8s 且 ≥600 条** |
| **`step-window.py`（新）** | 【换步出错窗口】全速过零采样图：4 个最差窗口 × 3 栏（悬空相−V0 全速 + 换相竖线 + 段内变号点 / 未钳制步内时间锯齿 / 逐步明细表） | ★ **求过零必须跳过换相后 ~2 个采样的建立瞬态**（实测悬空相从"被驱动"释放：VA 999→77→350，(悬空相−V0) 走 +527→−398→−110），否则会把假变号当成过零（我第一次就踩了，报出"过零贴在换相点上 0.02"）。同一现象正是固件 `zc_lo=150 拍` 要挡的"换相振铃" |
| **`esc-dbg.sh poke <符号> <值>`（新命令）** | SWD 写 1 字节，给运行时开关用 | 例：`poke win_enable 0/1`（关/开窗口流）。`win_enable` 的代码注释本来就写着"SWD 写 0/1 即可，不用重编译" |
| `cap-evt.py`（修两处） | 采集 + 出图 + 埋点 dump | ① 埋点 dump 的 `mdw` 数据行在 **stderr** 上，只扫 stdout 会读到空列表 ⇒ `list index out of range` ② 取字宽：`OL_CM_D` 是 `int16[32]` ⇒ 只占 16 个**字**、每个字里 2 个 int16，要拆半字；`OL_CM_S` 是 `uint8[32]` 同理。修前会印出 16 位巨数（如 1258289370058217） |
| `count-run.py` 的 `valid()` 扩展 | 剔"窗口包魔数被当成事件帧"的假帧 | 原来只查 step/duty/cur/delta ⇒ 窗口包魔数 `A5 5A`(23205) 会以 `input` 的形式混进来（踩过 3 次） |

**判"补偿好不好"的口径（本轮定下来的）**：① **换相节拍有没有被改**（决定相位对不对）② **六步极差** ③ 多轮漏过零的**最小值**。
**不能只看单轮漏过零** —— 同一配置实测能差 20 倍（补偿 ON：1 ↔ 21）。

| **`stab-view.py`（新，2026-10-14 晚，已在 test-01 与 test-06 两个分支上）** | **闭环稳定性视图**：从事件 CSV 直接画（不驱动电机），每 CSV 一行 4 栏 —— ① 换相节拍按 step 上色（画基线 2000 拍参考线）② 每秒换相数 ③ **漏过零每秒增量 + 累计**（暴露"爆发式"）④ 电流。可多份并排 | ★ 一眼看三件事：**六步是否被压到 2000 拍以下且彼此分开**（补偿在改相位）、**漏过零是不是爆发式**（所以平均值无意义）、**电流高低**（补偿 ON 换了 1.8 倍相、电流反而更低 ⇒ 多出的换相没做功）。用法：`python3 tools/stab-view.py a.csv b.csv` |

| **`speed-view.py`（新）** | 闭环**整体转速图**：转速 = 3.3333e6 / 步长拍（本板 6 极对、36 次换相/机械转；步长 2000 拍 → 1667 rpm，与 cap-evt 打印一致）。两栏：①转速（开环灰底/锚定闭环绿底）+ 自动标【最快加速点】与 |Δrpm| 前 3【突变】并打印其后去 NPZ 取素材的定位 ②步长(ms) + 离群步(>1.5×中位，= 漏过零兜底)打红× | 用法 `python3 tools/speed-view.py <csv>` |
| **`phase-view.py`（新）** | ★**六步换向的每相时间 + 逐采样详图**：自动挑【加速/恒速/突变】三窗，每窗 4 栏 —— ①四路原始波形全速 512 点 ②悬空相−V0 + 换相竖线 + 真过零 ③**每相状态 Gantt**（红=高边驱动/蓝=低边驱动/黄=悬空，逐段标 step，并与悬空相映射交叉验证）④每步时长(拍)+步内时间锯齿 | ⚠ 必须用波形轮的 NPZ；**闭环窗判据 = 每窗步长中位 ≤ 1.35×15分位**（斜坡窗本身最"均匀"，不加闸会被误选成"恒速"，踩过）；求过零/判相状态都要跳过换相后 ~2 采样的建立瞬态。用法 `python3 tools/phase-view.py <csv>` |

| **`ao-dump.py` / `ao-view.py`（新，2026-10-14 晚）** | 自适应电压偏移的**读数与结果图**。`ao-dump.py` 走 SWD 读 4 个 RAM 计数器（`ao_off` 当前偏移 / `ao_chg` 改动次数 / `ao_nozc` 无过零次数 / `ao_err` 最近误差）—— **不占串口带宽**（串口今晚卡死过 3 次）；`ao-view.py` 出四栏图 | ★ 结果图第①栏是核心：把 `ao_off` 画在**可见性上限 ±A_s 黄带**上 —— 红柱戳出黄带 ⇔ 交点被推出弧线 ⇔ 该步整段无过零（第④栏）。这条因果链一眼可见（第1轮：六步全超带、无过零 8129 次） |
