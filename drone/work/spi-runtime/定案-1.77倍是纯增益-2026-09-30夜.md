## 1. 判决实验：用 ST-Link **直读原始码**扫四档量程

**为什么这次能定**：以前所有测量都是经过驱动的 `_scale` 之后的数据，而 `_scale` 正是
被怀疑的对象；这次用 `rawbyte-dump.tcl` 手工拉 CS **直读 0x0C~0x11 的原始十六进制字节**，
完全绕开驱动的换算。

板子**静止平放**（重力在 Z 轴）。**取数方法经过一次修正**：

- ❌ 第一版 `fs-scan.tcl`：只读 Z 轴、每档 3 个样本取中位 ⇒ 噪声 ~12%，
  把 ±8g 那档测成 **2056**（比值 0.502）的离群点，**最小二乘被它拉低到 0.569，看上去"像 0.5"**。
- ✅ 第二版 `gain-scan.tcl`：**读三轴**、每档 **64 样本**、**先对各轴求平均再取模**
  （`|平均| = √(mx²+my²+mz²)`）⇒ 消除板子倾斜影响、噪声按 1/√N 收敛，并打印样本 sd 让噪声现形。

**干净结果**（sd 一并列出）：

| `ACC_RANGE` 设定 | 回读 | 均值 (x, y, z) | **\|a\| 码（=该档 LSB/g）** | sd | 手册理论（§5.38+规格表） | **比值** |
|---|---|---|---|---|---|---|
| `0x00` | 0x00 | (18, 1321, 9240) | **9334.2** | 166 | 16384（±2g） | 0.5697 |
| **`0x01`（在用）** | 0x01 | (56, 574, 4642) | **4678.0** | 13.5 | 8192（±4g） | **0.5710** |
| `0x02` | 0x02 | (11, 351, 2348) | **2374.4** | 8.0 | 4096（±8g） | 0.5797 |
| `0x03` | 0x03 | (−10, 178, 1200) | **1213.0** | 18 | 2048（±16g） | 0.5923 |

**⇒ ±8g 那档从 0.502 回到 0.5797 —— 那个离群点是测量噪声，不是芯片行为。**

（流程 A「ACC 保持开启时改 FS」与流程 B「关 ACC → 改 FS → 开 ACC」两套都跑过，
两版脚本都做过 ⇒ 与 §5.39 那种"关-配-开"时序无关。**ACC_RANGE 是生效的**，与 `GYR_CONF` 那次不同。）

## 2. 结论：纯**增益**，零偏被排除

干净数据四点最小二乘：**实测码 = 0.5665 × 手册码 + 52.7**（残差 **< 0.35%**）

| | 斜率 | 截距 |
|---|---|---|
| 实测拟合 | **0.5665** | **+52.7 码**（≈ 0.006 g @±4g，落在手册 ATyOff ±80mg 内） |

**看"实测 − 手册"**：

| | FS=00 | FS=01 | FS=02 | FS=03 |
|---|---|---|---|---|
| 实测 − 手册 | −7050 | −3514 | −1722 | −835 |

**⇒ 差值随量程同步变化，不是一个常数 ⇒ 纯零偏模型被排除。**
**⇒ 斜率恒定 0.5665 ⇒ 这是一个乘性增益偏差。**

### 2.1 ★ 顺手否掉一个很自然的怀疑：「是不是干净的二倍？」

**如果"芯片实际量程比寄存器标称粗一档"（即 ±4g 档实际是 ±8g），那么
`|a| ÷ (手册÷2)` 应当严格等于 1.000。**

实测：**1.139 / 1.142 / 1.159 / 1.185** ⇒ **高出 14~19%，不是 1 ⇒ 干净的二倍被否掉。**

**⇒ 不是 2 倍，是 1.751 倍。**

### 2.2 ★ 修正系数怎么取 —— **按器件真实 counts/g 反推，不是去凑手册**

```
真实标度   = 重力 / (1g 对应的码) = 9.80665 m/s² ÷ 4678 码 = 0.0020964 m/s²/码
驱动假定   = 4g × 9.80665 / 32768                          = 0.0011971 m/s²/码
⇒ 修正 = 0.0020964 / 0.0011971 = 8192 / 4678 = 1.7512
```

（若改用四点拟合的斜率 0.5665 ⇒ 1.7653，两者差 0.8% —— 差别就是那 52.7 码零偏
被算进/算出的问题；零偏最终应由六面标定单独估。**这里取工作点 ±4g 上使 `|a|` 精确的 1.7512**，更保守。）

## 7. ⚠️ 连带的真 bug：`set_range()` 没跟着改（已修）

`PX4Accelerometer::UpdateClipLimit()`：

```cpp
_clip_limit = fabsf(_range / _scale * 0.999f);     // 单位 = 原始码
```

**上一版只把 `scale` 乘了 1.7512，`set_range()` 还按 ±4g 设** ⇒ 裁剪阈值停在
`4g × 0.999 / scale = 18692 码`，而器件能出到 32767 码
⇒ **4g ~ 7g 之间会被误报 `clip_counter`。**

**修法**：`set_range()` 也乘 `ACCEL_GAIN_CORRECTION`（真实满量程本来就是 7.00 g）。
烧写后启动日志：

```
INFO [hxy42688p] accel: ACC_RANGE(0x41) read 0x01 (expected 0x01),
                 nominal=+-4g -> real range=+-7.00g, scale=0.002096362 m/s^2/LSB (手册值 x 1.7512)
```

**⇒ `real range = ±7.00 g` 正好等于表中反推的 7.005 g —— 两条独立路径对上了。**

## 10. ★ 更正（2026-10-01）：上次那次"采集脏"的警报要**降级**

§5 之后我写过一条"ST-Link 采集是脏的 ⇒ 1.7512 置信度只有 ~10%"。**现在这条要更正。**

**三条踩坑 + 最终结论：**

| # | 坑 | 现象 | 教训 |
|---|---|---|---|
| ① | **动了 `SPI1_CFG1` 的 DMA 使能位却没恢复** | 之后**读什么都恒为 `0x1F`**，连 `WHO_AM_I` 都是 `0x1F` —— 看着像"芯片挂了" | **恢复：`reset run`**（复位 MCU 让 PX4 重init SPI1），之后 `WHO_AM_I=0x6A` 立刻回来。**绝不要碰 CFG1 的 bit0/1** |
| ② | **把"双读一致"用在数据寄存器上** | `retries` 爆表、返回值全垃圾 | 0x0C~0x17 是**活动数据**，ODR=1600Hz 下两次读天生不同。双读一致只适用于**配置寄存器** |
| ③ | **把一轴拆成两次单字节读** | 容易被寄存器更新撕开 | 改**一次 CS 周期原子读 16 位**（cmd + 2 哑字节，收 3 字节取后 2 个） |

**修好后的干净测量（`measure-point.tcl`：原子读 + 64 样本 + "陀螺≈0"静止门）：**

```
前置: WHO_AM_I=106 (0x6A)   ACC_RANGE=1   GYR_RANGE=0   PWR_CTRL=14
POINT ok=64  moving=0
POINT acc_raw X=40.6  Y=608.4  Z=4654.8   |a|=4694.6   极差 X=53 Y=207 Z=50
POINT gyr_dps X=-0.024 Y=0.605 Z=-0.302   abs=0.676
```

| 测量 | \|a\| 码/g | 与干净值差 |
|---|---|---|
| `gain-scan`（单字节读 + 64 样本平均） | 4678.0 | **0.35%** |
| **`measure-point`（原子读 + 64 样本 + 静止门）** | **4694.6** | — |
| `decode-proof`（单字节读 + 6 样本 + 无静止门） | 5200 | **10.8% ← 这个才是脏的** |

**⇒ 结论更正：**
- **上次那个 11% 的落差不是"器件/标度不稳"，是 `decode-proof` 那条读法脏。**
- **干净值 ≈ 4690 码/g ⇒ 修正系数 = 8192/4694.6 = `1.7450`**，与已提交的 `1.7512` **只差 0.36%**。
- **⇒ `1.7512` 可用；下一次改动顺手收成 1.745 即可，不需要"推倒重测"。**

**⚠️ 仍未做**：**平放 / 翻过来的差分法**（`S = (Z_下 − Z_上)/2`、`b = (Z_下 + Z_上)/2`）
—— 那是唯一能把**标度**与**零偏**分开、且不受姿态影响的做法。
按 `gain-scan` 的拟合，零偏只有 +53 码（≈1.1%），所以它对 `|a|` 的影响 ≤±1.1%；但要坐实仍需一次翻转。

## 11. ★★ 更正（2026-10-01 · 来自代码审查的两个实质性纠错）

队友 `code-auditor` 的逐条审查（`work/review-01-手册逐条对照.md`）推翻了本文**两处**论证。都记下来。

### 11.1 ❌ 本文 §2.1「顺手否掉干净的二倍」—— **这个否证在数学上不成立**

本文用 `|a| ÷ (手册÷2) = 1.139/1.142/1.159/1.185 ≠ 1.000` 来否掉"档位偏移一档"。
**但那是错的，因为两个模型是简并的：**

```
模型 A（纯增益）      : 实测 = k1 · 手册        + b
模型 B（档位差一档）  : 实测 = k2 · (手册 ÷ 2)  + b
取 k2 = 2·k1  ⇒  模型 B ≡ 模型 A          ← 同一条直线，残差完全相同
```

⇒ **四档量程扫描对"纯增益"与"档位偏移 + 残余增益"是简并的，分不开。**
本文 §2.1 的那组比值（1.139~1.185）**恰恰就是模型 B 的预测**（b≠0 时比值本就不为 1），
我把它当成"否证"是**用错了判据**。

**要判别必须引入不随"标称码"线性缩放的外部参照** —— 例如 H104 读出的**物理重力**（1g）。
而这恰好就是现在用的口径：`1g = 4650~4700 码`（见第 10 节、以及 `measure-point`/`hold-steady` 实测）。

⇒ **操作层面的结论不变**（标度用实测 counts/g），但**"否掉二倍"这个论断撤回。**

### 11.2 ❌ 产出 `1.7512` 那次的 `gain-scan.tcl` 读原语不合规

审查指出：`gain-scan.tcl:37` 用的读原语**没有**本项目自己证明必需的净化/双读，
而且**那一次运行没有落盘日志**（同目录只有 `.tcl`）。
⇒ 该次数据只能当"旁证"，不能当"证据"。

**好消息**：后来 `measure-point.tcl`（原子 16 位读 + 64 样本 + 静止门）独立复现出
**4694.6 码/g（与 4678 差 0.35%）**，且 `hold-steady.tcl` 的 60 秒连续记录显示
**静止时 |a| = 4636~4919 码（最大偏差 5.8%），所有大数值都伴随高陀螺（运动）**。
⇒ **标度结论本身站得住，只是"证据链"要换成后面这两条。**

### 11.3 ✅ `GYR_RANGE(0x43)` 位域错误（已修）

手册 §5.40 逐列核对：`B7 B6 B5 B4 B3 B2 B1 B0` / `-- -- -- -- OIS_RANGE FS2 FS1 FS0`
⇒ **`OIS_RANGE` 在 `B3`**，旧代码写 `Bit4`（旧注释也写 B4）—— 两处都错。
危害：旧 `gyr_range_mask = 0x17` 会**去清 B4（保留位）**，而手册警告"保留位不要更改，
可能引起永久性破坏"。已改为 `Bit3` / 掩码 `0x0F`。

### 11.4 ✅ 标度不再依赖"一次性运行时回读"（已修）

`SetAccelScaleAndRange/SetGyroScale` 原本用 Configure() 末尾**那一次**回读决定 2 的幂次标度；
而 **`GYR_RANGE` 的 `set_bits = 0` ⇒ `CheckRegisterConfig` 对它恒判 OK** ⇒ 读错了没人发现。
已改为**用驱动自己写下去的值**定标度，回读只作校验并打差异。

### 11.5 ⚠️ 最重要的一条：**本文全篇与 `[cal] accel 0 invalid X-axis` 无关**

审查给出源码级结论：六面标定的判定**只看符号**（`accelerometer_calibration.cpp:222-273`，
失败消息在 `:231/:239`），**幅值完全不参与**。
⇒ **无论标度是 0.57 倍还是 1.75 倍，都不可能造成那条错误。**
⇒ `README.md` 里"先重烧（修标度）再重标很可能就过了"—— **在代码层不成立，撤回**。
⇒ 真因是**轴向**（`-R` / 轴映射），定位中。
