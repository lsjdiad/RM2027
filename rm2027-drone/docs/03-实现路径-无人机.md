# 03 · 实现路径：RM2027 小型空中机器人（150-249g）

> 2026-08-28 初版（旧"大无人机"路线）；**2026-08-28 因官方新规全面重写**。
> 依据：RM2027 官方规则亮点 PPT（小型空间智能机器人 / 150-249g / 4架 / 30s 续航 / 机库充电）+ 时效性开源（Fast-Drone-250、EGO-Swarm、UWB）。

---

## 〇、一句话路线

**第一台 = 参考 Fast-Drone-250 尺度的 250g 级自主四旋翼：PX4（或 ArduPilot）小飞控 + UWB 场边定位 + 机载算力（可选）+ 自研机库（充电/通讯/起降引导）。先让一台在仿真和室内"自己飞、自己落、自己充"，再谈 4 架与撞击/拦截任务。**

> 新规把无人机从"带云台的载重平台"变成了"小型空间智能体"。你们的战场从"云台稳瞄+图传"转成"**自主定位 + 自动起降 + 能量调度 + 任务执行**"——这是新天地，也是新门槛。

## 一、飞控 vs 电控：责任划分（按新规重划）

| 层 | 干这个 | 你们要做 |
|----|--------|---------|
| **飞控（底层）** | 姿态/位置控制律、传感器融合、外部定位(UWB)接入 | 选现成小飞控板（PX4/ArduPilot），**理解并调参**，重点学"外部位置估计" |
| **机载电控/算力（你们主场）** | 自主任务状态机（起飞→任务→回库）、UWB 数据处理、撞击/拦截逻辑、充电管理、与机库通讯 | 自研，复用 rm_2027 的 ThreadX 分层思维（换更轻量平台） |
| **机库系统（全新角色，必须自研）** | 充电（触点/磁吸）、通讯网关（有线/近场无线）、起降引导、裁判接入 | 完全自研，这是新赛季的"另一半战场" |
| **上位机/视觉（可选）** | 侦察回传、目标识别、4 机协同 | 对接点：机库网关 ↔ 雷达/操作间 |

**关键接口**：
- 飞控 ↔ 定位：UWB 基站给飞控发位置（PX4 `vehicle_external_position` / EKF2 外部位置融合）。
- 飞控 ↔ 机库：降落引导（UWB 或视觉/机械）、充电握手、任务指令。
- 机库 ↔ 场外：信息回传（侦察数据→雷达）、裁判系统。
- 4 机之间/机库：相对定位（EGO-Swarm 思路）与调度。

## 二、方案选型（关键决策点）

### 2.1 飞控三选一
| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| **PX4 小飞控**（Kakute F7 / Pixracer / 自研） | 自主能力最强，原生支持外部位置估计（UWB/视觉），SITL 仿真成熟 | 系统重（NuttX+多进程），板级重量/功耗略高 | ⭐ 首选（自主任务需要） |
| ArduPilot 小机架 | 稳定、可参考，支持外部定位 | 生态偏航测/大机，微小型资料少 | 备选 |
| Betaflight/INAV | 极轻、竞速手感好 | 自主定位弱，UWB 支持少 | 仅当"手动操作+轻量化"路线 |
| **Fast-Drone-250 路线**（参照） | 250g 全自主已验证，开源完整 | 用 NUC 级算力，重量/功耗高 | 学习其架构，按新规减配 |

> 判断：任务含"自动起飞/回库/撞击/拦截"，**必须自主** → PX4 系为主，学习 Fast-Drone-250 架构取舍。

### 2.2 定位方案（场内无 GPS）
| 方案 | 说明 | 精度 |
|------|------|------|
| **UWB 场边基站 + 机载标签**（Nooploop LinkTrack 类） | ZJU 高飞已验证；分布式测距；RM 场内可提前布设 | 10-30cm，够用 |
| 光流 + 气压计（机载） | 悬停/低速段，低成本 | 漂移大 |
| 视觉（单目/双目里程计） | 需算力，全自主更强 | 视环境 |
| UWB + 光流/IMU 融合（PX4 EKF2） | 推荐组合：UWB 慢漂+光流短稳，融合互补 | 稳 |

### 2.3 动力与储能
- **30s 续航上限**（规范限制最高储能）→ 电池容量被"卡死"，不是做大而是**做高效**。
- 选高推力重量比：微型无刷（如 110x/120x 系）+ 大桨距小桨 + 高效电调（DShot/PWM）。
- 重量预算：249g 上限，桨保+机架+动力+飞控+UWB+电池，**每克都要预算表**，目标留 150-200g 区间余量。

### 2.4 机库系统（全新，占一半工作量）
- **充电**：触点/磁吸/感应；安全（防反接、过充、限流）。
- **起降引导**：降落精度是关键（机库开口小）→ UWB 相对 + 末端视觉/机械漏斗导引。
- **通讯**：机库做有线/近场无线网关，把侦察信息转发雷达/操作间；也是 4 机调度中心。
- **裁判接入**：机库与裁判系统对接（出场计数/状态上报按正式规则）。

## 三、电控要干什么、负责什么（新职责清单）

1. **机载自主电控**（核心新增）
   - 任务状态机：待机→自动起飞→任务→自动返航→降落→充电→再起飞。
   - 定位数据处理：收 UWB 位置 → 校验 → 喂给飞控外部位置估计；掉定位保护。
   - 撞击/拦截逻辑：与飞控联动（撞击后姿态恢复、触发拦截机动）。
   - 安全：解锁安全、低电回库、失控保护、桨保内限速。
2. **机库电控**（另一半新增）
   - 充电管理（多机排队/按需）、通讯网关、起降引导、裁判接入。
3. **传感器与负载集成**
   - 侦察传感器（轻量摄像头/测距，按规则）、UWB 标签、指示灯。
4. **与现有框架协同**
   - 机库电控可用你们现有 ThreadX 框架；**机载电控受 249g 限制，可能要走更轻的 MCU/裸机或轻 RTOS**（这是你们要评估的点：249g 内塞不塞得下 ThreadX 栈）。

> 一句话：**飞控管"飞得稳"，电控管"自己会飞+会回库+会干任务"，机库管"能量+信息+调度"。**

## 七、是否仿真验证？—— **必须做，且是第一步**

1. **PX4 SITL + Gazebo**（免费官方）：把"微小型无人机 + UWB 外部定位"在仿真里跑通。
   - Windows 下用 **WSL2 + Ubuntu** 装 PX4 SITL + Gazebo + QGroundControl。
   - 找 Fast-Drone-250 的仿真配置参考，建一个 249g 尺度的机架模型。
2. **UWB 仿真**：先软件模拟基站-标签测距，再引真实 LinkTrack 数据。
3. **机库/降落仿真**：验证自动降落精度与回库流程（PX4 支持 precision landing / mission 降落点）。
4. **实机流程**：系留 → 室内无风（UWB 定位）→ 回库充电循环 → 带任务 → 双机/四机。
5. **物理任务仿真（撞击/拦截）**：用动力学仿真估算 249g 撞击力能否达到"42mm 级伤害"、拦截机动响应是否够——**先算后造，避免造完发现物理上做不到**。

> 这次比旧路线更依赖仿真，因为：新平台没成熟先例 + 撞击/拦截是全新物理问题 + 249g 造错成本高。

## 十、风险与坑

1. **规则数值未最终定**：249g/30s/机库尺寸可能微调 → Phase 0 只做"通用自主能力"，不做机制绑定。
2. **定位是命门**：UWB 在金属场馆内多径/遮挡，要提前做抗干扰与失效保护（掉定位=掉飞机）。
3. **撞击物理可行性**：249g+全包围桨保能不能打出"42mm 级伤害"、拦截机动够不够快——**先仿真，别赌**。
4. **重量预算失控**：桨保/UWB/传感器/电池/机架，每克记账，从 150g 起做增量设计。
5. **Windows 环境**：PX4 SITL 要 Linux（WSL2），环境先行。
6. **机载算力限制**：249g 内跑不跑自主规划，要在"板载算力 vs 地面/机库算力"间取舍（Fast-Drone-250 用 NUC，但 249g+桨保 会很紧；可把重算放机库/场外）。
7. **别照抄旧大无人机**：云台/图传/42mm 发射那套不适用，省下的重量用在定位与任务上。
