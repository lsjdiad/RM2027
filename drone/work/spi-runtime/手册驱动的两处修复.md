# 按厂商手册补的两处 upstream 修复（PX4 `e567d41`）

> 依据：深圳华轩阳 HXY《ICM-42688P 六轴惯性传感器模块》手册
> （原件已收入 `references/硬件手册/华轩阳HXY_ICM-42688P_六轴传感器模块_手册.pdf`）
> 状态：**已改 + 编译通过 + 已提交；未上板验证**（ST-Link 掉线、板子断电）

## 1. 温度高低字节反了（upstream 既有 bug）

**手册 5.22 TEMP_H(22h), TEMP_L(23h)** 原文：

```
TEMP_H   TEMP [15:8]
TEMP_L   TEMP [7:0]
T = (signed short int)((X_H << 8) | X_L) / 512 + 23℃
```

**PX4 upstream 写的**：

```cpp
const uint16_t temp = temperature_buf[2] | (temperature_buf[3] << 8);   // ← H 和 L 反了
```

`temperature_buf[2]` 是 0x22 的内容（TEMP_H），`[3]` 是 0x23（TEMP_L）。
按手册应该是 `(buf[2] << 8) | buf[3]`。换算系数 `1/512` 本来就对（`lsb = 1/2^9`），**只有字节序错**。

⇒ 已修正。注意：这不是本板特有的 —— **正品 BMI270 的温度也是高字节在前，所以上游这个 bug 对所有板子都成立**。

## 2. `PWR_CTRL` 的启动时序没遵守

**手册 5.45 PWR_CTRL(7Dh) 备注**原文：

> 备注：0x7D 要先写入 0x0E 并延时 10ms 之后再进行其他配置。另外，在配置完寄存器后
> 建议延时 1ms 再进行寄存器读取操作。

**upstream 的做法**：一口气把 `_register_cfg` 里全部寄存器写完，两条时序都没满足。

**改法**：兼容件（`_skip_microcode`）走手册顺序；**正品 BMI270 仍走上游原路径**，不在上游已验证的
行为上引入回归。

```
PWR_CONF → PWR_CTRL=0x0E → usleep(10ms) → 其余配置(ACC_CONF/GYR_CONF/ACC_RANGE)
        → usleep(1ms) → 回读校验
```

## 3. 一条重要线索：1185 vs 2048 的增益之谜

- 手册规格：`A_FS=3`(±16g) 灵敏度 **0.488 mg/digit** ⇒ **2048 counts/g**
- 实测静止 1g 只有 **1185 counts/g**（四档 9289.5/4648/2316/1185，严格 8:4:2:1 ⇒ 量程对）
- 子代理实测：读数随 `ACC_CONF` 的 **bwp 半字节**出现两个离散档位 —— **~1177 和 ~2302**，
  而 PX4 原配置 `0xAC` 落在**低档**

**`2302` 离手册 `2048` 只差 12%，`1185` 差 42%。** ⇒ **高档很可能才是正确配置。**

### 上电后的验证顺序

| # | 动作 | 判据 |
|---|---|---|
| 1 | 读 `DATA_STAT(0x0B)` 的 `ACC_CONF_ERR`/`GYR_CONF_ERR` 位 | 若置位 ⇒ 配置被器件拒绝 ⇒ 第 2 节的时序修复可能真的有用 |
| 2 | 静止读 3 轴加速度 | 看 1g 对应多少 counts。若已 ≈2048 ⇒ **撤掉 `ACCEL_COMPAT_GAIN_CORRECTION`（设为 1.0）** |
| 3 | 换 `ACC_CONF` 的 bwp 落进高档再测 | 若 1g ≈2048 ⇒ 正解是改 `ACC_CONF`，不是加增益补丁 |
| 4 | **翻板 30 秒**（`listener sensor_accel`） | \|a\| 不变 ⇒ 增益误差；变成 ≈1.4g ⇒ 零偏误差 |
| 5 | 手转 90°/180° 对比 | 定陀螺刻度与 X/Y 轴向（**姿态传播靠陀螺积分，这是最大风险项**） |

⚠️ **第 5 步定论前不要放飞。**
