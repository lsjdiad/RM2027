## 2. `ACC_CONF(0x40)` 的位定义 —— 可能解释那个 2× 跳档

**手册 §5.37 原文位表：**

```
B7           B6   B5   B4      B3   B2   B1   B0
ACC_FILTER_PERF  ACC_BWP[2:0]      ACC_ODR[3:0]
```

| 位 | 名称 | 含义 | 缺省 |
|---|---|---|---|
| B7 | `ACC_FILTER_PERF` | **0 = 低功耗模式使能，1 = 高性能模式使能** | **1** |
| B6-B4 | `ACC_BWP[2:0]` | 带宽/滤波模式（`000`=OSR4_AVG1、`001`=OSR2_AVG2、`010`=NORM_AVG4 …） | `010` |
| B3-B0 | `ACC_ODR[3:0]` | 输出数据率 | `1000` |

**代入实际值：**

```
PX4 写的   0xAC = 1010 1100 → FILTER_PERF=1(高性能)  BWP=010(NORM_AVG4)  ODR=0xC
手册缺省   0xA8 = 1010 1000 → FILTER_PERF=1(高性能)  BWP=010(NORM_AVG4)  ODR=0x8
```

**⇒ 两条重要推论：**

1. **`0xAC` 是合法组合**，而且和缺省**只差 ODR**、`BWP` 完全一样
   ⇒ **`ACC_CONF_ERR` 预期应该是 0**。上板读 `DATA_STAT(0x0B)` 直接验证这一点。
2. 子代理扫"高半字节"时看到的**两个 2× 档位**，其中 **B7 就是"高性能 / 低功耗"电源模式开关**。
   ⇒ 那个 2× 跳档**最可能来自电源模式切换，而不是 `ACC_BWP`**。
   这与手册的灵敏度规格（`0.488 mg/digit` @ `A_FS=3`）到底对应哪个模式有关。

### 上板时的优先试验顺序

| # | 试什么 | 判据 |
|---|---|---|
| 1 | 读 `DATA_STAT(0x0B)`（驱动已自动打印） | `ACC_CONF_ERR/GYR_CONF_ERR` 是否为 0 |
| 2 | 静止读 1g 码值 | 是否 ≈2048 |
| 3 | **把 `ACC_FILTER_PERF`(B7) 翻成 0**（即 `ACC_CONF` 用 `0x2C`） | 1g 是否变成 ≈2302 |
| 4 | 若 3 成立 | 那个 1.73× 是**电源模式**造成的，正解是选对模式 + 撤掉 `ACCEL_COMPAT_GAIN_CORRECTION` |

> `0x2C = 0010 1100` → FILTER_PERF=0(低功耗)、BWP=010、ODR=0xC。ODR 不变，只翻电源模式位，
> 是干净的单一变量对比。**注意低功耗模式噪声更差**，若代码值对了但噪声大，要权衡。
