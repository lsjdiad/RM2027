## 1. 器件身份

| 项 | 手册写的 | 实测 |
|---|---|---|
| 厂商 | 深圳华轩阳电子（HUAXUANYANG / HXY） | — |
| 厂商型号 | ICM-42688P（"六轴惯性传感器模块"） | — |
| 封装/丝印 | LGA-14 2.5x3x1.00mm，丝印 **7I22/xxxx** | — |
| ID 寄存器 | **WHO_AM_I = 0x01**，缺省 **0x6A**（§4.1 / §5.1；"等同 CHIP_ID 值为 0x6A"） | 读 0x01 = 0x6A（早期 ST-Link 就抓到了 0x6A） |
| 0x00 地址 | **手册寄存器表里没有 0x00** | 读 0x00 = 0x00 |
| 接口 | I²C（7bit 0011 00xb）/ SPI（**≤10 MHz**，4 线；COM_CFG.SIM 可切 3 线） | PX4 用 SPI1 @6 MHz、MODE3 ✓ |

⇒ PX4 的 bmi270 驱动按 BMI270 去读 `CHIP_ID(0x00)==0x24`，在本片必然失败（0x00 读出 0x00）。
**更严谨的识别是 `RegisterRead(0x01) == 0x6A`**（transfer() 补丁已保证返回该地址内容）。
现有"接受 0x00"的补丁已在实机验证可用，故先不改逻辑，只记录（见代码注释）。

## 2. 通信层（手册 vs 实测）

**SPI 读（§3.2.1）**：读命令 16 个时钟；Bit0=RW=1，Bit1-7=地址，**Bit8-15 = DO(7:0)**，
原文："如果是读，则电路会在 **bit8** 开始驱动 SDO"；多字节读再追加 8 位块。
⇒ **地址字节之后立刻是数据，没有 dummy 字节** —— 与 `1f614b3` 补丁（transfer() 右移补一格）
**完全一致**。这条终于不再是"经验 hack"，而是手册时序。

**写（§3.2.2）**：16 时钟，Bit8-15 = DI(7:0) —— 与 PX4 的写法一致。

**地址自增**：`COM_CFG(0x05)` 的 `Addr_Auto` 缺省 = 1 ⇒ 突发读 0x0C~0x17 一次 CS 内自增 ✓
（实测 64 次突发读数据自洽）。

**其他 COM_CFG 位**：`BDU` 缺省 = 1（"输出数据寄存器不更新直到 MSB 和 LSB 被读取"）
⇒ 一次突发读拿到的 H/L 是同一采样，不会撕裂 ✓。

**手册的配置时序要求（尚未遵守，见 §7）**：
- §5.45 PWR_CTRL 备注："0x7D 要**先写 0x0E 并延时 10ms** 之后再进行其他配置"。
- §4.1 备注："在配置完寄存器后建议**延时 1ms** 再进行寄存器读取操作"。
- §5.43 自测步骤：`PWR_CTRL=0x0E`(+10ms) → `ACC_CONF=0xAC`(+2ms) → 自测(+50ms)。

### 3.1 关键寄存器位定义（手册原文，已核对）

- **ACC_CONF(0x40)**：B7 `ACC_FILTER_PERF`(1=高性能)、B6:B4 `ACC_BWP[2:0]`(缺省 010)、
  B3:B0 `ACC_ODR[3:0]`。`0xAC` = 高性能 + BWP=010 + **ODR=1100 = 1600Hz** ⇒ PX4 写的合法。
  越界组合会自动回落到缺省 `0xA8` 并置 `DATA_STAT.ACC_CONF_ERR=1`。
- **ACC_RANGE(0x41)**：`FS[1:0]`：00=±2g、01=±4g、10=±8g（缺省）、11=±16g
  ⇒ PX4 写 `0x03` = ±16g，与手册一致。
- **GYR_CONF(0x42)**：B7 `GYR_FILTER_PERF`、B6 `GYR_NOISE_PERF`、B5:B4 `GYR_BWP`、
  B3:B0 `GYR_ODR`；合法 ODR = 0110..1101（25Hz..3200Hz），**1100 = 1600Hz**
  ⇒ PX4 写的 `0xEC`（含 NOISE_PERF=1）合法（手册另注：切 NOISE_PERF 要先关再开 accel/gyro）。
- **GYR_RANGE(0x43)**：`FS[2:0]` 缺省 **000 = ±2000dps** ⇒ **PX4 不写 0x43 也没问题**。
  手册陀螺灵敏度 61 mdps/LSB @±2000dps = 16.39 LSB/dps ⇒ PX4 的
  `radians(2000)/32767` **与本手册一致**（这条以前没法验证，现在有依据了）。
- **PWR_CTRL(0x7D)**：B3 TEMP_EN / B2 ACC_EN / B1 GYR_EN（B0/B4-B7 保留）
  ⇒ PX4 写的 `0x0E` = 三个都开 ✓（实测也是写了就出数据）。
- **HPF&LPF_CFG(0x08)**：缺省 `0x80`，其中 **FDS(B5)=0 = 跳过内部高通滤波**、DLPF_EN=0
  ⇒ **缺省没有高通滤波**，这也是"静止数据稳定、不衰减"的正式依据（PX4 不写 0x08，正好用缺省）。
- **DATA_STAT(0x0B)**：B5 `GYR_CONF_ERR` / B4 `ACC_CONF_ERR` / B2 `DRDY_TMP` /
  B1 `DRDY_GYR` / B0 `DRDY_ACC` ⇒ **回读配置是否被接受 / 数据是否就绪，都可以在这里查**。
- **INT_CFG1(0x06)/INT_CFG2(0x07)**：`INT1_SEL[4:0]`（00001=DRDY_ACC，00011=DRDY_GYR…）
  ⇒ 本片 DRDY 中断的正规配法（BMI270 的 0x53/0x58 在本片不存在）。

## 4. 数据寄存器格式（手册 §5.9~§5.14）

手册原文示例代码：

```c
SL_ACCEL_X = (signed short int)((X_H << 8) | X_L);   // 高字节在前
SL_ACCEL_X = SL_ACCEL_X >> 4;                        // 手册说"取 12 位"
```

- **两次补码、16 位、高字节在前** ⇒ 与实测（MSB-first）一致，`combine(msb,lsb)` 正确。
- 手册的 `>>4`（左对齐 12 位）**与实测不符**：实测低 4 位非零、且随噪声连续取值
  （64 样本 Z 低字节 0x89~0xB3 的低半字节覆盖 0~F）⇒ 本片给的是**完整 16 位输出**。
  而且手册这张示例表自身也不自洽（`0x4000` 的"10bits"列写 256，实际 `>>4` 应为 1024）。
  ⇒ **实现按完整 16 位取用**（当前驱动就是这么做的）。
- `TIME_H/M/L`(0x18~0x1A)：24 位、分辨率 **39.06125 µs**、与 ODR 同步
  ⇒ 实测两轮采样间计数 +169022，与粗略估计的采样耗时 5~6 s 同量级（≈25.6kHz），**量级吻合**。
- `TEMP_H/L`(0x22/0x23)：`T = (signed short)((H<<8)|L)/512 + 23℃`。
  ⚠️ 顺带发现 **PX4 的 `UpdateTemperature()` 把高/低字节写反了**
  （`temp = buf[2] | (buf[3]<<8)`，应为 `(buf[2]<<8)|buf[3]`）——upstream 既有问题，
  本次不动，仅记录（温度只进日志/健康，不影响姿态）。

## 5. ★ 灵敏度与量程：手册规格 vs 实测（1.73x 之谜，仍未解）

### 5.1 手册规格（机械参数表 + §5.9 示例）

| ACC_RANGE | 量程 | 手册灵敏度 | 折算 counts/g | 实测 counts/g（静止 1g） | 手册/实测 |
|---|---|---|---|---|---|
| 0x00 | ±2g | 0.061 mg/digit | 16393 | **9289.5** | 1.764 |
| 0x01 | ±4g | 0.122 mg/digit | 8197 | **4648.0** | 1.763 |
| 0x02 | ±8g | 0.244 mg/digit | 4098 | **2316.0** | 1.769 |
| 0x03 | ±16g | **0.488 mg/digit** | **2049** | **1185.0** | 1.728 |

手册 §5.9 的示例表也自洽：`0x4000`(=16384) 在 FS=11 时代表 **8.0g** ⇒ 1g = 2048 counts。

### 5.2 实测（真机、CPU halted、板子静止）

- 四个量程是**严格 8:4:2:1**阶梯 ⇒ **量程寄存器工作正常，不是"量程语义不同"**。
- 但绝对值只有手册的 **1/1.73**（0.844 mg/digit 而不是 0.488）。
- 64 样本统计（0x03 档）：`|a| = 1185.0 ± 8.0 counts`，ACC_Z = 1183.1 ± 8.1。
- **物理约束**：静止时加速度合矢量必须是 1g ⇒ 器件在 0x03 档确实"把 1g 报成 ~1185 counts"。

### 5.3 两种解释**数学上等价**，单点 1g 无法区分

```
增益假说：measured = S·1g·α   （α ≈ 0.578）
零偏假说：measured = S·(1g + o)（o ≈ -0.42g）
```
两者都是 `measured = k·S`，在**单一加速度**下完全同形（换量程也一样，因为零偏是物理量、
码值同样按 8:4:2:1 缩放）。所以**必须换一个已知激励**才能定论。

### 5.4 ★ 手册给了两个能定论的实验（下一步必做）

1. **加速度计自测 `ACC_SELF_TEST(0x6D)`**（§5.43 + 机械参数表）：
   手册规格：A_FS=3 时自测偏转 **X 轴 ±6g、Y 轴 ±6g、Z 轴 ±8g**（正负激励方向幅度差）。
   - 增益假说（α=0.578）⇒ Z 轴自测应产生 ≈ 8g × 1185 ≈ **9480 counts** 差；
   - 零偏假说（灵敏度 2048）⇒ 应产生 ≈ 8g × 2048 ≈ **16384 counts** 差。
   两者差 73%，远超自测本身的容差 ⇒ **一次测试即可定论**。
   步骤（手册 §5.43）：`PWR_CTRL=0x0E`(+10ms) → `ACC_RANGE=0x03` → `ACC_CONF=0xAC`(+2ms)
   → `0x6D` 置 `SELF_TEST_EN=1` + `SELF_TEST_AMP=1`，分别取 `SELF_TEST_SIGN=0/1` 两次(+50ms)，
   相减。
   ⚠️ 注意：手册只给"典型值"，没给 min/max，所以它适合**二选一**，不适合当精密基准。
2. **把板子翻过来再读 |a|**（零成本）：
   - 纯增益误差 ⇒ 无论怎么翻，`|a|` 都是 **0.578g**（码值恒 ~1185）；
   - 存在 Z 轴零偏 ⇒ 翻过来 `|a|` 会变成 **≈1.42g**（码值 ~2908），因为零偏不随姿态改变。
   QGC `listener sensor_accel` 就能看，**30 秒出结论**。

### 5.5 这个未解之谜对当前实现的影响

- 现在驱动里用的是**增益标定**（`ACCEL_COMPAT_GAIN_CORRECTION = 2048/1185 ≈ 1.7283`，只作用于
  `set_scale`，不动 `set_range` —— Lead 已修正我原先误乘 `set_range` 的问题）。
- 如果最终证明是**零偏**：这个系数就是错的，正解是保持手册 scale、由 PX4 六面加速度计标定去修零偏。
- 所以：**定论之前不要放飞**；无论哪种结论，**跑一遍 PX4 加速度计六面标定**都是对的。

## 6. FIFO 真相（★ 重要更正）

以前写的是"这颗片子没有 FIFO"——**错**。手册 §5.16~§5.21：

| 寄存器 | 地址 | 说明 |
|---|---|---|
| FIFO_CFG0 | 0x1C | B2 FIFO_ACC_EN、B1 FIFO_GYR_EN、B0 FIFO_HEADER_EN（缺省 0 = 关） |
| FIFO_CFG1 | 0x1D | FM[1:0]：00=By-Pass(缺省)、01=FIFO、10=Stream、11=触发；FTH[10:8] |
| FIFO_CFG2 | 0x1E | FTH[7:0] 阈值高 8 位（缺省 0xFF） |
| FIFO_STAT0 | 0x1F | B6 EMPTY、B5 WTM、B4 OVER_FIFO、FSS[11:8] |
| FIFO_STAT1 | 0x20 | FSS[7:0]（未读组数） |
| FIFO_DATA | 0x21 | FIFO 数据 |

- 容量 **2048 Byte = 341 组**（每组 12B）；组内顺序 = **4B Sensor_Time + GYR_X/Y/Z + ACC_X/Y/Z**
  （**与 BMI270 的"header 帧"格式完全不同**，BMI270 的解析代码不能直接用）。
- 缺省是 **By-Pass**（不缓存）⇒ 也解释了"没配置就什么都读不到"。
- 之前的"0x48/0x49 写不进、0x24/0x25 恒 0"：**因为 BMI270 的 FIFO 地址在本片不存在**。
- 另注：手册 FIFO 模式要求"读完数据后先切 By-Pass 再切回 FIFO/Stream 才能继续工作"。

⇒ **本次实现仍然用查询方式（手册明确支持）+ 1kHz 轮询**，行为不变；但"FIFO 不可能"这个
判断已被推翻 —— 将来若要"不丢样本"，正确的路是按**本片**的 0x1C~0x21 实现一条 FIFO 路径。

## 7. 中断与复位（顺带更正）

- **中断**：本片 `INT_CFG1(0x06)`（INT1_SEL[4:0]：00001=DRDY_ACC、00011=DRDY_GYR、
  00101=DRDY_TMP、01000=EMPTY、01001=WTM…）、`INT_CFG2(0x07)`（INT2_SEL）、
  `INT_CFG1.INT_PP_OD/H_LACTIVE` 管推挽/开漏与极性；DRDY 状态位在 `DATA_STAT(0x0B)`。
  **BMI270 的 0x53/0x58 在本片不存在** ⇒ 原驱动的中断配置在本片是空操作；
  本次保持"定时轮询、不用中断"（手册也支持查询方式）。
- **复位**：本片软复位是 **`SOFT_RST(0x4A)` 写 `0xA5`**（"复位整个电路，数据清零"）。
  BMI270 的 `CMD(0x7E)=0xB6` 在本片是**不存在的地址** ⇒ 之前"软复位把片子打哑"的机制
  其实是写了个空地址（真正打哑它的是那次微码上传实验）。
  ⇒ 现在有了**正确**的软复位手段，但**未经测试**，不要贸然用（红线仍是：不上传微码）。
- **微码**：手册里**完全没有** BMI270 的 INIT_CTRL(0x59)/INIT_DATA(0x5E) 上传机制
  ⇒ "不要上传微码"这条红线现在有了正式依据：本片根本不需要、也没有这个机制
  （当初上传 329 字节微码写的就是不存在的/别功能的地址，把片子搞哑了）。

1. **上板验证轮询驱动是否真的发布数据**（ST-Link 掉线 + 用户主动断电，未完成）。
