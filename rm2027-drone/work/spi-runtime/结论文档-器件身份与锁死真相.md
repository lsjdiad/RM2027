# 器件身份 + "锁死"真相（2026-09-30 夜 · 上板子代理中途被停后由 Lead 收尾）

## 1. 器件身份（文档级硬结论，不依赖板子）

**这颗件是 BMI270 家族的 die。华轩阳手册 = BMI270 的寄存器表 + ICM-42688-P 的规格表，两家被抄混了。**

证据（逐条对原文，Lead 已复核）：

| | 华轩阳手册 / 本片实测 | 正品 ICM-42688-P |
|---|---|---|
| `0x40` | ACC_CONF：B7=FILTER_PERF / B6:4=BWP / B3:0=ODR（**与 BMI270 逐位相同**） | ACCEL_CONFIG0（FS 在 bit7:5、**无 BWP 字段**） |
| `0x41` | ACC_RANGE：B1:0，00=±2g…11=±16g | ACCEL_CONFIG0 的一部分 |
| `0x42` | GYR_CONF：B7/B6/B5:4 | GYRO_CONFIG0 |
| `0x43` | GYR_RANGE：B2:0，000=±2000dps | GYRO_CONFIG0 的一部分 |
| `0x4E` | — | **PWR_MGMT0 在这里** |
| `0x7D` | **PWR_CTRL**：B3/B2/B1=TEMP/ACC/GYR_EN | 不是 PWR_CTRL |
| 数据 | `0x0C` 起 | **`0x1F` ACCEL_DATA_X1** |
| WHO_AM_I | `0x01` = `0x6A` | **`0x75`** |
| FS 编码 | `0x00` → counts/g 最高（= BMI270 口径） | **反的**：FS_SEL=0 → ±16g（=2048） |

- 正品依据：仓库 `references/硬件手册/ICM-42688-P_datasheet_extract.md` 第 **3550** 行（`ACCEL_DATA_X1` 在 `0x1F`）、**3632** 行（`PWR_MGMT0` 在 `0x4E`）、**3636** 行（`ACCEL_CONFIG0` 在 `0x50`）、**3750** 行（`WHO_AM_I` 在 `0x75`）、**716-722** 行（FS 编码是反的）
- **规格表却全是 ICM-42688-P 的数**：`0.488 mg/digit`、`AVst` 6/6/8g、`GSo` 61 mdps/LSB

**⚠️ 但这解释不了那个 1.76 倍** —— **BMI270 自己的加速度计灵敏度也是 2048 LSB/g @±16g**。器件身份查清了，1.76 倍仍是悬案。

**⇒ 顺带放心一条**：正品 FS 编码是反的，我们实测阶梯（`0x00` 最高）遵守华轩阳/BMI270 口径
⇒ **驱动的量程映射没写反**。

## 2. ★ "锁死"真相：**芯片根本没锁，是 SPI1 被写坏了**

子代理报告"IMU 锁死（`WHO_AM_I=0x00`、数据全 0）"，**Lead 复核后推翻**：

它自己在一个脚本里写了 **`SPI1 CR1 = 0`**。`SSM=1` + `SSI=0` 会触发 **MODF 模式错误**，此后 `SPE` 再也置不上
⇒ **MCU 侧 SPI1 死了** ⇒ 之后所有读都是垃圾（`0x00`/`0x01`/`0xFF`），**看起来像芯片锁死，其实是主机侧坏了**。

**Lead 的恢复操作（全程没断电）：**
```text
1) mww SPI1_IFCR (0x40013018) = 0xFFFFFFFF    ← 清 MODF/SUSP 等所有标志
2) mww SPI1_CR1  (0x40013000) = 0x00001001    ← 恢复 SPE|SSI
   ⇒ WHO_AM_I(0x01) 立刻读回 0x6A ✓   ← 芯片一直是好的！
3) reset run（复位 MCU，让 PX4 重新配置 IMU）
   ⇒ 0x40=AC 0x41=01 0x43=00 0x7D=0x0E 0x0B=0x07，数据恢复为活值 ✓
```

**⇒ 结论：不用断电。** 任何"读出来全 0/全 FF/ID 不对"的情况，**先检查主机侧 SPI1 状态**（`CR1` 应为 `0x1001`、`IFCR` 要清），
再怀疑芯片。

> ⚠️ **2026-09-30 深夜补充（更正）**：上面那句 `CR1` 应为 `0x1001` 是**固件侧**的说法。
> **手工用 GPIO 拉 CS 的脚本（本目录所有 `*.tcl`）必须用 `0x00001201`**（含 bit9 `SSM=1`）；
> 用 `0x1001` 会**读出全 0x00**，从而**误判成"芯片锁死"**。
> A/B 实测见 `cri-ab.tcl`：
> ```
> CR1=00001001 -> WHO_AM_I=00 0x7D=00 0x0B=00 0x40=00 0x42=00
> CR1=00001201 -> WHO_AM_I=6A 0x7D=0E 0x0B=07 0x40=8C 0x42=CC   ← 全对
> ```
> 详见 `GYR_CONF-否证与复现-2026-09-30夜.md` §7。

**⚠️ 遗留**：复位后 `0x42 GYR_CONF = 0xA9`（手册缺省值），**不是驱动应写的 `0xEC`** —— 说明这次冷启动 GYR_CONF 没写进去。
需要一次干净的冷启动复核（可能是我的软复位干预造成的，也可能是真 bug）。

## 3. 子代理留下的手法坑（已在脚本里改掉）

| 坑 | 教训 |
|---|---|
| `xf` 轮询上限 20000 | 降到 **300**；SPI 不响应时每字节烧 10 秒，一个脚本因此跑了 6 分钟 |
| **写 `CR1=0`** | **绝对不能写** —— 见第 2 节，会把 SPI1 打死 |
| 会话开头 | 必须清 `IFCR`（含 `SUSP`/`MODF`）+ 用 `WHO_AM_I==0x6A` 自检 |
| `SUSP=1` 时读 | 读到的是**陈旧 RXDR**，会伪装成有效数据 |
