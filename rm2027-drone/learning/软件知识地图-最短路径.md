# 软件知识地图 · 最短路径（PX4/QGC/SITL/ROS 按需学）

> 适用人：拿到自研飞控板后负责 bring-up、驱动、调参、集成的同学。
> 目标：用最少时间建立“够用”的 PX4/SITL/QGC 认知，不被大而全的资料淹没。
> 创建：2026-09-09

---

## 一、核心心法

```
你不是要“学完 PX4”，你是要“拿到板子后能让它飞”。
所以只学四件事：
1. 怎么把固件跑起来（SITL / 编译 / 烧录）
2. 数据怎么流动（uORB / MAVLink）
3. 驱动/模块往哪里插（driver / module）
4. 出问题怎么查（日志 / QGC / 参数）
```

---

## 二、最短学习路径（4 步）

### Step 1：PX4 数据流骨架（1-2 天）
看本地源码：

```
~/RM2027/PX4-Autopilot/src/modules/
~/RM2027/PX4-Autopilot/msg/
```

重点概念：
- `uORB`：PX4 内部“话题总线”
- `ModuleBase`：每个模块怎么启动/循环
- `vehicle_attitude_s` / `vehicle_local_position_s`：核心消息
- `px4_sitl`：不是真飞机，只是让模块在 PC 上跑

### Step 2：SITL 当“假飞控”用（半天）
已经会的：
```
make px4_sitl gz_x500
QGC 连接 127.0.0.1:14550
```

再加一个技能：
```
改 PX4 代码 → make → SITL 跑 → 看日志
```

以后你写的驱动/模块都可以先在 SITL 里“假装有硬件”验证逻辑。

### Step 3：写/改一个最小模块（3-5 天）
从官方示例开始：

```
PX4-Autopilot/src/examples/hello
```

然后按这个顺序练：
1. 加一个 uORB 消息
2. 写模块发布/订阅这个消息
3. 在 SITL 里启动它
4. 用 `listener` 或日志确认数据

这就是你“自定义”的基础。

### Step 4：把自定义接到真实硬件（拿到板后）
对照：
- `src/drivers/imu/`：IMU 驱动长什么样
- `src/drivers/distance_sensor/`：外设驱动怎么注册
- `boards/`：不同板子的默认配置、引脚映射

到时候你有原理图，按板子改 `boards/<你的板>/` 下的配置即可。

---

## 三、QGC 你只需要会这些

不要一上来学 QGC 二次开发，先会用：

| QGC 功能 | 什么时候用 |
|---|---|
| 连接状态 | 看 SITL/飞控是否在线 |
| 模式切换 | 起飞前切 Position/Mission |
| 校准 | 传感器/遥控/水平 |
| 参数表 | 改 PID / 改起飞高度 |
| 日志下载 | 飞完拉 ulog 分析 |
| MAVLink Console | 在飞控上敲命令/看输出 |

QGC 二次开发（QML/加页面/自定义 MAVLink）等你把 PX4 玩熟后再碰。

## 四、SITL 文件/目录到底怎么用

```
PX4-Autopilot/
├── build/px4_sitl_default/   # 编译产物（SITL 固件）
├── ROMFS/px4fmu_common/      # 启动脚本、默认参数
├── src/modules/              # 所有模块
├── msg/                      # uORB 消息定义
├── Tools/simulation/gz/      # Gazebo 仿真模型/插件
└── boards/                   # 各硬件板配置
```

SITL 本质：
- `px4` 二进制在 PC 上运行
- Gazebo 提供“假传感器/假电机”
- QGC/MAVLink 照常连接
- 你写代码时不用真硬件，先验证逻辑

---

## 五、ROS 先放后面

只有当你需要：
- 机载电脑/视觉/路径规划
- 更复杂的 Offboard 控制
- 多机协同

才学 ROS。现在可以只知道一个概念：
```
PX4  <--MAVLink-->  ROS/MAVROS  <--你的程序-->
```

## 六、给你的“先穷尽后行动”替代方案

我不可能替你“学完”所有东西，但我可以帮你做一张**按需知识地图**：

- 你说一个具体任务，例如“写一个 UART 传感器驱动”
- 我帮你列出：
  1. 要看哪几个源码文件
  2. 要懂哪几个 PX4 概念
  3. 哪些先不用管
  4. 第一步改哪里

这样你每次只面对一小块，而不是面对整个 PX4/QGC/ROS 海洋。

---

## 七、下一步建议动作

1. 在 SITL 里跑一次 `hello` 示例模块
2. 读 `src/examples/hello/CMakeLists.txt` + `hello_main.cpp`
3. 试着自己改打印内容，重新 make，在 SITL 终端里看到输出
4. 完成后，我们就开始学“加自定义 uORB 消息”

完成这 4 步，你对“自定义 PX4”就不再是焦虑，而是有实际手感。
